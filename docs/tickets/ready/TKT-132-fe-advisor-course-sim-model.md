## 문제
택시 엔진의 "차량"은 목적지까지 간 뒤 입구로 돌아와야 다음 호출을 받는다. 창구 은유에서는 이 복귀가 없다. 결과: 10시(분당 2.8명)·창구 3·혼합 처리 28초에서 명목 처리 능력 분당 ≈6.4명인데 평균 대기 18.8분·최장 37.5분. 화면의 `혼합 처리시간`과 실제 모델 처리량이 다르므로 학습 문항("창구 +1 vs 예약 60%", "임계 이용률")의 답이 왜곡된다.

## 목표
1. 유효 처리시간 = 표기 처리시간이 되게 한다. 방법은 구현자 제안 — 예: 완료 즉시 창구를 `entry` 로 되돌려(상태 복제 후 zone 리셋) 복귀 이동 제거, 또는 엔진 밖 얇은 결정론적 다중 창구 큐(도착 간격·서비스 시간·c 창구)로 교체. 후자를 택하면 "엔진 재사용" 문구를 결과 설명에서 뺀다. 공수·정확도 비교를 `[구체화 질문]` 으로 먼저 올려도 좋다.
2. 결과에 `이용률 %`(도착률 × 처리시간 / 창구 수) 표시 — 문항 3 의 근거.
3. tick 양자화(15초 ceil)로 인한 오차를 결과 설명에 한 줄로 명시하거나 tick 을 5초로.

## 완료 조건
1. [ ] 10시·창구 3·예약 35% 에서 평균 대기 ≤ 2분(이용률 < 50%일 때 대기가 폭발하지 않음) — unit.
2. [ ] 창구 +1 과 예약 35%→60% 의 대기 감소 비교가 이용률 계산과 방향 일치 — unit 1건.
3. [ ] 결과에 이용률 % 표시, 375/1440 overflow 0, 기존 E2E 그린.
