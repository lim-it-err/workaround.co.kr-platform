# TKT-035

## 메타데이터

- 제목: 엘리베이터 실시간 수요 분포와 연속 이동 루프
- 우선순위: P1
- 대상 버전: `v0.3.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-035-elevator-live-traffic-loop`

## 목표

`TKT-021` 의 23층 다중 엘리베이터 dispatch 보드를, 승객 단위 상태와 자동 수요 루프를 가진 실시간 시뮬레이터로 확장한다.

## 이번 구현

- `services/elevator-service/app.py`
  - 시간 기반 자동 운행 루프 추가
  - 승객 단위 상태(`waitingPassengers`, `completedPassengers`, `passengers[]`) 추가
  - 정원 20명, `currentLoad`, `position` 기반 이동 모델 추가
  - `POST /api/passenger`, `POST /api/demand` 추가
  - `POST /api/call` 은 레거시 승객 생성 호환 경로로 유지
  - `POST /api/step` 은 디버그 보조 제어로 유지
- `frontend/src/App.vue`
  - 수요 프리셋(`quiet`, `normal`, `busy`)과 강도 슬라이더 연결
  - 승객 단위 대기열/목적층 요약 표시 추가
  - car overview 카드에 연속 위치 shaft, 적재 인원, 차내 목적층 요약 추가
  - 자동 poll 기반 상태 갱신과 local mock 저하 흐름 갱신
- `frontend/src/styles.css`
  - 수요 제어 패널, car mini shaft, 부하 meter, 층별 queue copy 스타일 추가
- 문서 갱신
  - `services/elevator-service/README.md`
  - `docs/network.md`
  - `docs/frontend-ux.md`
  - `docs/history/2026-06-15.md`

## 완료 기준 점검

- `localhost:7000` 기준 수요 프리셋과 강도 슬라이더를 UI 에서 조절할 수 있다.
- 수동 제어는 승객 1명 추가 개념으로 서비스 API 와 mock 상태 양쪽에 반영된다.
- 승객은 출발층과 목적층을 가진다.
- car 정원 20명, 적재 인원, 대기 승객 상태가 응답 모델에 포함된다.
- 자동 운행이 기본이며 `step` 은 디버그 버튼으로만 남겨 두었다.
- car overview 카드에서 층 사이 연속 위치가 보이도록 `position` 기반 shaft 를 추가했다.
- `frontend` production build 와 `elevator-service` smoke 결과를 남겼다.

## 남은 리스크

- 인앱 브라우저 시각 검증은 이번 Windows sandbox 에서 `CreateProcessAsUserW failed: 5` 로 막혀 자동 확인하지 못했다.
- 층별 버튼 텍스트는 현재 title/queue copy 중심으로 의미를 보강했으며, 최종 시각 polish 는 review 에서 한 번 더 볼 가치가 있다.
- 오케스트레이터 판정: 서비스 smoke 와 프런트 build 근거는 충분하지만, 실제 브라우저 기반 UX 검수와 통합 환경 근거가 아직 부족해 backlog 로 되돌린다.
