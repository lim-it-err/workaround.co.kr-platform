# TKT-054

## 메타데이터

- 제목: Writing Studio 저장/발행 무결성

- 문서 상태: `작성완료`

- 권장 브랜치: `codex/tkt-054-writing-studio-save-publish-integrity`

## 목표

Writing Studio 의 저장/발행 흐름에서 데이터가 사라지거나 상태가 뒤집히는 문제를 없앤다. 편집 중 이탈로 인한 유실, 발행일(`publishedAt`) 소실, "draft 저장"이 라이브 글을 몰래 내리는 동작, 지나치게 엄격한 draft 검증과 발행 글 재편집 진입점 부재, 수동 슬러그가 제목 편집으로 덮이는 문제를 함께 바로잡아 저장/발행을 신뢰할 수 있게 만든다.

## 작업 내용

아래 각 항목은 2026-07-05 블로그 QA 조사의 발견 번호와 정확한 파일:라인을 근거로 한다. 라인은 별도 표기가 없으면 `frontend/src/App.vue` 기준이다.

1. (발견 #1, MAJOR) 편집 중 이탈 시 미저장 내용 유실 방지.
   - 근거: Studio 버튼 핸들러 `frontend/src/App.vue:3738-3740`, 페이지 이동 `openPage` `frontend/src/App.vue:1688-1706`. 현재 autosave/dirty-guard/beforeunload 가 전혀 없다.
   - 수정 방향: 편집 상태를 감지하는 dirty 플래그를 두고, 디바운스된 autosave(초안 임시 저장)를 추가한다. `openPage` 로 화면을 벗어나거나 브라우저 `beforeunload` 시 미저장 편집이 있으면 저장하거나 사용자에게 경고한다. 화면에 "미저장 변경 있음/저장됨" 표시(unsaved indicator)를 노출한다.
2. (발견 #4, MAJOR) draft/archive 왕복 시 `publishedAt` 소실 방지.
   - 근거: `persistStudioPost` `frontend/src/App.vue:1516-1517` 의 `: ''` 분기가 발행일을 빈 값으로 덮는다. 재발행하면 새 날짜가 찍힌다.
   - 수정 방향: `publishedAt` 은 최초 발행 시 1회만 설정하고, 이후 어떤 상태 전환(draft/archive/재발행)에서도 절대 비우지 않는다. 이미 값이 있으면 유지한다.
3. (발견 #5, MAJOR) "draft 저장"이 라이브 글을 몰래 내리지 않게 한다.
   - 근거: `saveStudioDraft` `frontend/src/App.vue:1475-1478` 가 저장 시 `status='draft'` 로 강제한다(`frontend/src/App.vue:1511`). 그 결과 발행 중인 글이 저장만 해도 비공개로 내려가고, #4 와 겹쳐 발행일까지 사라진다.
   - 수정 방향: 발행 상태(`published`)인 글을 저장할 때는 상태를 유지한다. 비공개 전환은 "발행 취소(unpublish)" 같은 명시적 액션으로만 일어나게 분리한다.
4. (발견 #11, MINOR) draft 검증 완화 + 발행 글 편집 진입점 추가.
   - 근거: draft 저장이 제목+요약+본문을 모두 요구한다(`frontend/src/App.vue:1503-1507`, 너무 엄격). 발행된 글을 다시 편집할 진입점이 없고 draft 선반(draft shelf)만 있다(`frontend/src/App.vue:3715-3725`).
   - 수정 방향: draft 저장 검증을 완화한다(예: 제목만 있어도 임시 저장 가능). 발행된 글에서 Studio 편집으로 들어오는 진입점(edit affordance)을 추가한다.
5. (발견 #7, MINOR) 수동 슬러그가 이후 제목 편집으로 덮이지 않게 한다.
   - 근거: 제목 watcher `frontend/src/App.vue:1166-1174` 가 슬러그를 다시 만든다. `populateStudio` 가 `studioSlugTouched` 를 초기화한다(`frontend/src/App.vue:1467`, `frontend/src/App.vue:1544`).
   - 수정 방향: 사용자가 슬러그를 직접 만졌다는 사실(slugLocked)을 글 모델에 저장/복원한다. 잠긴 슬러그는 제목 편집으로 덮지 않는다.

## 범위

- 포함: dirty-guard/autosave/미저장 표시, `publishedAt` 1회 설정 규칙, 발행 글 저장 시 상태 유지 + 명시적 발행 취소, draft 검증 완화, 발행 글 편집 진입점, slugLocked 저장/복원. 대상 파일은 `frontend/src/App.vue` (필요 시 `frontend/src/styles.css`).
- 제외: 공개 라우팅/딥링크(→ TKT-055), 아카이브 목록/복원과 상태 배지 색(→ TKT-056), 마크다운 렌더러(→ TKT-057), localStorage 견고화/다중 탭/스키마 마이그레이션(#6, 서버측 저장 전환 티켓), 서버 저장 전환 자체.

## 완료 기준

- (발견 #1) 편집 중 다른 화면으로 이동하거나 새로고침해도 미저장 내용이 유실되지 않는다(autosave 또는 경고). QA 런타임 체크 "unsaved-edit loss" 통과.
- (발견 #5, #4) 발행 중인 글을 저장(draft 저장 포함)해도 공개 상태와 `publishedAt` 이 유지된다. QA 런타임 체크 "publish→draft-save flow" 통과.
- (발견 #11) 제목만 있어도 임시 저장이 되고, 발행된 글을 다시 편집으로 열 수 있다.
- (발견 #7) 사용자가 직접 만든 슬러그가 이후 제목 편집으로 덮이지 않는다. QA 런타임 체크 "custom slug overwrite" 통과.
- production build 또는 동등한 검증이 성공한다.

## 질문/결정 기록

- 결정: localStorage 견고화(#6: `setItem` try/catch 부재 `frontend/src/App.vue:2383-2388`, 배열 전체 재기록 deep watcher `frontend/src/App.vue:1081-1083`, 파싱 실패 시 seed 가 사용자 데이터 대체 `frontend/src/App.vue:2367-2381`, 다중 탭 clobber, schemaVersion 부재)는 이 티켓에서 다루지 않는다. 서버측 글 저장 전환 티켓(Phase 4)으로 통합한다. 따라서 "two-tab clobber", "malformed JSON reload" 런타임 체크도 이 티켓 범위 밖이다.
- 결정: 발행 취소는 별도 명시 액션으로 둔다. 저장 동작이 상태를 뒤집지 않는다.
- 결정: `publishedAt` 은 최초 발행 시 1회만 기록하고 이후 보존한다.
- 열린 질문: autosave 저장 위치를 현재 localStorage 로 둘지, 서버측 전환 시점에 맞춰 임시 초안 저장 계약을 다시 정할지.
