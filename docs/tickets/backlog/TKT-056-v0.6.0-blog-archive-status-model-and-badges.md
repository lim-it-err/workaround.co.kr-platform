# TKT-056

## 메타데이터

- 제목: 블로그 아카이브 상태 모델 + 상태 배지
- 우선순위: P2
- 대상 버전: `v0.6.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-056-blog-archive-status-model-and-badges`

## 목표

`archived` 를 삭제가 아닌 "보관" 상태로 되돌린다. 보관 글을 볼 수 있는 목록과 복원(restore) 동선을 만들고, draft/published/archived 상태 배지를 디자인 문서 §6 규칙(슬레이트/그린/브론즈)에 맞게 서로 구분한다.

## 작업 내용

아래 각 항목은 2026-07-05 블로그 QA 조사의 발견 번호와 정확한 파일:라인을 근거로 한다. 라인은 별도 표기가 없으면 `frontend/src/App.vue` 기준이다.

1. (발견 #2, MAJOR) 아카이브를 되돌릴 수 없는 막다른 길(사실상 삭제)에서 "보관 + 복원" 모델로 바꾼다.
   - 근거(코드): `archiveStudioPost` `frontend/src/App.vue:1490-1497` 로 보관하면 되돌릴 방법이 없다. `archivedBlogPosts` computed `frontend/src/App.vue:874-877` 는 개수(count)로만 쓰인다(`frontend/src/App.vue:900`). 보관 목록/복원/삭제 UI 가 없다.
   - 근거(디자인): `design/blog-district-ui-system-2026-06-26.md` §6 은 "`archived` 는 삭제가 아니라 보관, 기본 공개 흐름에서 제외"라고 명시한다.
   - 수정 방향: 보관된 글을 실제로 보여주는 목록을 추가한다(개수뿐 아니라 항목 노출). 각 항목에서 draft/published 로 되돌리는 복원 액션을 제공한다. 필요하면 명시적 영구 삭제를 보관 목록 안의 별도 액션으로 분리한다(삭제와 보관을 혼동시키지 않는다).
2. (발견 #9, MINOR) 상태 배지를 3상태 모두 회색으로 두지 않고 §6 색 규칙으로 구분한다.
   - 근거(코드): `.status-chip` 스타일 `frontend/src/styles.css:609-613` 이 3상태 모두 같은 회색이다. 배지 템플릿은 `frontend/src/App.vue:3569`, `frontend/src/App.vue:3630`, `frontend/src/App.vue:3653`, `frontend/src/App.vue:3688`, `frontend/src/App.vue:3786` 에 있다.
   - 근거(디자인): §6 권장 색 — `draft` 회청/슬레이트, `published` 짙은 초록/블루그린, `archived` 갈회/브론즈. 금지: `archived` 를 위험/삭제 색과 동일하게 두지 않기, `draft` 와 `archived` 를 회색 하나로 퉁치지 않기.
   - 수정 방향: 상태별 배지 색 클래스를 나눠 슬레이트/그린/브론즈로 구분한다. Line-B accent `#7e294f` 는 그대로 둔다(QA 확인 OK).

## 범위

- 포함: 보관 글 목록 노출, 복원 액션(및 필요 시 명시적 영구 삭제 분리), 상태별 배지 색 구분. 대상 파일은 `frontend/src/App.vue`, `frontend/src/styles.css`.
- 제외: 저장/발행 무결성(→ TKT-054), 공개 라우팅/딥링크(→ TKT-055), 마크다운 렌더러(→ TKT-057), localStorage 견고화/서버 저장(#6, Phase 4), 상태 값(draft/published/archived) 자체의 이름/의미 변경.

## 완료 기준

- 보관된 글을 목록에서 볼 수 있고, 복원 액션으로 다시 draft/published 로 되돌릴 수 있다. QA 런타임 체크 "archive recovery attempt" 통과(보관→복원이 실제로 성공).
- draft/published/archived 배지가 시각적으로 서로 구분된다(슬레이트/그린/브론즈). 3상태가 동일 회색이 아니다. QA 런타임 체크 "status chip visual" 통과.
- 배지 색이 디자인 §6 금지 규칙을 위반하지 않는다(archived ≠ 위험/삭제 색, draft/archived 회색 단일화 금지).
- production build 또는 동등한 검증이 성공한다.
