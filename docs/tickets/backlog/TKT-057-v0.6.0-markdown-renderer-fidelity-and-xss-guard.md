## 목표

마크다운 렌더러의 충실도를 높인다(중첩/순서 목록, 링크/이미지, 인라인 코드 정확도). 동시에 현재의 XSS 안전성을 절대 훼손하지 않는다. 부수적으로 중복 태그 key 와 취약한 ID 생성을 정리한다. 안전성이 이 티켓의 1순위 불변식이다.

## 작업 내용

**먼저 읽을 XSS 안전 제약 (필수, 위반 금지)**

QA 검증 결과 현재 파이프라인은 안전(SAFE)하다: escape-first 파이프라인, `v-html` 싱크 `frontend/src/App.vue:3661`, `frontend/src/App.vue:3793`, 렌더러 `frontend/src/App.vue:2077-2152`. 아래를 반드시 지킨다.

- 렌더러를 바꾸더라도 "토큰화 전에 이스케이프(escape-before-tokenize)" 순서를 반드시 유지한다. 안전성은 이 순서에 의존한다.
- 원시 HTML(raw HTML)을 절대 활성화하지 않는다. 사용자 입력이 그대로 HTML 로 들어가면 안 된다.
- 링크를 추가한다면 URL 스킴 allowlist(예: `http`, `https`, `mailto` 만 허용, `javascript:` 등 차단)를 적용한다.
- 현재 `escapeHtml` 은 따옴표(`"`, `'`)를 이스케이프하지 않는다. 따라서 속성(attribute) 싱크를 절대 새로 만들지 않는다(예: `href`/`src` 를 이스케이프 없이 문자열 결합하지 않는다). 속성이 필요하면 값 검증 + 인코딩을 별도로 한다.
- 권고: 백엔드 공유(서버 저장/다중 사용자) 전에 검증된 새니타이저(vetted sanitizer)로 교체하는 것을 권장한다. 이번 티켓에서 도입한다면 위 제약을 그 라이브러리로 강제한다.

아래 각 항목은 2026-07-05 블로그 QA 조사의 발견 번호와 정확한 파일:라인을 근거로 한다. 라인은 별도 표기가 없으면 `frontend/src/App.vue` 기준이다. 모든 변경은 위 XSS 안전 제약을 지킨다.

1. (발견 #8, MINOR) 마크다운 렌더러 충실도 개선.
   - 근거: 중첩 목록이 목록을 깨고 닫아버림 `frontend/src/App.vue:2116-2119`, 순서 목록(ordered list) 미지원, 링크/이미지 미지원(Markdown-first 원칙과 충돌), 인라인 코드 안에서 bold/italic 이 처리됨(`a**b**`), 모든 줄이 각자 `<p>` 가 됨, 홀로 있는 `*` 가 italic 처리됨. 코드 펜스(fence)는 올바르게 처리됨.
   - 수정 방향:
     - 순서 목록과 중첩 목록을 지원한다.
     - 인라인 코드(code span)를 다른 인라인 서식보다 먼저 처리한다(code-span-first). 코드 안의 `**`/`*` 는 서식으로 해석하지 않는다.
     - 링크(및 필요 시 이미지)를 지원하되, 위 XSS 제약대로 URL 스킴 allowlist 를 적용하고 원시 HTML 은 열지 않는다.
     - 문단 처리로 줄마다 `<p>` 가 남발되지 않게 한다.
   - 검증: QA 의 "markdown fidelity samples" 로 확인한다(중첩/순서 목록, 링크, `a**b**`, 홀로 있는 `*`).
2. (발견 #12 일부, COSMETIC) 중복 태그 key 정리.
   - 근거: 중복 태그 key `frontend/src/App.vue:3575`, `frontend/src/App.vue:3636`, `frontend/src/App.vue:3657`.
   - 수정 방향: 리스트 렌더링 key 가 항목마다 고유하도록 바꾼다(중복 key 제거).
3. (발견 #12 일부, COSMETIC) 취약한 ID 생성 교체.
   - 근거: `Math.random` 기반 ID 생성 `frontend/src/App.vue:2052-2054`.
   - 수정 방향: `crypto.randomUUID()` 로 교체한다(가능 환경 확인 후 fallback 처리).

## 범위

- 포함: 순서/중첩 목록, code-span-first 인라인 처리, URL 스킴 allowlist 를 지킨 링크(및 필요 시 이미지), 문단 처리 개선, 중복 태그 key 제거, `crypto.randomUUID` ID 생성. 대상 파일은 `frontend/src/App.vue` (필요 시 `frontend/src/styles.css`).
- 제외: 원시 HTML 허용(금지), 속성 싱크 신설(금지), 저장/발행 무결성(→ TKT-054), 공개 라우팅(→ TKT-055), 아카이브/배지(→ TKT-056), 슬러그 입력 UX(#12 의 slug 관련 부분, 질문/결정 기록 참고), localStorage/서버 저장(#6, Phase 4).

## 완료 기준

- 중첩/순서 목록, 링크, 인라인 코드 충실도가 QA "markdown fidelity samples" 에서 기대대로 렌더된다.
- XSS paste 테스트가 여전히 통과한다(악성 페이로드가 실행되지 않고 이스케이프됨). QA 런타임 체크 "XSS paste test" 통과. escape-before-tokenize 순서와 raw-HTML 미허용이 유지된다.
- 링크가 추가된 경우 `javascript:` 등 위험 스킴이 차단되고 `http`/`https`/`mailto` 만 통과한다.
- 태그 리스트에 중복 key 경고가 없다.
- ID 생성이 `crypto.randomUUID` 를 사용한다.
- production build 또는 동등한 검증이 성공한다.

## 질문/결정 기록

- 결정(보안): 현재 escape-first 파이프라인은 안전하다. 렌더러 변경은 이스케이프 순서와 raw-HTML 미허용을 반드시 유지한다(위 XSS 안전 제약).
- 결정: 링크 지원 시 URL 스킴 allowlist 를 적용한다. `escapeHtml` 이 따옴표를 이스케이프하지 않으므로 속성 싱크를 새로 만들지 않는다.
- 권고/열린 질문: 백엔드 공유 전에 검증된 새니타이저로 교체 권장. 이번 티켓에서 라이브러리를 도입할지, 자체 렌더러를 보강만 할지는 결정 필요. 도입 시 제약을 라이브러리로 강제한다.
- 결정: #12 의 슬러그 입력 부분(키 입력마다 slugify + 단방향 바인딩 `frontend/src/App.vue:1470-1473`, `frontend/src/App.vue:3753-3759`, 내부 하이픈 입력 불가 `frontend/src/App.vue:2063`)은 이 티켓 범위가 아니다. 슬러그 처리(#7)는 TKT-054 에서 다루므로, 슬러그 입력 UX 개선은 그쪽 또는 후속으로 둔다. 이 티켓은 렌더러 충실도 + 중복 key + ID 생성만 다룬다.
- 결정: 날짜/타임존은 QA 확인상 문제 없음(작업 불필요).

## Notes

- 이 티켓의 1순위 불변식은 "충실도 개선이 XSS 안전성을 깨지 않는다" 이다. 리뷰어는 escape-before-tokenize 순서와 raw-HTML 미허용, 링크 스킴 allowlist 를 먼저 확인한다.
