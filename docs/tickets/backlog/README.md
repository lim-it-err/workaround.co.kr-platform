# 백로그

이 폴더에는 아직 시작하지 않은 티켓을 둔다. worker가 실제로 집을 수 있는지는 각 티켓의 `진행 판정` 을 우선 확인한다.

## 버전별 묶음

- `infra`: 워커, Docker, GPU 런타임, Ollama 서빙 같은 기반 인프라 작업
- `v0.1.2`: 빌드 툴 기준선 이후 현재 런타임을 다시 맞추는 정렬 작업
- `v0.2.0`: `http://localhost:7000` 에서 확인하는 통합 결과물과 그 안에 들어갈 기능 연결 작업
- `v0.2.1`: 테스트 코드 추가와 커버리지 측정 기반 작업
- `v0.3.0`: 엘리베이터 시뮬레이터 연속 운행과 수요 흐름 보강 작업
- `v0.3.1`: 엘리베이터 시뮬레이터의 움직임/시각화 안정화 patch 작업
- `v0.4.0`: Work Manager, Jira 스타일 보드, command 게이트, 테스트/CI/PR 품질 게이트를 붙이는 운영 트랙
- `v0.5.0`: 다양한 시뮬 포털과 택시 시뮬레이터 코어를 붙이는 다음 시뮬레이션 트랙
- `v0.5.1`: 택시 시뮬레이터의 피드백 반영과 자동 학습 후속 작업
- `v0.6.0`: 블로그 허브, 글쓰기 스튜디오, 공개 아카이브, 이미지 업로드를 붙이는 글쓰기 트랙
- `v0.7.0`: Flash Game 공간, SWF 플레이어, 카탈로그를 붙이는 아케이드 트랙
- `chore`: 문서 언어 통일과 티켓 흐름 정리 작업

## 티켓 메모

티켓 본문 끝에는 필요하면 `Notes` 를 붙인다.

- 다른 티켓으로 넘겨야 할 말
- 릴리스나 main 동기화 관련 주의사항
- scope 밖이지만 바로 다음 티켓에 필요한 힌트

## 읽는 순서

1. `docs/releases.md` 로 버전 목표를 확인한다.
2. `v0.4.0` 과 `v0.5.0` 범위면 `docs/feature-definition.md` 를 먼저 읽어 기능 경계를 확인한다.
3. 이 폴더에서 대상 버전에 맞는 티켓을 고른다.
4. 티켓의 `진행 판정` 이 `진행 가능` 인지 확인한다.
5. `진행 불가` 또는 아직 열리지 않은 `vX.Y.Z 진행 시 가능` 티켓이면 시작하지 않는다.
6. 티켓의 선행 읽기 목록과 최신 히스토리를 먼저 읽는다.
7. 작업이 끝나면 산출물과 검토 메모를 티켓 흐름에 맞게 남긴다.
