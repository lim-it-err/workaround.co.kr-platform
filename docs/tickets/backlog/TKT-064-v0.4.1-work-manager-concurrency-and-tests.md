# TKT-064

## 메타데이터

- 제목: Work Manager 동시성/원자적 쓰기와 테스트 보강
- 우선순위: P2
- 대상 버전: `v0.4.1`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-064-work-manager-concurrency-and-tests`

## 목표

Work Manager 공개 보드 읽기의 스레드 안전성과 `board.md`/store 쓰기의 원자성을 확보하고, Vue computed 의 반응성 부작용을 제거하며, 결함 회귀를 막을 테스트를 채운다.

## 작업 내용

1. [MAJOR] 공개 보드 읽기의 스레드 안전성 + 원자적 쓰기 (#7)
   - 공개 보드가 mutable `workManagerAuditLog` 를 비동기화로 읽는다: `workManagerPersistenceSummary`(`gateway/src/main/java/com/workaround/platform/gateway/PlatformGatewayApplication.java:1758-1766`)가 비동기화 `workManagerBoard`(`:854`, `:913`)와 fallback(`:1961`)에서 호출된다.
   - 반면 `recordWorkManagerAudit`(`gateway/.../PlatformGatewayApplication.java:1775-1792`)는 synchronized 로 `add(0)`/`remove` 를 수행한다. `ArrayList` 는 thread-safe 하지 않아 IndexOutOfBounds/torn read 가 가능하다.
   - 수정 방향: 보드 읽기를 synchronized 로 감싸거나, audit 읽기를 방어 복사(snapshot)로 가드한다.
   - 또한 `board.md` 를 `Files.readAllLines`(`gateway/.../PlatformGatewayApplication.java:872`)로 락 없이 읽는데, `writeUtf8BomDocument` 는 truncate-write(`:1398`, `:1444`) 한다. 쓰기 도중 읽으면 partial read -> 조용히 fallback 보드로 떨어진다.
   - 수정 방향: `board.md`/store 쓰기를 temp-file 에 쓴 뒤 atomic move(`Files.move(..., StandardCopyOption.ATOMIC_MOVE)`)로 교체한다.

2. [MINOR] Vue computed 안의 반응성 부작용 (#12)
   - `workBoardColumns` computed 가 `readyTicketIds` 와 localStorage 를 mutate 한다(`frontend/src/App.vue:957-963`). Vue anti-pattern 이다.
   - 수정 방향: prune/persist 로직을 `watch` 로 옮기고, computed 는 순수 계산만 하게 한다.

3. [MINOR PROCESS] 테스트 공백 보강 (#14)
   - 현재 테스트는 3개뿐(board, auth+command, lockout): `gateway/src/test/java/com/workaround/platform/gateway/PlatformStoreWorkManagerTest.java`.
   - 추가할 테스트:
     - (a) 전이 매트릭스 합법/불법(#3/#4, TKT-062 의 새 매트릭스와 정합)
     - (b) persist round-trip(#2, command-history 저장/로드 키 통일 검증)
     - (c) 세션 TTL 만료(#1/#6, 만료 후 401)
     - (d) metadata update(메타 편집 저장/재로드)
     - (e) concurrent read(#7, 보드 읽기와 audit 기록을 동시에 hammering)
   - lockout 테스트가 단일 IP 만 검증한다. XFF 회전 케이스(#5, TKT-060 의 신뢰 프록시 정책과 정합)를 추가한다.

## 범위

- 포함: 게이트웨이 보드/audit 동시성, `board.md`/store 원자적 쓰기, `App.vue` computed 리팩터, 테스트 추가
- 제외: 각 결함의 기능 수정 본체(TKT-060~063). 본 티켓은 동시성/원자성/테스트에 집중하되, 추가 테스트는 TKT-060/062/063 의 수정 동작을 검증한다.

## 완료 기준

- 보드 읽기와 audit 기록을 동시에 hammering 해도 IndexOutOfBounds/torn read 가 발생하지 않는다. (런타임 체크: board concurrency hammering)
- `board.md`/store 쓰기 도중 읽어도 partial read 로 fallback 보드로 떨어지지 않는다. (런타임 체크: board/folder desync 해소)
- `workBoardColumns` computed 가 상태/localStorage 를 mutate 하지 않는다.
- 위 (a)~(e) 테스트와 XFF 회전 lockout 테스트가 추가되고 `mvn -q -pl gateway test` 가 통과한다.

## 선행 조건

- 없음. 다만 전이 매트릭스 테스트(#3/#4)와 XFF 테스트(#5)는 각각 TKT-062, TKT-060 의 동작 계약에 맞춰 작성해야 하므로, 해당 계약이 정해진 뒤 작성하는 것을 권장한다(엄격한 선행은 아님, 조율 사항).

## 질문/결정 기록

- 열린 질문: 원자적 쓰기를 `ATOMIC_MOVE` 로 할지 파일 락으로 할지. 기본은 temp-file + `Files.move(ATOMIC_MOVE)`.
- 열린 질문: concurrent read 테스트의 스레드 수/반복 수 기준. 기본은 다수 reader + 1 writer 로 기존 IndexOutOfBounds 를 재현할 수 있는 수준.
