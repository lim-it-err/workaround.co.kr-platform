# TKT-067

## 메타데이터

- 제목: 취향 노선 - 10선택 규칙 기반 와인/커피 추천
- 우선순위: P2
- 대상 버전: `v0.9.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `v0.9.0 진행 시 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-067-taste-line-recommender`

## 목표

취향 노선(`Line P`)의 테이스팅 바 UI를 만들고, 10개 A/B 선택을 규칙 기반 스코어링으로 처리해 와인 1종 + 커피 1종을 즉시(런타임 토큰 0) 추천한다.

## 작업 내용

1. 사전 생성된 정적 데이터를 로드한다: `frontend/src/data/taste/axes.json`, `questions.json`(10), `wines.json`(24), `coffees.json`(24). 스키마는 `docs/taste-line-definition.md` 를 따른다.
2. 환승 홀 노선도(C 방식)에 `Line P / 테이스팅 바` 지선 진입점을 추가한다.
3. 테이스팅 바 페이지: 10개 A/B 질문을 한 번에 하나씩(또는 카드 스택) 제시하고 선택을 받는다.
4. 매칭 계산(`docs/taste-line-definition.md` 알고리즘):
   - 답변별 `axesA`/`axesB` 를 축별로 합산 → 사용자 벡터 `u`.
   - 각 후보의 `profile` 과 가중 유클리드 거리 계산 → 와인·커피 각 최소 거리 1종.
   - 동점은 `adventurous` 축 근접 우선.
5. 결과 카드: 추천 와인 + 커피 + 각 `why`(이유 한 줄) + "다른 후보 보기"(상위 2~3종) + "다시 하기".
6. 다크 테마 기본, 모바일 재배치를 확정 디자인 방향에 맞춘다. 좌우분할 대신 세로 흐름.

## 범위

- 포함: 정적 데이터 로드, 10 질문 UI, 규칙 매칭, 결과 카드, 다시 하기, 노선도 진입점.
- 제외: 구매/재고 연동, 취향 이력 저장(첫 버전은 세션 1회), 음식 페어링, API 설명(후속 옵션).

## 완료 기준

- 10개 선택을 마치면 와인 1종 + 커피 1종이 이유와 함께 추천된다.
- 서로 다른 선택 조합이 서로 다른(그럴듯한) 추천으로 이어진다.
- 계산이 프런트에서 즉시 끝난다(외부 호출 없음).
- `tools/run-frontend-build.ps1` 빌드가 통과한다.

## 질문/결정 기록

- 결정: 2^10 조합을 만들지 않고 규칙 기반 스코어링 + 최근접 매칭. 런타임 토큰 0.
- 열린 질문: 축 개수 6 vs 7~8(기본 7), 결과를 1종 고정 vs 상위 후보 선택(기본 1종 + 다른 후보 보기).
- 결정: "왜 이 조합?" 심화 설명 API 는 첫 버전 제외, 후속에서 `TKT-066` 프록시 재사용.
