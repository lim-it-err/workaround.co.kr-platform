# TKT-043

## 메타데이터

- 제목: Work Manager DB 저장소 전환과 감사 로그
- 우선순위: P2
- 대상 버전: `v0.5.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `v0.5.0 진행 시 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-043-work-manager-db-persistence`

## 목표

파일 기반으로 운영 중인 Work Manager 보드/활동 피드를 장기적으로 안정적인 DB 기반 저장소로 옮기고, 감사 로그를 남길 수 있는 구조를 마련한다.

## 작업 내용

- 현재 파일 기반 보드/티켓/피드 저장 경로를 정리한다.
- DB 전환 시 필요한 최소 스키마를 정의한다.
- 티켓 상태, 메타데이터, activity feed, command history 중 무엇을 우선 영속화할지 기본안을 정한다.
- 파일 기반 경로를 한 번에 버리지 말고 migration 또는 fallback 경로를 함께 남긴다.
- 감사 로그가 필요한 이벤트 범위를 정리한다.
  - 티켓 상태 전이
  - 우선순위 변경
  - 대상 버전 변경
  - command 실행
- 관련 문서와 운영 가이드를 갱신한다.

## 범위

- 포함: DB 저장소 설계, 영속화 범위 정의, 감사 로그 범위 정의, migration/fallback 기준, 문서 갱신
- 제외: 멀티유저 권한 체계 전체, 외부 SSO, 운영 대시보드 전체 재작성

## 완료 기준

- Work Manager 저장소의 파일 기반 현재 구조와 DB 전환 목표 구조가 정리돼 있다.
- 최소 영속화 범위와 감사 로그 범위가 문서화돼 있다.
- 파일 기반 fallback 또는 migration 경로가 남아 있다.

## 선행 조건

- `TKT-039` 와 `TKT-040` 의 UI/메타데이터 구조가 정리되어 있어야 한다.
- `TKT-042` 의 worker 가시화 / 우선순위 반응 설계와 충돌하지 않아야 한다.

## 질문/결정 기록

- 결정: 첫 단계의 Work Manager 는 파일 기반 저장으로 시작한다.
- 결정: 장기적으로는 DB 기반 저장소로 간다.
- 열린 질문: DB 후보를 무엇으로 둘지, gateway 내장형으로 둘지, 별도 저장소로 둘지.
