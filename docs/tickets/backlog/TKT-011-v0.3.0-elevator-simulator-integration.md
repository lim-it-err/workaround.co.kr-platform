# TKT-011

## 메타데이터

- 제목: 엘리베이터 시뮬레이터 통합 프리뷰 연결
- 우선순위: P2
- 대상 버전: `v0.3.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-011-elevator-preview-integration`

## 목표

`localhost:7000` 통합 프리뷰 안에서 엘리베이터 시뮬레이터를 실제 진입 가능한 기능으로 연결하고, 프런트엔드와 `elevator-service` 사이의 기본 상태 조회 흐름을 검토 가능한 상태로 정리한다.

## 이번 작업 결과

- 프런트엔드가 `GET /api/services/elevator-service/api/state` 를 읽는 통합 프리뷰 경로를 유지하는지 다시 검증했다.
- `tools/check-elevator-preview.ps1` 를 추가해 프런트엔드와 `elevator-service` 의 기본 스모크를 반복 실행 가능한 형태로 남겼다.
- backlog 에 남아 있던 깨진 티켓 문서를 복구하고, 현재 구현/검증 상태에 맞게 `need_review` handoff 문서로 다시 정리했다.

## 작업 내용

- `frontend/src/App.vue`, `frontend/src/main.js`, `services/elevator-service/app.py`, `gateway/src/main/java/com/workaround/platform/gateway/PlatformGatewayApplication.java` 의 현재 연결 상태를 재검토했다.
- `tools/check-elevator-preview.ps1` 로 아래 확인 흐름을 자동화했다.
  - `http://127.0.0.1:7000/`
  - `http://127.0.0.1:7000/src/main.js`
  - `http://127.0.0.1:7000/src/App.vue`
  - `http://127.0.0.1:8003/health`
  - `http://127.0.0.1:8003/api/state`
- gateway 의 `GET /api/services/{serviceId}/**`, `POST /api/services/{serviceId}/**` 프록시 경로가 코드에 남아 있는지 다시 확인했다.

## 범위

- 통합 프리뷰 안에서 엘리베이터 시뮬레이터 진입 경로와 상태 조회 흐름을 검토 가능 상태로 유지한다.
- 프런트엔드 production build, `elevator-service` 단독 HTTP smoke, 로컬 프리뷰 HTTP 응답을 근거로 남긴다.
- gateway Java/Maven compile, gateway Docker build, 인앱 브라우저 시각 검수는 이번 환경 제약을 명시한 채 review 항목으로 넘긴다.

## 검토 메모

- 현재 세션에서는 `java`, `mvn`, `docker` 가 없어 gateway compile / Docker build 를 검증하지 못했다.
- 인앱 브라우저 기반 시각 검수는 Windows sandbox 의 `CreateProcessAsUserW failed: 5` 제약으로 막혀 있다.
- 다만 프런트엔드 build 와 `elevator-service` smoke, 로컬 프리뷰 HTTP 응답은 모두 재검증했다.
- gateway 코드에는 여전히 `GET /api/services/{serviceId}/**`, `POST /api/services/{serviceId}/**` 프록시 경로가 존재한다.
- 오케스트레이터 판정: 서비스 단독 smoke 와 프런트 정적 응답은 확인했지만, gateway compile, gateway Docker build, 브라우저 기반 통합 검수까지 닫히지 않아 `finished` 로 올리기에는 근거가 부족하다. 같은 근거를 유지한 채 backlog 로 되돌린다.
