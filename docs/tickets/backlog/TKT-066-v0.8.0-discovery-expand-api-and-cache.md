# TKT-066

## 메타데이터

- 제목: 발견 노선 depth 2~3 확장 API와 캐싱 (Claude API 프록시)
- 우선순위: P2
- 대상 버전: `v0.8.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `v0.8.0 진행 시 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-066-discovery-expand-api`

## 목표

발견 노선에서 사용자가 depth 1 아래로 더 파고들 때만 Claude API 로 설명을 온디맨드 생성하고 캐싱하는 게이트웨이 경로를 만든다. 정적 depth 0~1(`TKT-065`)과 결합해 토큰을 아낀다.

## 작업 내용

1. 게이트웨이에 `POST /api/discovery/expand` 를 추가한다. body: `{ topicId, path: ["deeper", "twist", ...] }` (path 길이 = depth, 최대 3).
2. 캐시 우선: `gateway/data/discovery-cache.json`(또는 동등 저장소)에서 `{topicId, path}` 키로 조회해 히트면 저장분을 반환한다.
3. 미스면 **로컬 Ollama(RTX5070)** 를 호출한다.
   - 프롬프트: 해당 주제(`topics.json` 의 title/teaser)와 지금까지의 path(선택 경로)를 맥락으로 주고, 한 단계 더 파고든 2~4문장 한국어 설명을 요청한다.
   - LLM 제공자는 로컬 Ollama 로 확정(`docs/ollama-policy.md`, `OLLAMA_BASE_URL`). Claude API 등 외부 유료 제공자는 쓰지 않는다.
   - 시크릿은 서버 환경변수로만 둔다(프런트/저장소에 쓰지 않는다).
4. 응답을 캐시에 저장하고 반환한다. 같은 노드 재요청은 이후 토큰 0.
5. `TKT-065` 의 depth 2~3 버튼을 이 엔드포인트에 연결한다.
6. 실패/미설정(키 없음, 제공자 down) 시 사용자에게 "지금은 더 파고들 수 없다" 수준으로 저하 처리하고 depth 0~1 은 계속 동작하게 한다.

## 범위

- 포함: expand 엔드포인트, 캐시 저장/조회, 로컬 Ollama 호출, 저하 처리, 프런트 연결.
- 제외: depth 0~1(TKT-065), 스트리밍 응답, 사용자별 캐시 격리, 무한 depth.

## 완료 기준

- depth 2 버튼을 누르면 설명이 생성되어 표시된다.
- 같은 노드를 다시 열면 캐시에서 즉시(추가 토큰 없이) 나온다.
- 키 미설정/제공자 장애 시 앱이 깨지지 않고 저하 메시지를 보인다.
- 게이트웨이 테스트와 `tools/run-gateway-tests.ps1` 가 통과한다.
