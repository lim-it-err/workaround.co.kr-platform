# TKT-063

## 메타데이터

- 제목: Work Manager 저장소 정합 (persistence 키/감사 로그/seed 피드/게이트)
- 우선순위: P2
- 대상 버전: `v0.4.1`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-063-work-manager-store-consistency`

## 목표

Work Manager 저장소·피드·게이트의 정합성 결함을 닫아, 재시작 후 데이터 유실, 유령 seed 피드, fail-open 게이트, 렌더되지 않는 타임스탬프를 없앤다.

## 작업 내용

1. [MAJOR] command-history 영속화 키 불일치로 재시작 후 데이터 유실 (#2)
   - 저장은 `requestedBy`/`requestedAt` 키로 쓴다(`toMap`, `gateway/src/main/java/com/workaround/platform/gateway/PlatformGatewayApplication.java:2166-2179`). 로드는 `actor`/`createdAt` 키로 읽는다(`gateway/.../PlatformGatewayApplication.java:314-324`). 키가 어긋나 재시작마다 blank 가 된다.
   - 저장 파일이 증거다: in-session `gateway/data/work-manager-store.json:11-12` vs reloaded `:22-23`, `:33-34`, `:44-45`.
   - 수정 방향: 저장/로드 키를 일치시킨다. #9 와 함께 API 표면과 일치하는 `requestedBy`/`requestedAt` 로 통일하는 것을 기본으로 한다.

2. [MINOR] command-history 타임스탬프가 UI 에 렌더되지 않음 (#9)
   - 템플릿은 `formatTimestamp(entry.createdAt)` 를 쓴다(`frontend/src/App.vue:4180-4187`). API 는 `requestedAt` 를 준다(`gateway/.../PlatformGatewayApplication.java:2174`).
   - `formatTimestamp` 는 입력이 없으면 빈 문자열을 반환한다(`frontend/src/App.vue:2217-2220`).
   - 수정 방향: 템플릿이 `entry.requestedAt` 를 읽게 한다(#2 의 키 통일과 정합시킨다).

3. [MINOR] audit 로그가 메모리/디스크 모두 20개로 잘림 (#8)
   - `recordWorkManagerAudit` 가 20개로 캡한다(`gateway/.../PlatformGatewayApplication.java:1788-1790`). feed 는 12(`:1703-1705`), command 는 12(`:1711-1713`), persist 도 캡된 값만 저장한다(`:350-352`).
   - 잘리는 audit 은 defect 다. UI `auditEventCount`(`frontend/src/App.vue:3944`)가 20 을 넘지 못한다.
   - 수정 방향: audit 을 append-only 또는 rotated 파일 sink 로 분리해 잘리지 않게 한다(메모리 표시 캡과 영속 audit 을 분리). TKT-043(DB 전환)과 커플링되므로 Notes 참조.

4. [MINOR] seed activity feed 가 stale 하고 매 poll 마다 재-타임스탬프 (#10)
   - `workManagerSeedActivityFeed`(`gateway/.../PlatformGatewayApplication.java:1603-1664`)가 need_review 의 TKT-031/034 를 제목 키로 삼지만(`:1606-1608`) 실제로는 Finished 다(`docs/tickets/board.md:49`, `:52`).
   - 타임스탬프를 매 fetch(8초 poll)마다 `now.minusSeconds(...)` 로 재계산해 seed 가 항상 최신으로 떠오르고, 실제 이벤트가 top-6(`frontend/src/App.vue:4172`) 아래로 밀린다.
   - 수정 방향: 실제 board 에서 파생하거나, seed 타임스탬프를 고정하거나, 실제 이벤트가 있으면 seed 를 드롭한다(기본: 실제 이벤트 존재 시 seed 미표시 + 고정 타임스탬프).

5. [MINOR] validateTransitionGate 가 파싱 불가 메타데이터에서 fail-OPEN (#11)
   - 게이트(`gateway/.../PlatformGatewayApplication.java:1263-1282`)가 `진행 판정` 이 blank 면 allowed 로 조기 반환한다(`:1271-1273`).
   - `readTicketMetadata` 는 예외 시 `{}` 를 반환한다(`gateway/.../PlatformGatewayApplication.java:1025-1027`). mojibake 티켓 TKT-031/032/033/034(헤더가 `## 메타데이터` 대신 `## ë©"íƒ€...` 로 깨짐)는 blank 게이트 -> 무조건 `-> started` 허용. 상세 패널도 blank 가 된다(`frontend/src/App.vue:4049-4092`).
   - 수정 방향: 메타데이터가 비면 fail-closed(전이 차단)로 바꾸고, 헤더 매칭이 BOM 을 허용하도록 관대화한다. (mojibake 파일 자체 복구는 별도 chore 로, Notes 참조.)

## 범위

- 포함: command-history 키 통일, 타임스탬프 렌더, audit append-only sink, seed feed 정합, 게이트 fail-closed
- 제외: 인증(TKT-060/061), 전이 매트릭스 자체(TKT-062, 단 게이트 fail-closed 는 본 티켓 범위), 동시성/원자적 쓰기(TKT-064), mojibake 티켓 파일 복구(별도 chore), TKT-043 DB 전환 본체

## 완료 기준

- 재시작 후에도 command-history 의 actor/timestamp 가 보존된다. (런타임 체크: persist data loss on restart 해소)
- command-history 타임스탬프가 UI 에 정상 렌더된다.
- audit 이벤트가 20개를 넘겨도 영속 sink 에서 잘리지 않는다.
- 실제 이벤트가 있을 때 seed 피드가 최신 이벤트를 밀어내지 않는다.
- 메타데이터 파싱에 실패한 티켓의 `-> started` 전이가 차단된다(fail-closed). (런타임 체크: board/folder desync 맥락)
- persist round-trip 등 관련 테스트는 TKT-064 와 조율해 추가한다.
