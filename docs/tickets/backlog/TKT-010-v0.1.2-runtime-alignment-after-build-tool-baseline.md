# TKT-010

## 메타데이터

- 제목: 빌드 툴 기준선 이후 런타임 정렬
- 우선순위: P1
- 대상 버전: `v0.1.2`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 불가`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-010-runtime-alignment`

## 목표

`v0.1.1` 빌드 툴 기준선 이후 실제 실행 경로를 다시 맞춰 `v0.1.2` 를 런타임 정렬 버전으로 완성한다.

## 작업 내용

- 프런트엔드, 게이트웨이, 워커의 현재 빌드/실행 명령을 조사한다.
- `README.md` 와 각 하위 `README.md` 의 실행 절차가 실제 파일 구조와 맞는지 비교한다.
- 실행 도구가 없는 환경에서는 필요한 도구와 미검증 항목을 명시한다.
- 현재 로컬 기준으로 `java`, `mvn`, `docker` 가 PATH 에 없고 Maven/Gradle wrapper 도 없으므로, 이 세 도구를 어떻게 재현할지 결정한다.
- 프런트엔드는 `TKT-030` 에서 정리한 정식 기준선인 `Node.js 22 LTS + npm/npx` 를 표준으로 사용한다.
- Codex 제한 세션에서는 `tools/run-frontend-dev.ps1`, `tools/run-frontend-build.ps1` fallback 을 임시 재현 경로로만 사용한다.
- Python 서비스는 번들 Python 으로 syntax check 와 HTTP smoke 가 가능하다는 사실을 공식 로컬 절차에 반영한다.
- 게이트웨이는 JDK 21 과 Maven 3.9.x 를 기본값으로 두고, 실제 설치 또는 문서화가 완료될 때까지 blocker 를 명확히 남긴다.
- 수정한 실행 절차와 남은 위험을 문서에 반영한다.

## 범위

- 현재 저장소에서 프런트엔드, 게이트웨이, 워커의 실행 진입점과 빌드 기준선을 비교한다.
- 빌드는 되지만 실행이 어긋나는 지점, 또는 실행은 되지만 문서가 어긋나는 지점을 정리한다.
- 다음 작업자가 혼란 없이 따라갈 수 있도록 로컬 실행 절차를 맞춘다.
- `v0.2.0` 통합 프리뷰를 막는 런타임 불일치를 줄인다.
- 필요하면 관련 문서와 설정을 현재 저장소 기준에 맞게 조정한다.

## 완료 기준

- 주요 구성요소의 로컬 실행 경로가 현재 기준선과 맞게 문서화되거나 정렬되어 있다.
- 빌드 툴 기준선 이후 남아 있던 런타임 불일치가 명시적으로 해소되거나 기록되어 있다.
- 다음 작업자가 `v0.2.0` 통합 프리뷰를 준비할 때 참고할 수 있는 현재 상태가 정리되어 있다.
- 실행 불가 지점이 남아 있으면 재현 조건과 우회 경로가 문서에 남아 있다.
- 게이트웨이 컴파일 검증을 수행할 수 있는 Java/Maven 경로가 생기거나, 실행 불가 사유와 후속 설치 절차가 문서에 남아 있다.

## 질문/결정 기록

- 결정: 빌드 도구 버전과 플랫폼 운영 버전은 분리한다.
- 결정: `VERSION` 은 최신 배포 완료 버전이고, 개발 상한은 `docs/releases.md` 와 `docs/version-policy.md` 를 따른다.
- 결정: 2026-06-14 현재 `git` 은 PATH 에는 없지만 `C:\Program Files\Git\cmd\git.exe` 로 실행 가능하다.
- 결정: Codex 번들 Node 와 저장소 로컬 `tools/local-node/node.exe` 는 smoke 검증용 fallback 이며, 정식 로컬 기준선은 아니다.
- 결정: 2026-06-15 `TKT-030` 기준으로 프런트엔드의 정식 로컬 기준선은 Windows x64 `Node.js 22 LTS + npm/npx` 다.
- 열린 질문: Java/Maven/Docker 의 호스트 설치를 사용자 승인 후 실제로 수행할지, 문서화만 유지할지.

## 권장 검증 명령

도구가 준비된 환경에서는 아래 순서로 확인한다.

```powershell
java -version
mvn -version
docker --version
& 'C:\Program Files\Git\cmd\git.exe' --version
```

프런트엔드 정식 기준선 확인:

```powershell
node --version
npm --version
npx --version
Set-Location frontend
npm install
npm run build
```

Codex fallback 경로 확인:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\check-node-toolchain.ps1
powershell -ExecutionPolicy Bypass -File .\tools\run-frontend-build.ps1
```
