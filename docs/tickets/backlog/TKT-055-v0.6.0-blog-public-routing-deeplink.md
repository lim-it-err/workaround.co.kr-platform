# TKT-055

## 메타데이터

- 제목: 블로그 공개 라우팅/딥링크
- 우선순위: P1
- 대상 버전: `v0.6.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-055-blog-public-routing-deeplink`

## 목표

라이브 블로그에 실제 URL/딥링크/새로고침 지속성을 부여해 공개 호스팅이 가능하게 한다. 블로그 목록과 글 상세가 고유 경로를 갖고, 새로고침/뒤로가기에도 같은 화면이 유지되며, 없는/보관된 슬러그는 엉뚱한 글 대신 not-found 를 보여주게 한다.

## 작업 내용

아래 각 항목은 2026-07-05 블로그 QA 조사의 발견 번호와 정확한 파일:라인을 근거로 한다. 라인은 모두 `frontend/src/App.vue` 기준이다.

1. (발견 #3, MAJOR) 라이브 블로그의 URL/딥링크/새로고침 지속성 추가.
   - 근거: `LIVE_PAGES` `frontend/src/App.vue:12-15`, `syncTestLocation` 조기 반환 `frontend/src/App.vue:2315-2318`, `readInitialPage` 가 splash 로 보냄 `frontend/src/App.vue:2276-2285`, `popstate` 처리 없음. 글 상세에서 새로고침하면 splash→junction 으로 튕겨 공개 호스팅이 불가능하다.
   - 수정 방향: 실제 경로 `/blog`(목록), `/blog/:slug`(상세) 를 도입하고 History API(`pushState`/`popstate`)로 앞으로/뒤로/새로고침을 지원한다. 초기 로드 시 현재 경로를 읽어 해당 화면으로 복원한다(splash 강제 이동 제거). URL 스킴은 이후 라우터 도입과 충돌하지 않도록 설계한다(선행 조건 참고).
2. (발견 #10, MINOR) 없는/보관된 슬러그에 대해 not-found 상태 노출.
   - 근거: `activeBlogPost` `frontend/src/App.vue:879-885` 와 `openBlogPost` `frontend/src/App.vue:1428-1431` 가 매칭 실패 시 `published[0]`(첫 글)를 보여준다.
   - 수정 방향: 매칭되는 published 슬러그가 없으면 명시적 not-found 상태(전용 화면/메시지)를 렌더한다. 첫 글로 폴백하지 않는다. 보관(archived) 슬러그도 공개 경로에서는 not-found 로 취급한다.

## 범위

- 포함: `/blog`, `/blog/:slug` 경로, pushState/popstate 기반 앞뒤/새로고침 지속성, 초기 경로 복원, not-found 상태. 대상 파일은 `frontend/src/App.vue` (필요 시 `frontend/src/styles.css`).
- 제외: 저장/발행 무결성(→ TKT-054), 아카이브 목록/복원과 배지(→ TKT-056), 마크다운 렌더러(→ TKT-057), 전체 라우터 라이브러리 도입과 대규모 App.vue 컴포넌트 분해(연계는 하되 이 티켓의 완료 조건은 아니다), 서버측 라우팅/SSR, localStorage 견고화(#6, Phase 4).

## 완료 기준

- 글 상세에서 새로고침해도 같은 글이 유지되고 splash/junction 으로 튕기지 않는다. QA 런타임 체크 "refresh/back on post" 통과.
- 뒤로가기/앞으로가기가 블로그 목록↔상세 사이에서 자연스럽게 동작한다.
- 없는/보관된 슬러그로 접근하면 첫 글이 아니라 not-found 가 보인다.
- 공개 글의 URL 을 복사해 새 탭에서 열면 같은 글이 열린다(딥링크).
- production build 또는 동등한 검증이 성공한다.

## 선행 조건

- 하드 블로커는 없음. 이 티켓은 네이티브 History API(`pushState`/`popstate`)만으로 지금 진행할 수 있다.
- 단, 이 작업은 예정된 App.vue 라우터 채택 + 컴포넌트 분해(Phase 2)와 결합된다. URL 스킴(`/blog`, `/blog/:slug`)이 이후 라우터 도입과 충돌하지 않도록 경로/상태 접근을 설계한다. 라우터 도입 티켓이 먼저 열리면 그 위에서 구현한다.

## 질문/결정 기록

- 결정: 첫 공개 경로는 `/blog`(목록)과 `/blog/:slug`(상세)로 둔다. (QA #3 수정 방향)
- 결정: 없는/보관 슬러그는 `published[0]` 폴백이 아니라 not-found 로 처리한다. (QA #10)
- 결정: localStorage 견고화/다중 탭 동기화(#6)는 이 티켓이 아니라 서버측 저장 전환 티켓(Phase 4)에서 다룬다.
- 열린 질문: 전용 라우터 라이브러리를 이 티켓에서 도입할지, 아니면 History API 로만 먼저 열고 라우터 도입 티켓에서 통합할지. 기본값은 History API 우선.
