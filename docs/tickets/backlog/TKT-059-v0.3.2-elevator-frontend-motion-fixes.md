# TKT-059

## 메타데이터

- 제목: 엘리베이터 프런트 모션 수정 B (렌더 동기화·경계 표시·타이머 정리)

- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-059-elevator-frontend-motion-fixes`

## 목표

엘리베이터 시뮬의 프런트 렌더 측 결함을 고쳐 이동이 매끄럽게 보이고, 층 경계/카운트 표시가 서로 일치하며, 페이지를 떠난 뒤에도 poll 타이머가 계속 돌지 않게 한다. 모든 수정은 `frontend/src/App.vue` 와 `frontend/src/styles.css` 안에서 이루어진다. 서비스측 상태/시뮬 루프 수정은 TKT-058 이 담당한다.

## 작업 내용

각 항목은 QA 발견(2026-07-05)과 1:1로 대응한다. 인용한 `file:line` 은 착수 시점 기준이며, 리팩터로 줄이 밀리면 동일 함수/블록을 기준으로 판단한다. 아래에 나오는 서비스 `file:line`(`app.py`)은 원인 추적용 참고이며 이 티켓에서 고치지 않는다.

1. [MAJOR] easing/poll 불일치로 이동이 stutter(글라이드-정지 반복)로 보인다.
   - 위치: `frontend/src/styles.css:974-984`의 `transition: left 0.68s cubic-bezier(0.21, 1, 0.34, 1)`(`styles.css:983`)가 900ms poll(`frontend/src/App.vue:1201-1203`)과 어긋난다 → 0.68초 글라이드 뒤 0.22초 정지.
   - 원인 보강: `sync_state` 가 poll 당 2/3틱을 번갈아 전달(0.9/0.35≈2.57)해 점프량이 0.36/0.54층으로 교차한다. 베지어가 앞쪽에 몰려(≈150ms 안에 90%) whoosh 후 정착처럼 보인다. 숫자 readout(`frontend/src/App.vue:3265`)과 그리드 glyph 는 즉시 갱신되어 eased dot 과 어긋난다.
   - 수정 방향: transition 지속시간을 poll 간격(가능하면 `demand.stepSeconds`)에 맞추고, 거의 선형에 가까운 easing 으로 바꾸며, poll 당 틱 delta 를 고르게 반영해 점프량 교차를 줄인다. 숫자 readout/그리드 glyph 가 eased dot 과 같은 프레임에서 갱신되게 맞춘다.

2. [COSMETIC] `isCarNearFloor` 임계값 0.55 때문에 glyph 가 중복 표시된다.
   - 위치: `frontend/src/App.vue:1729-1731`(`isCarNearFloor`, 임계값 0.55), 사용처 `frontend/src/App.vue:3327`, `frontend/src/App.vue:3329`.
   - 증상: position 이 N.5 일 때 두 행에 동시에 매칭되어 glyph 가 중복된다. `.shaft-cell` 에는 transition 이 없어 카드 dot 이 easing 되는 동안 그리드가 튄다.
   - 수정 방향: 임계값을 0.5 미만으로 낮추거나 가장 가까운 정수 층에 대한 반올림 동치 비교로 바꿔 한 번에 한 행만 매칭되게 한다.

3. [MINOR] position dot 이 `minFloor=1` 을 하드코딩한다.
   - 위치: `frontend/src/App.vue:3280-3286`이 `minFloor=1` 을 하드코딩한다. 서비스 환경변수 `MIN_FLOOR`(`services/elevator-service/app.py:12`)와 어긋난다. 그리드는 `building.minFloor` 를 올바르게 쓴다(`frontend/src/App.vue:731`).
   - 증상: `MIN_FLOOR` 가 1 이 아니면 dot 위치가 그리드와 어긋난다.
   - 수정 방향: dot 계산도 `building.minFloor` 를 사용한다.

4. [MINOR] intensity 슬라이더가 상태를 다시 읽지 않는다.
   - 위치: `frontend/src/App.vue:1288-1295`(`updateDemandIntensity`)가 POST 후 `loadElevatorState` 를 호출하지 않는다. 이벤트가 `@input` 이 아니라 `@change` 다(`frontend/src/App.vue:3214`). 프리셋/car 수 조작과 동작이 다르다.
   - 수정 방향: POST 후 상태를 await 로 다시 로드해 즉시 반영한다. 필요하면 `@input` + 디바운스도 선택적으로 적용한다.

5. [MINOR] fetch 실패 시 공유 fallback 으로 snap 해 warp 가 보인다.
   - 위치: `frontend/src/App.vue:1262-1268`이 실패 시 공유 `fallbackElevatorState`(정의 `frontend/src/App.vue:123-200`)로 되돌린다.
   - 증상: poll 한 번 실패 → car 가 2/8/14/20 층으로 warp 하고 demand 라벨이 바뀌었다가 다시 warp 로 복귀한다. fallback 이 참조로 공유되는 mutable 객체라 오염된다.
   - 수정 방향: 일시적 오류에서는 마지막으로 알려진 상태를 유지한다. fallback 은 deep-clone 해서 참조 공유를 끊는다. degraded(저하) 배지로 사용자에게 알린다.

6. [MINOR] 페이지 전환 시 타이머가 정리되지 않는다.
   - 위치: `frontend/src/App.vue:1201-1207`(`onMounted`)에서 시작한 타이머가 `onBeforeUnmount`(`frontend/src/App.vue:1210-1217`)에서만 정리된다.
   - 증상: 엘리베이터 900ms + 택시 1200ms poll 이 다른 페이지에서도 계속 돌아 보이지 않는 동안에도 시뮬이 진행/스폰된다(TKT-058 #2 와 맞물린다).
   - 수정 방향: `watch(page)` 로 현재 페이지에 맞춰 타이머를 시작/중지한다. 라우터/페이지 분해 작업과 결합되는 부분이므로 아래 "선행 조건" 을 따른다.

## 범위

- 포함: `frontend/src/App.vue` 와 `frontend/src/styles.css` 의 transition/easing 동기화, near-floor 임계값, position dot 의 `minFloor` 사용, intensity 반영, fallback 유지/deep-clone/배지, 페이지별 타이머 시작·정지.
- 제외: `services/elevator-service/app.py` 의 상태/시뮬/배차 수정(TKT-058), 엘리베이터 UI 전면 리디자인, 택시 시뮬레이터 로직, 라우터 전면 재작성(#6 는 최소 `watch(page)` 범위로만).

## 완료 기준

기능 기준:

- car 이동이 글라이드-정지 반복 없이 부드럽게 이어지고, 숫자 readout/그리드 glyph/dot 이 같은 프레임에서 일치한다(#1).
- position 이 반 층(N.5)일 때 glyph 가 한 행에만 표시된다(#2).
- `MIN_FLOOR` 가 1 이 아니어도 dot 이 그리드와 정렬된다(#3).
- intensity 슬라이더 조작이 프리셋/car 수와 동일하게 즉시 반영된다(#4).
- poll 이 한 번 실패해도 car 가 fallback 층으로 warp 하지 않고 마지막 상태를 유지하며 degraded 배지가 뜬다(#5).
- 엘리베이터/택시 페이지를 떠나면 해당 poll 타이머가 멈춘다(#6).

런타임 확인(QA 의 "runtime checks" 를 인수 검사로 사용):

- 60fps stutter 녹화: 화면 녹화로 whoosh-정지 패턴이 사라졌는지 확인.
- half-floor 이중 glyph: position 을 N.5 로 만들어 glyph 가 한 행에만 뜨는지 확인.
- `MIN_FLOOR=-2` 테스트: 서비스 `MIN_FLOOR=-2` 로 띄워 dot 과 그리드가 정렬되는지 확인.
- fallback snap on kill: 서비스를 잠깐 죽여 poll 을 실패시켜 car 가 warp 하지 않고 배지가 뜨는지 확인.
- 페이지 전환 후 타이머가 멈추는지(다른 페이지에서 poll 요청이 더 나가지 않는지) 네트워크 탭으로 확인.
- `frontend` build 검증 결과를 남긴다.
