# TKT-012

## 메타데이터

- 제목: 테스트 코드와 커버리지 기반 정리
- 우선순위: P1
- 대상 버전: `v0.2.1`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `v0.2.1 진행 시 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-012-test-coverage-foundation`

## 목표

핵심 흐름을 보호할 테스트 코드를 추가하고, `v0.2.1` 에서 커버리지를 측정하는 기반을 마련한다.

## 작업 내용

- 프런트엔드, 게이트웨이, 워커 중 가장 먼저 보호해야 할 핵심 경로를 고른다.
- 해당 경로에 최소 자동화 테스트를 추가한다.
- 커버리지 측정이 가능한 도구와 명령을 정리한다.
- CI에 바로 붙일 수 있는 형태인지 확인하고, 아니면 후속 티켓을 남긴다.
- 테스트 공백과 우선순위를 문서화한다.

## 범위

- 현재 저장소에서 자동화 테스트가 가장 먼저 필요한 영역을 고른다.
- 대표적인 테스트 코드를 추가하거나 테스트 구조를 정리한다.
- 커버리지 측정 명령, 출력물, 또는 보고 경로를 정의한다.
- 로컬에서 테스트와 커버리지를 어떻게 실행하고 해석하는지 문서화한다.
- 이후 버전이 이 기반을 이어받을 수 있도록 남은 공백을 정리한다.

## 완료 기준

- 핵심 경로를 다루는 자동화 테스트가 적어도 하나 이상의 실행 가능한 경로로 존재한다.
- 커버리지를 측정하는 방법이 문서화되어 있거나 구현되어 있다.
- 테스트와 커버리지 실행 절차가 작업자와 오케스트레이터 모두에게 재현 가능하다.
- 남은 테스트 공백과 다음 단계가 명시되어 있다.

## 선행 조건

- `v0.2.0` 구현 결과 또는 보호할 핵심 경로가 확정되어야 한다.
- `v0.2.0` 전에는 테스트 후보 조사와 계획까지만 진행한다.

## 질문/결정 기록

- 결정: `v0.2.1` 은 테스트와 커버리지 기반 안정화 버전이다.
- 결정: `v0.2.0` 배포 전에는 이 티켓이 기능 작업 상한을 밀어 올리지 않는다.
- 열린 질문: 첫 테스트 대상은 `v0.2.0` 구현 결과를 본 뒤 다시 우선순위를 조정할 수 있다.
