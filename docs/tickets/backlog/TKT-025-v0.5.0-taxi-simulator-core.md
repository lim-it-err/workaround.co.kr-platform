# TKT-025

## 메타데이터

- 제목: 택시 시뮬레이터 코어
- 우선순위: P1
- 대상 버전: `v0.5.0`
- 상태: `backlog`
- 문서 상태: `작성완료`
- 진행 판정: `v0.5.0 진행 시 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-025-taxi-simulator-core`

## 목표

가상의 지도 위에서 랜덤/수동 호출이 발생하고, 인원수에 따라 택시가 이동하며, 처리 시간 기반 리워드와 차량 추가 패널티를 보여주는 택시 시뮬레이터 코어를 만든다.

## 작업 내용

- 가상의 지도 또는 구역 기반 보드를 만든다.
- 랜덤 호출을 생성한다.
- 사용자가 수동으로 출발지, 도착지, 인원수를 넣을 수 있게 한다.
- 호출에 따라 적절한 택시가 이동하도록 기본 배차 흐름을 구현한다.
- 처리 시간을 측정하고 리워드에 반영한다.
- 차량을 추가 배치할 때 리워드를 깎는 규칙을 구현한다.
- 프런트에서 차량 상태, 현재 요청, 처리 시간, 누적 리워드를 읽을 수 있게 한다.
- 강화학습/자동학습은 `v0.5.1` 후속으로 분리하고, 이번 티켓에서는 게임/시뮬레이션 코어에 집중한다.

## 범위

- 포함: 지도/구역 시각화, 요청 생성, 수동 요청 입력, 기본 배차, 리워드 계산, 상태 표시, 문서 갱신
- 제외: 사람 피드백 루프, RTX5070 평가 보조, 자동 학습 파이프라인, 멀티플레이, 실제 지도 API 연동

## 완료 기준

- 택시 시뮬레이터가 별도 기능 페이지 또는 명확한 포털 진입 경로에서 동작한다.
- 랜덤 호출과 수동 호출이 모두 가능하다.
- 인원수에 따라 차량 이동 결과가 달라진다.
- 처리 시간이 리워드에 반영된다.
- 차량 추가 배치 시 패널티가 반영된다.
- 시뮬레이터 상태를 프런트에서 읽을 수 있다.

## 선행 조건

- `TKT-024` 시뮬 포털 진입 구조가 먼저 열려야 한다.
- 택시 시뮬레이터 서비스 경계 또는 프런트 단독 프로토타입 경계 중 기본안이 정리되어야 한다.

## 질문/결정 기록

- 결정: 처리 시간은 리워드로 둔다.
- 결정: 차량 추가 배치는 리워드 패널티로 둔다.
- 결정: 사용자 수동 입력은 출발지, 도착지, 인원수를 포함한다.
- 열린 질문: 첫 버전을 프런트 단독 시뮬레이션으로 둘지, 별도 서비스 계약으로 바로 분리할지.
- 열린 질문: 지도 표현을 자유 좌표 기반으로 둘지, 단순 구역 기반으로 둘지.
