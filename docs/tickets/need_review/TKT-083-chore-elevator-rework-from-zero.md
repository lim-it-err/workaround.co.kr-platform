# TKT-083

## 메타데이터

- 제목: 엘리베이터 승강장 원점 재설계 — 표현·기능 전면 재검토
- 우선순위: P1
- 대상 버전: `chore`
- 상태: `need_review`
- 문서 상태: 작성완료
- 담당: 1단계 스펙 = claude / 2단계 구현 = `[SIM]` 레인
- scope(구현 단계): `frontend/src/**` 중 엘리베이터 모듈 한정

## 배경 (PO, 2026-08-17)

> "23층 수직 승강장 — 얘도 아무것도 안 해. 표현 방식부터 원점 재검토로 다시 진행해. 디자인, 기능 모두 별로야."

현재 화면의 근본 문제: 수치 타일 + 슬라이더 + 텍스트 상태뿐이라 **아무 일도 일어나지 않는 것처럼 보인다.** 시뮬레이터인데 시뮬레이션이 안 보인다 (택시 TKT-074 와 동일 계열 — 관측성 부재).

## 진행 방식 (2단계)

1. **스펙 (claude)**: `design/` 에 재설계 문서 — ①이 시뮬의 존재 이유(핵심 루프) 재정의 ②**수직 단면 뷰**(샤프트×층 그리드에서 car 가 실제로 움직이고, 층별 대기 인원이 보이고, 호출→반응이 즉시 시각화) ③자동 수요 흐름(방치해도 살아있는 화면) ④조작부 최소화. 좌표·컴포넌트·상태 모델까지 코덱스가 추측 없이 구현 가능한 수준으로.
2. **구현 (`[SIM]`)**: 스펙 확정 후 ready 전환. 완료 게이트 = build + 다크/라이트 + 모바일 + "방치 30초 관찰 시 화면에 변화가 보인다" 체크.

## 원칙

- 원점 재검토라도 **도메인 계약은 유지** (사람 단위 모델·연속 위치·워프 금지 — feature-definition).
- 스펙 없이 구현부터 시작하지 않는다 — "뭐가 뭔지 모를 화면"의 재생산 방지.

## 작업 진행

- 2026-08-17 `[SIM]` codex-1 착수 — `design/sim-elevator-spec.md` R1 승인본 기준.

## 구현 결과

- `ElevatorCrossSection.vue`를 추가해 23층 눈금, 층별 대기 도트, 4개 shaft, 연속 `position` 기반 car를 하나의 수직 단면으로 표시했다. car 위치에는 CSS transition을 사용하지 않았다.
- 기존 목록형 car/dispatch 표를 제거하고 대기·탑승·이동 중·평균 대기 지표, 한산·보통·혼잡 프리셋, 최근 8건 이벤트로 우측 패널을 재구성했다.
- 강도·car 수·초기화는 고급 설정으로 접었고, 층 클릭은 즉시 생성 도트를 표시한 뒤 해당 층 승객 추가 API를 호출한다.
- 화면 진입 시 자동 수요를 활성화하고 기존 시간대 프리셋은 기본 `보통`으로 정규화한다. 모바일에서는 단면을 먼저, 패널을 아래에 두고 최근 운행은 접힌 상태로 시작한다.

## 검증

- `cd frontend && npm run build`: 통과 (Vite 6.4.3, 16 modules, 656ms).
- 데스크톱 1280px: 다크·라이트 육안 확인, 양 테마에서 `--line-e` car/track 대비와 70:30 단면·패널 배치 확인, 최종 브라우저 console error 0.
- 모바일 375×812: `documentElement`/`body` 모두 `scrollWidth=clientWidth=375`, 단면 315.68px 폭·60vh, 패널이 단면 아래 배치되고 최근 운행이 기본 접힘임을 확인.
- 30초 방치: car 위치 4대 모두 변화, 대기 도트 13→9, 최근 이벤트 목록 갱신 확인. 시작/종료 시점 모두 이동 중 car 4대.
- 12F 클릭: 즉시 생성 도트 1개와 대기 1명 표시, 2.2초 뒤 car 위치 변화로 반응 확인.

## 남은 위험

- 현 워킹트리의 gateway는 다른 레인 변경 상태에서 Spring `PlatformApiController` 생성자 오류로 기동되지 않았다. SIM 검증은 코드를 수정하지 않고 임시 로컬 프록시로 실제 `elevator-service:8003`에 연결해 수행했으며, gateway 회귀 판정은 플랫폼 레인 검토가 필요하다.
