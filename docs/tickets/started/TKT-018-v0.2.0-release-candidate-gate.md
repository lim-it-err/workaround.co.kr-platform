## 메타데이터

- 제목: `v0.2.0` 릴리스 후보 검증과 PR 수용 게이트
- 우선순위: P1
- 대상 버전: `v0.2.0`
- 상태: `started`

## 목표

사용자가 `v0.2.0 배포해도 돼` 라고 말하기 전까지, 현재 들어온 PR과 finished 티켓이 `v0.2.0` 릴리스 후보로 충분한지 검토하고 남은 막힘을 명확히 한다.

## 작업 내용

- `docs/tickets/board.md` 와 실제 티켓 파일 위치가 일치하는지 확인했다.
- `TKT-005` 통합 프리뷰 결과와 `TKT-016` 준비 슬라이스 결과가 `docs/releases.md` 의 `v0.2.0` 목표와 맞는지 확인했다.
- `TKT-010` 런타임 정렬 티켓의 상태를 점검하고, 릴리스 차단 여부를 구분했다.
- `TKT-019` 로컬 빌드/PR 도구 preflight 결과를 확인하고, gateway compile / Docker build / Git PR 준비 가능 여부를 체크리스트에 반영했다.
- `TKT-020` 결과를 확인해 gateway 티켓 생성 기본 `serviceId` 가 `sample-python-service` 로 남아 있지 않은지 확인했다.
- 사용자가 확인해 넣는 PR들이 어떤 티켓을 닫는지 추적하고, board와 history를 갱신했다.
- `VERSION`, `docs/releases.md`, `docs/roadmap.md`, `docs/steering.md`, `docs/version-policy.md` 를 함께 점검해 `v0.2.0` 이 아직 조건부 릴리스 후보라는 상태를 다시 맞췄다.
- 릴리스 승인 시 필요한 체크리스트를 `docs/releases.md` 와 티켓 Notes에 정리했다.

## 범위

- 새 기능 구현이 아니라 릴리스 후보 검증과 오케스트레이터 수용 판단을 다룬다.
- PR 생성, PR 본문 작성, 티켓 상태 갱신, 히스토리 갱신 기준을 확인한다.
- Git tag, GitHub Release, `VERSION` 승격은 사용자 승인 이후 절차로 남겨두었다.
- 공개 도메인 배포는 `TKT-014`, GitHub Actions 기준선은 `TKT-015` 로 분리한다.

## 완료 기준

- `v0.2.0` 릴리스 후보에 포함할 티켓과 제외할 티켓이 구분되어 있다.
- `v0.2.0` 릴리스를 막는 항목이 있으면 board 또는 Notes에 명시되어 있다.
- 사용자에게 `v0.2.0` 배포 승인 여부를 물을 수 있는 체크리스트가 준비되어 있다.
- 승인 전에는 릴리스 태그, GitHub Release, `VERSION` 승격을 하지 않았다는 점이 기록되어 있다.

## 질문/결정 기록

- 결정: `v0.2.0` 은 큰 구현 묶음이 아니라 최종 통합 프리뷰 릴리스 게이트다.
- 결정: 사용자가 명시적으로 승인하기 전까지 `VERSION` 을 `0.2.0` 으로 올리지 않는다.
- 결정: 사용자가 PR을 확인해 넣으면 오케스트레이터가 티켓과 릴리스 문서를 갱신한다.
- 결정: `TKT-010` 이 끝나기 전의 `v0.2.0` 은 정식 승인 가능한 완료 상태가 아니라 조건부 릴리스 후보로만 본다.
- 결정: `TKT-011` 은 `v0.3.0` 선작업 PR 후보로 문서화할 수 있지만, Java/Maven 컴파일 전에는 finished 또는 ready PR 로 승격하지 않는다.
- 결정: `TKT-010` 의 기본 해결책은 JDK 21, Maven 3.9.x, Git, Docker 를 worker/로컬 환경에 준비하는 것이다.
- 결정: Docker 는 공개 서버 배포와 컨테이너 빌드 검증에 필요하지만, gateway Java 컴파일 확인은 Maven 로컬 빌드로 먼저 막힘을 줄인다.
- 결정: `TKT-010` 의 도구 확인 부분은 `TKT-019` 로 분리해 먼저 처리한다.
- 결정: gateway 티켓 생성 기본 `serviceId` 의 `sample-python-service` 잔여값은 `TKT-020` 으로 분리해 처리한다.
- 결정: `TKT-019` 이후 `TKT-010` 과 `TKT-020` 은 병렬 진행 가능하며, `TKT-018` 이 둘의 결과를 모아 최종 판단한다.
- 결정: 사용자가 명시적으로 지시한 범위에서는 `v0.2.0` 배포 전에도 `v0.3.0` 선작업을 진행할 수 있다. 다만 이것은 `VERSION` 승격이나 `v0.2.0` 배포 승인으로 해석하지 않는다.

## Notes

- 이 티켓은 `v0.2.0` 배포 전까지 오케스트레이터가 반복적으로 갱신한다.

- `TKT-010` 이 끝나지 않았기 때문에 현재 `v0.2.0` 은 “로컬 프런트 HTTP/build 검증 완료, 게이트웨이 컴파일 미검증” 상태의 조건부 후보로 본다.
- 원격 GitHub 에 열린 PR 이 새로 생기면 오케스트레이터가 티켓 ID, 테스트 근거, 릴리스 포함 여부를 이 티켓에 추가한다.
