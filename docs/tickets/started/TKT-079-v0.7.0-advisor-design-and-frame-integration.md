- 대상 버전: `v0.7.0`
- 상태: `started` — `blocked` (Pages 배포 연결 담당/수정 범위 PM 결정 대기)

## 배경 (PO 지시)

advisor 는 2026-08-16 subtree 로 흡수됐다(D-008). PO: **"흡수하고 디자인이 다른 건 백로그로"** — advisor 프런트(Vue 3 프로토타입, 자체 스타일)는 모선의 지하철/노선 디자인 언어와 다르다. 기능 편입과 디자인 통합을 분리해, 디자인 차이는 이 티켓이 담당한다.

## 작업 내용

- `design/` 기준선 문서에 advisor 화면 진단 1장 추가 (현행 스타일 vs 모선 토큰 차이 목록).
- advisor 미션 화면(`services/advisor/frontend/src/modules/missions/` — 이식 단위로 동결돼 있음)을 모선 프레임에 연결:
  - 1안(기본): 미션 모듈을 모선 `frontend/src/modules/advisor/` 로 가져와 모선 토큰·내비를 적용.
  - 2안(과도기): advisor 프런트를 별도 빌드로 두고 `/advisor` 경로 서빙 + 모선 상단 프레임만 공유.
  - 선택 근거를 티켓에 기록하고 진행.
- 모선 노선도/게임·서비스 목록에 advisor 역 등록 (D-006 매니페스트).
- 콘텐츠 파일(`sampleContent.js` 등)은 **불가침** — 톤·문구 수정 금지 (advisor AGENTS.md 동결 계약).

## 완료 기준

- advisor 화면이 모선 디자인 토큰(색·타이포·간격)으로 렌더된다.
- 모선 내비에서 advisor 로 진입·복귀가 자연스럽다 (같은 오리진 경로).

- 편입 전후 화면 비교 기록을 히스토리에 남긴다.

### 2026-09-09 codex-1 — 1단계 정적 진입 연결 사전 점검

- 인박스 지시: TKT-100 need_review 뒤 `/advisor` 별도 정적 빌드 연결 및 노선도 A 개통을 먼저 수행. TKT-100의 need_review 상태를 확인했다.
- 현재 `.github/workflows/deploy-github-pages.yml`은 모선 `frontend`만 설치·빌드하고 `frontend/dist`만 Pages에 업로드한다. Advisor 설치·빌드·산출물 병합 단계가 없다.
- `infra/public-site/prepare-github-pages.mjs`는 모선 `index.html`을 루트 `404.html`로 복사한다. 별도 Advisor 앱의 깊은 경로를 선택하는 분기는 없다. `frontend/public`·`frontend/dist`에도 Advisor 산출물이 없음을 확인했다.
- Advisor router는 `createWebHistory(import.meta.env.BASE_URL)`이므로 project base를 포함한 `/workaround.co.kr-platform/advisor/` 빌드 및 하위 경로 새로고침 처리와 모선 복귀를 함께 검증해야 한다.
- 현재 티켓 scope에는 `.github/workflows/**`, `infra/**`, 모선 `frontend/vite.config.js`/`package.json`이 없다. 레인 지침도 `services/` 수정을 금지하므로, 기존 티켓의 `services/advisor/frontend/**` 허용과의 우선관계까지 PM이 명시해야 한다.
- **PM 질문**: ① Pages 빌드/산출물 병합/깊은 경로 처리를 codex-2의 명시적 티켓으로 배정할지, ② 이 티켓 및 레인 예외에 필요한 파일을 명시해 codex-1이 함께 수행할지 결정해 주세요. 현재 1단계에 별도 빌드를 지정한 인박스를 모듈 복사 방식으로 임의 대체하지 않았다.
- 해제 조건: 배포 연결 담당과 수정 범위가 확정되고, 같은 오리진 Advisor 진입 경로를 검증할 수 있는 빌드 계약이 마련될 것. 그 뒤 A의 upcoming 해제와 진입·복귀·375px·회귀 게이트를 수행한다.
