## 목표

스플래시 이후 첫 화면을 `Main page` 로 두고, Work Manager 와 각 시뮬레이터를 기능별 페이지로 분리해 페이지 길이를 줄이며, 전체 포털에 일관된 디자인 시스템과 다크모드를 도입한다.

## 작업 내용

- 스플래시 이후 진입 화면을 `Main page` 로 재구성한다.
- `Main page` 에서 Work Manager, Elevator Station, 후속 시뮬레이터 등 기능별 페이지로 라우팅한다.
- 각 기능 페이지에는 명확한 `Main page 로 돌아가기` 동선을 둔다.
- Work Manager 와 Elevator Station 을 같은 긴 스크롤 안에 억지로 쌓지 않고 기능별 페이지로 분리한다.
- 디자인 기준은 현재 `design/` 문서와 `docs/frontend-ux.md` 를 따른다.
- 라이트/다크 모드를 둘 다 지원하고, CSS 토큰 또는 동등한 테마 구조를 정리한다.
- 디자이너 에이전트가 아직 고정되지 않았더라도, 현재는 일관된 기준선 중심으로 디자인을 정리한다.
- 검수용 `/test` 더미가 기본 `/` 사용자 경로를 덮어쓰지 않도록 유지한다.

## 범위

- 포함: Main page, 기능별 라우팅, 뒤로가기, 다크모드, 공통 토큰 정리, 문서 갱신
- 제외: 새 시뮬레이터 본체 구현, 멀티테넌트 테마, 개인화 설정 동기화

## 완료 기준

- 스플래시 이후 `Main page` 가 먼저 보인다.
- Work Manager 와 Elevator Station 이 기능별 페이지로 분리된다.
- 기능별 페이지에서 `Main page` 로 돌아갈 수 있다.
- 라이트/다크 모드가 모두 동작하고, 최소한 Work Manager 와 Main page 에서 같은 위계가 유지된다.
- `/test` 는 검수 경로로 남고, `/` 는 실사용 포털로 남는다.

## 선행 조건

## 질문/결정 기록

- 결정: 페이지가 길어지는 문제를 피하기 위해 Main page 기반 기능 분리를 한다.
- 결정: 다크모드는 후속이 아니라 `v0.4.0` 안에 넣는다.
- 결정: 첫 진입 테마 기본값은 저장된 사용자 선택이 없으면 시스템 `prefers-color-scheme` 를 따른다.
- 결정: 검수 전용 `/test` 경로에서는 스플래시를 건너뛰고 `junction|elevator|work|runtime` 뷰를 직접 열 수 있게 유지한다.

## 작업자 산출물

- `frontend/src/App.vue` 기준으로 `splash -> junction -> elevator/work/runtime` 라우팅 구조가 동작하도록 정리돼 있다.
- 메인 허브는 `junction` 페이지에서 요약 카드와 환승 동선만 보여 주고, 실제 조작 화면은 `elevator`, `work`, `runtime` 기능 페이지로 분리돼 있다.
- 각 기능 페이지 상단에는 `Main page 환승 홀로` 복귀 버튼이 있어 허브로 되돌아갈 수 있다.
- `/test` 경로는 `?view=junction|elevator|work|runtime` 쿼리로 개별 검수 진입이 가능하고, 기본 `/` 경로는 실제 API 연결 포털을 유지한다.
- 테마는 `localStorage` 저장값이 없으면 시스템 `prefers-color-scheme` 를 따르고, 전체 포털은 `data-theme` 기반 토큰 구조로 라이트/다크 2모드를 지원한다.
