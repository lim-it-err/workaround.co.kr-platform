# TKT-031

## 메타데이터

- 제목: Work Manager 메뉴와 Jira 스타일 티켓 보드
- 우선순위: P1
- 대상 버전: `v0.4.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-031-work-manager-board`

## 목표

기존 웹사이트 안에 별도 admin 앱을 두지 않고 `Work Manager` 메뉴를 추가해, Jira 스타일의 티켓 보드와 컬럼 기반 상태 흐름을 같은 프런트엔드 안에서 보여준다.

## 작업 내용

- `frontend` 에 `Work Manager` 메뉴 또는 진입점을 추가한다.
- `backlog`, `started`, `need_review`, `finished` 컬럼을 보드 형태로 보여준다.
- 각 컬럼에는 티켓 번호, 제목, 우선순위, 대상 버전, 진행 판정을 보여준다.
- 티켓을 드래그하거나 이동 액션으로 다른 컬럼으로 옮길 수 있는 UI 를 만든다.
- 기본안은 같은 웹사이트 안의 work-manager route 또는 패널이며, 별도 admin 전용 앱은 만들지 않는다.
- 티켓 상세 패널에서 `작업 내용`, `선행 조건`, `Notes`, `검토 메모` 를 읽을 수 있게 한다.
- command 패널과 활동 로그 패널이 들어갈 오른쪽 레이아웃 슬롯을 함께 잡는다.

## 범위

- 포함: Work Manager 메뉴, 보드 레이아웃, 컬럼 표현, 상세 보기, 활동 로그 표시 영역, 프런트 라우팅/패널 구조, 문서 갱신.
- 제외: 실제 명령 실행 백엔드, 비밀번호 검증, 암호화 저장, worker 명령 프로토콜, 릴리스 승인.

## 완료 기준

- 웹사이트 안에서 `Work Manager` 메뉴로 들어갈 수 있다.
- Jira 스타일 컬럼 보드가 보인다.
- 티켓 이동 UI 가 존재하고, 이후 backend 연동 지점이 명확하다.
- 오른쪽 패널에 command 입력 영역과 활동 로그 표시 영역이 함께 포함된다.
- `frontend` build 또는 동등 검증이 성공한다.

## 선행 조건

- `TKT-018` 기준 현재 티켓 상태 표현 방식과 board 문서를 따른다.
- `docs/tickets/board.md` 와 각 티켓 본문 구조를 읽을 수 있는 최소 데이터 공급 경로가 필요하다.

## 질문/결정 기록

- 결정: 별도 admin 앱이 아니라 기존 웹사이트 안의 `Work Manager` 메뉴로 간다.
- 결정: 보드 UI 는 Jira 느낌의 컬럼 중심 흐름을 따른다.
- 결정: 조회(read-only) 보드는 공개로 두고, 이동/실행 같은 실행성 액션만 비밀번호로 막는다.
- 열린 질문: route 기반(`/work-manager`)으로 둘지, 메인 포털 내부 패널로 둘지.

## 검토 메모

- `frontend` 에 Work Manager 메뉴, 4컬럼 보드, 티켓 상세 패널, command/활동 로그 슬롯을 추가했다.
- `gateway` 에 `GET /api/work-manager/board` 조회 경로를 추가해 `docs/tickets/board.md` 와 티켓 본문을 읽어 보드 데이터를 구성한다.
- Work Manager 카드 이동은 현재 preview-only 이며 실제 상태 저장/명령 브리지는 `TKT-032` 에서 이어진다.
- `powershell -ExecutionPolicy Bypass -File .\tools\run-frontend-build.ps1` 검증은 통과했다.
- 현재 작업 환경에는 `java`, `mvn`, wrapper 가 없어 gateway compile 검증은 아직 못 했다.

## Notes

- 이 티켓은 보드 화면과 정보구조를 먼저 만든다.
- 실제 이동 저장, 실행 트리거, command 전송, 비밀번호 검증은 후속 티켓으로 분리한다.
- 활동 로그 데이터의 실제 공급 경로와 보관 방식은 후속 티켓에서 정한다.
