# TKT-019

## 메타데이터

- 제목: 로컬 빌드/PR 도구 가용성 preflight
- 우선순위: P1
- 대상 버전: `v0.1.2`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-019-local-toolchain-preflight`

## 목표

`TKT-010` 런타임 정렬과 `TKT-018` 릴리스 후보 검증을 막는 로컬 도구 부재를 먼저 분리해서 확인한다.

## 작업 내용

- 현재 실행 환경에서 `java`, `mvn`, `git`, `docker` 의 사용 가능 여부를 확인한다.
- gateway 기준 Java 21 과 Maven 3.9.x 가 필요한지 확인하고, 실제 버전이 맞는지 기록한다.
- Docker 가 있으면 gateway Docker build 를 실행할 수 있는지 확인한다.
- Git 이 있으면 현재 브랜치, 변경 파일, 원격 origin 을 확인한다.
- 도구가 없으면 설치를 직접 시도하지 말고, 필요한 도구 목록과 설치 후 재검증 명령을 문서에 남긴다.
- `TKT-010`, `TKT-018`, 히스토리에 반영할 수 있게 결과를 정리한다.

## 범위

- 이 티켓은 도구 가용성 확인과 재현 명령 정리에 집중한다.
- 애플리케이션 기능 구현, 릴리스 태그 생성, `VERSION` 승격은 하지 않는다.
- Maven wrapper 추가는 기본 해결책이 아니다.
- Docker 는 공개 서버 배포와 컨테이너 검증 경로로 본다.

## 완료 기준

- `java -version`, `mvn -version`, `git --version`, `docker --version` 결과가 기록되어 있다.
- 도구가 있으면 gateway Maven build 또는 Docker build 중 가능한 검증을 실행했다.
- 도구가 없으면 무엇이 없어서 어떤 검증이 막혔는지가 명확히 기록되어 있다.
- `TKT-010` 이 이어서 어떤 작업을 할 수 있는지 Notes 로 전달되어 있다.
- 사용자 승인 없이 시스템 설치, 릴리스, 배포, 원격 push 를 하지 않았다.

## 선행 조건

- 없음

## 질문/결정 기록

- 결정: 2026-06-13 현재 확인 환경에서는 `java`, `mvn`, `docker` 가 PATH 에 없다.
- 정정: `git` 은 PATH 에는 없지만 `C:\Program Files\Git\cmd\git.exe` 와 `C:\Program Files\Git\bin\git.exe` 에 설치되어 있다.
- 결정: Git fetch, worktree, commit 은 전체 경로를 사용하면 가능하다. 단, push 는 현재 HTTPS 인증 정보가 없어 실패한다.
- 결정: gateway 는 `gateway/pom.xml` 기준 Java 21 을 사용한다.
- 결정: gateway Docker build 는 `gateway/Dockerfile` 기준 `maven:3.9.9-eclipse-temurin-21` 빌더 이미지를 사용한다.
- 결정: `TKT-010` 의 광범위한 런타임 정렬 전에, 이 티켓에서 도구 가용성과 막힘을 먼저 분리한다.
- 결정: 2026-06-14 현재 Codex 번들 런타임 절대 경로는 아래와 같다.
  - Node: `C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe`
  - Python: `C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`
- 결정: 2026-06-15 `TKT-030` 으로 프런트엔드 정식 기준선은 `Node.js 22 LTS + npm/npx` 로 고정했고, 번들 Node 와 저장소 로컬 Node 는 fallback 으로 분리했다.

## 권장 검증 명령

도구 확인:

```powershell
java -version
mvn -version
git --version
docker --version
& 'C:\Program Files\Git\cmd\git.exe' --version
```

gateway Maven build:

```powershell
Set-Location gateway
mvn -q -DskipTests package
```

저장소 루트에서 gateway Docker build:

```powershell
docker build -t workaround-gateway:local gateway
```

Git 상태 확인:

```powershell
& 'C:\Program Files\Git\cmd\git.exe' status --short
& 'C:\Program Files\Git\cmd\git.exe' branch --show-current
& 'C:\Program Files\Git\cmd\git.exe' remote -v
```

프런트엔드 기준선 확인:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\check-node-toolchain.ps1
```

- 2026-06-14 재확인 기준 `where.exe java`, `where.exe mvn`, `where.exe docker`, `where.exe node`, `where.exe npm` 은 모두 실패했다.
- `C:\Program Files\Git\cmd\git.exe --version` 은 `git version 2.54.0.windows.1` 로 응답했다.
- Codex 번들 Node `v24.14.0`, 번들 Python `3.12.13` 경로를 확인했고, 프런트엔드 build 와 Python smoke 검증은 가능했다.
- 저장소 로컬 `tools/local-node/node.exe` 는 동작하지만 `tools/local-node/npm.cmd` 는 `npm-cli.js` 부재로 실패한다.
- 2026-06-15 `TKT-030` 에서 정식 Node/npm 기준선과 fallback 경로의 역할 분리를 문서화했다.

## Notes

- 이 티켓은 `TKT-010` 의 선행 preflight 로 본다.
- `TKT-018` 릴리스 게이트는 이 티켓 결과를 보고 gateway compile, Docker build, Git PR 준비 가능 여부를 갱신한다.
- worker 는 Git 이 필요할 때 우선 전체 경로 `C:\Program Files\Git\cmd\git.exe` 를 사용한다.
- worker 는 프런트엔드 재검증이 필요할 때 정식 기준선이면 `npm install`, `npm run build` 를 사용하고, 제한 세션이면 `tools/run-frontend-build.ps1` fallback 을 사용한다.
