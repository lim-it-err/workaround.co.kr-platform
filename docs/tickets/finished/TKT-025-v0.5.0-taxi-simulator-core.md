# TKT-025

## 메타데이터

- 제목: 택시 시뮬레이터 코어
- 우선순위: P1
- 대상 버전: `v0.5.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-025-taxi-simulator-core`

## 목표

가상의 지도 위에서 랜덤/수동 호출이 발생하고, 인원수에 따라 택시가 이동하며, 처리 시간 기반 리워드와 차량 추가 패널티를 보여주는 택시 시뮬레이터 코어를 만든다.

## 작업 내용

- 가상의 지도 또는 구역 기반 보드를 만든다.
- 첫 구현은 자유 좌표 지도보다 단순한 구역 기반 맵을 기본안으로 둔다.
- 랜덤 호출을 생성한다.
- 사용자가 수동으로 출발지, 도착지, 인원수를 넣을 수 있게 한다.
- 호출에 따라 적절한 택시가 이동하도록 기본 배차 흐름을 구현한다.
- 처리 시간을 측정하고 리워드에 반영한다.
- 차량을 추가 배치할 때 리워드를 깎는 규칙을 구현한다.
- 프런트에서 차량 상태, 현재 요청, 처리 시간, 누적 리워드를 읽을 수 있게 한다.
- 첫 구현은 별도 서비스보다 `frontend` 안의 프런트 단독 시뮬레이션 코어를 기본안으로 둔다.
- 강화학습/자동학습은 `v0.5.1` 후속으로 분리하고, 이번 티켓에서는 게임/시뮬레이션 코어에 집중한다.

## 범위

- 포함: 지도/구역 시각화, 요청 생성, 수동 요청 입력, 기본 배차, 리워드 계산, 상태 표시, 문서 갱신
- 제외: 사람 피드백 루프, RTX5070 평가 보조, 자동 학습 파이프라인, 멀티플레이, 실제 지도 API 연동

## 완료 기준

- 택시 시뮬레이터가 별도 기능 페이지 또는 명확한 포털 진입 경로에서 동작한다.
- 랜덤 호출과 수동 호출이 모두 가능하다.
- 인원수에 따라 차량 이동 결과가 달라진다.
- 처리 시간이 리워드에 반영된다.
- 차량 추가 배치 시 패널티가 반영된다.
- 시뮬레이터 상태를 프런트에서 읽을 수 있다.
- 강화학습, 모델 학습, RTX5070 연결 없이도 시뮬레이터 코어만 독립적으로 재현된다.

## 선행 조건

- `TKT-024` 시뮬 포털 진입 구조가 먼저 열리거나, 같은 작업 라인 안에서 선행 구현되어야 한다.
- 프런트 단독 프로토타입 경계를 기본안으로 사용한다.

## 질문/결정 기록

- 결정: 처리 시간은 리워드로 둔다.
- 결정: 차량 추가 배치는 리워드 패널티로 둔다.
- 결정: 사용자 수동 입력은 출발지, 도착지, 인원수를 포함한다.
- 결정: 첫 버전은 프런트 단독 시뮬레이션으로 시작한다.
- 결정: 지도 표현은 자유 좌표보다 단순 구역 기반 보드를 우선한다.
- 결정: 강화학습, 사람 피드백, RTX5070 연계는 이 티켓에 넣지 않는다.
- 결정: 첫 버전의 기본 맵은 9구역으로 고정한다.
- 결정: 실제 지도 질감을 일부 참조하는 것은 가능하지만, 실지도 API 나 정밀 지형이 선행조건이 되면 안 된다.
- 결정: 실지도 반영이 부담되면 9구역 도시형 추상 지도를 우선 구현한다.

## 구현 메모

- 기본 수정 위치:
  - `frontend/src/App.vue`
  - `frontend/src/styles.css`
  - 필요 시 `docs/feature-definition.md`, `docs/frontend-ux.md`
- 권장 1차 상태 모델:
  - `zones[]`
  - `taxis[]`
  - `activeRequests[]`
  - `completedRequests[]`
  - `score.reward`
  - `score.penalty`
  - `clock.elapsedSeconds`
- 권장 1차 규칙:
  - 랜덤 요청은 일정 간격으로 생성
  - 수동 요청은 출발지/도착지/인원수 직접 입력
  - 가장 가까우면서 정원 여유가 있는 차량을 우선 배차
  - 처리 시간이 길수록 reward 감소
  - 차량 추가 시 즉시 penalty 누적
- 권장 1차 맵 규칙:
  - 9개 구역은 고정 ID 와 이름을 가진다.
  - 각 구역은 인접 구역 관계를 가져 이동 시간이 설명 가능해야 한다.
  - 구역 색/라벨은 사용자가 경로를 직관적으로 구분할 수 있을 정도로만 준다.
- 하지 말 것:
  - 강화학습 루프를 이번 티켓에 끼워 넣지 않는다.
  - 실지도 API, 외부 DB, 외부 추론 런타임을 이번 티켓 선행조건으로 만들지 않는다.
  - Taxi 와 Elevator 를 같은 화면에서 한꺼번에 조작하는 구조로 되돌리지 않는다.

## 검토 메모

- `frontend/src/App.vue` 에 9구역 맵, 랜덤/수동 호출, 기본 배차, reward/penalty, fleet 추가 패널티를 구현했다.
- 검토자는 `수동 호출`, `자동 호출`, `차량 추가`, `완료 호출 reward` 가 화면에서 함께 읽히는지 확인하면 된다.
- 오케스트레이터 판정: 9구역 neighbor 관계를 대칭적으로 보정해 route fallback 이 불필요하게 발생하던 부분을 닫았고, `frontend` build 검증도 통과했다.

## Notes

- 자동 학습, RTX5070 기반 평가, 사람 피드백 반영은 `TKT-026` 으로 넘기고, 본 티켓은 게임/시뮬레이션 코어를 우선 완성한다.
- 기능 정의서 기준으로 `v0.5.0` 은 웹 포털에서 읽히는 택시 시뮬레이션 코어까지가 범위고, 학습 운영은 `v0.5.1` 로 넘긴다.
- worker 는 맵 시각화보다 먼저 9구역 상태 모델, 요청 생성, 배차, 리워드 계산을 닫고 UI 는 그 위에 얹는다.
