# TKT-024

## 메타데이터

- 제목: 다양한 시뮬 포털 탭과 택시/엘리베이터 진입 라우팅
- 우선순위: P1
- 대상 버전: `v0.5.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-024-sim-portal-tab-routing`

## 목표

웹페이지 안에 `다양한 시뮬` 진입점을 만들고, 그 안에서 `엘리베이터 시뮬` 과 `택시 시뮬` 을 분리된 카드 또는 탭으로 노출한다.

## 작업 내용

- `frontend` 에 `다양한 시뮬` 상위 탭 또는 포털 섹션을 추가한다.
- 기본안은 현재 `frontend/src/App.vue` 의 page 상태 모델에 `simhub`, `taxi` 진입 상태를 추가하는 것이다.
- 포털 안에 `엘리베이터 시뮬`, `택시 시뮬` 카드나 서브탭을 나란히 배치한다.
- 각 시뮬 항목이 별도 페이지, 패널, 또는 라우팅 경로로 이어지도록 링크 구조를 정리한다.
- 기본 흐름은 `Main Junction -> Sim Hub -> Elevator / Taxi` 다.
- Elevator 기존 페이지는 유지하고, Sim Hub 에서 Elevator 와 Taxi 를 선택하게 한다.
- gateway 가 서비스 descriptor 나 route prefix 를 필요로 하면 최소한의 진입 계약만 추가한다.
- 실제 시뮬 서비스가 없거나 내려갔을 때도 포털 목록은 유지하고, 진입 실패는 명확한 저하 상태로 보여준다.
- Main page 가 다시 거대한 대시보드로 후퇴하지 않게, Sim Hub 는 진입 선택과 상태 요약만 담당한다.

## 범위

- 포함: 포털 네비게이션, 시뮬 항목 카드, 진입 라우팅, 기본 저하 메시지, 관련 문서 갱신
- 제외: 엘리베이터 시뮬레이터 내부 로직, 택시 시뮬레이터 내부 로직, 자동 학습, 릴리스 승인, `VERSION` 변경

## 완료 기준

- `다양한 시뮬` 진입점에서 `엘리베이터 시뮬` 과 `택시 시뮬` 을 구분해서 볼 수 있다.
- 각 항목이 사용자에게 다음 단계 진입 경로를 명확히 보여준다.
- 서비스가 아직 준비되지 않았을 때의 fallback 또는 placeholder 동작이 정의되어 있다.
- 기존 Elevator Station 기능이 Sim Hub 추가 때문에 회귀하지 않는다.
- `frontend` production build 또는 동등한 검증이 성공한다.

## 선행 조건

- 현재 `frontend/src/App.vue` 의 Main Junction / Elevator Station baseline 이 유지되고 있어야 한다.
- `TKT-011`, `TKT-021`, `TKT-023`, `TKT-035` 의 완전 종료를 기다리지는 않지만, 해당 기능을 회귀시키면 안 된다.

## 질문/결정 기록

- 결정: 택시 시뮬레이터는 엘리베이터 시뮬레이터 다음 트랙으로 둔다.
- 결정: 포털은 단일 서비스 목록이 아니라 시뮬레이션 허브처럼 보여야 한다.
- 결정: 첫 구현은 Vue Router 도입보다 현재 page 상태 모델 확장을 우선한다.
- 결정: 경로 이름은 코드에서 `simhub`, `elevator`, `taxi` 처럼 읽히는 방향을 기본안으로 둔다.
- 결정: Taxi 가 아직 부분 구현이어도 Sim Hub 에 진입 카드와 준비 상태는 먼저 보여준다.
- 결정: 정식 URL 라우터 도입은 후속 티켓으로 넘기고, 이번 티켓은 현재 page 상태 모델 확장과 최소 훅만 남긴다.
- 결정: gateway 서비스 descriptor 없이 프런트엔드 정적 라우팅으로 먼저 닫는다.

- 기본 수정 위치:
  - `frontend/src/App.vue`
  - `frontend/src/styles.css`
  - 필요 시 `frontend/README.md`, `docs/frontend-ux.md`
- 권장 순서:
  1. `simhub` 상태 추가
  2. Main Junction 에서 Sim Hub 진입 카드 추가
  3. Sim Hub 안에 Elevator / Taxi 카드 배치
  4. Taxi 준비 상태 placeholder 또는 실제 진입 연결
  5. 기존 Elevator 복귀/이동 동선 회귀 점검
- 하지 말 것:
  - 메인 허브에 Elevator 표나 Work Manager 보드를 다시 직접 펼치지 않는다.
  - Taxi 코어까지 이 티켓에 섞어 넣지 않는다.
  - 아직 없는 서비스 때문에 진입 자체를 숨기지 않는다.

## 검토 메모

- 라이브 포털에 `Main Junction -> Sim Hub -> Elevator / Taxi / Blog District` 동선을 추가했다.
- 검토자는 메인 허브가 다시 거대한 조작판으로 후퇴하지 않았는지와 `Sim Hub` 가 실제 진입 허브로만 동작하는지 확인하면 된다.
- 오케스트레이터 판정: `frontend` production build 를 fallback 경로로 다시 검증했고, 포털 진입 구조는 완료 기준을 충족한다고 본다.

## Notes

- 이 티켓은 택시 시뮬레이터 본체가 아니라 진입점과 선택 허브를 먼저 만드는 작업이다.
- `v0.4.0` 에 Work Manager 라인이 먼저 들어가므로, 이 티켓은 그 다음 시뮬레이션 minor 인 `v0.5.0` 으로 밀린다.
- 기능 정의서 기준으로 `v0.5.0` 포털 확장은 `v0.4.0` 허브 구조 위에 올라가며, 메인 허브가 다시 거대한 기능 대시보드로 후퇴하면 안 된다.
- worker 는 `Main Junction -> Sim Hub -> Elevator / Taxi` 동선 회귀 테스트를 먼저 만들고 카드/상태 요약을 얹는 순서로 진행한다.
