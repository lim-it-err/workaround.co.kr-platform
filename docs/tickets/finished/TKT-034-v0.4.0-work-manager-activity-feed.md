# TKT-034

## 메타데이터

- 제목: Work Manager 활동 로그와 사용자-AI 대화 피드
- 우선순위: P2
- 대상 버전: `v0.4.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-034-work-manager-activity-feed`

## 목표

Work Manager 오른쪽 패널에 지금까지 사용자와 AI가 이런 식으로 일해왔다는 인상을 주는 활동 로그/대화 피드를 보여준다. 첫 버전은 단일 사용자 기준의 전시용 운영 피드로 둔다.

## 작업 내용

- 오른쪽 패널에 활동 로그 또는 대화 피드 UI 를 추가한다.
- 피드 항목은 `사용자 요청`, `오케스트레이터 판단`, `티켓 발부`, `리뷰`, `후속 메모` 같은 타입으로 나눈다.
- 실제 채팅 원문 전체를 그대로 내보내기보다, 전시용 요약 카드 또는 짧은 대화형 로그로 정리한다.
- 기본안은 DB 없이 파일 기반 JSON, 정적 seed, 또는 `docs/history`/티켓 메모에서 만든 요약 feed 로 시작한다.
- 사용자는 한 명이라고 가정하고 multi-user 계정 모델은 넣지 않는다.
- 나중에 실제 command 이력과 이어 붙일 수 있도록 run id 또는 timestamp 필드를 남긴다.

## 범위

- 포함: 활동 로그 UI, feed 스키마, 초기 seed 데이터, 단일 사용자 기준 표시, 문서 갱신.
- 제외: 다중 사용자 협업, 실시간 채팅 동기화, 외부 메신저 연동, 완전한 원문 transcript 저장소.

## 완료 기준

- Work Manager 오른쪽 패널에 활동 로그/대화 피드가 보인다.
- 사용자와 AI가 운영해 온 흔적처럼 보이는 샘플 또는 실제 요약 피드가 채워져 있다.
- 첫 버전은 DB 없이도 재현 가능하다.
- 이후 실제 실행 로그와 이어 붙일 수 있는 데이터 스키마가 정리되어 있다.

## 선행 조건

- `TKT-032` command 패널 구조가 먼저 준비되어야 한다.

## 질문/결정 기록

- 결정: 사용자는 한 명으로 가정한다.
- 결정: 이 피드는 실시간 협업 도구라기보다 "이런 식으로 운영 중"이라는 인상을 주는 전시용 운영 피드다.
- 결정: 첫 버전은 DB 없이 파일 기반 feed 로 시작한다.
- 열린 질문: feed 원천을 `docs/history` 기반 요약으로 만들지, 별도 JSON 시드로 관리할지.

## 검토 메모

- Work Manager 오른쪽 패널에 `사용자 요청`, `오케스트레이터 판단`, `티켓 발부`, `리뷰`, `후속 메모` 타입 배지가 붙은 activity feed UI를 추가했다.
- `GET /api/work-manager/board` 응답에 `activityFeed[]` seed 구조를 추가해 fallback 없이도 같은 피드를 재현할 수 있게 했다.
- 첫 버전은 DB 없이 history summary 기반 seed 성격의 고정 피드로 시작하고, 실제 command 이력 병합은 `TKT-032`, `TKT-033` 뒤로 넘긴다.
- `powershell -ExecutionPolicy Bypass -File .\tools\run-frontend-build.ps1` 검증은 통과했다.
- 현재 작업 환경에는 `java`, `mvn`, wrapper 가 없어 gateway compile 검증은 아직 못 했다.
