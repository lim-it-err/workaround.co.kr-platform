# TKT-042

## 메타데이터

- 제목: Work Manager worker 할당 가시화와 우선순위 반응 실행
- 우선순위: P1
- 대상 버전: `v0.5.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `v0.5.0 진행 시 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-042-work-manager-worker-visibility`

## 목표

`v0.4.0` 에서 만든 Work Manager 메타데이터 편집/Ready 시각 흐름 위에, 실제 worker 가 어느 티켓을 잡았는지와 우선순위 변화가 실행 흐름에 어떻게 반영되는지를 보여준다.

## 작업 내용

- Work Manager 에서 현재 어떤 worker 가 어떤 티켓을 수행 중인지 보이게 한다.
- `Ready -> Started` 전이가 실제 worker 소유 구간이라는 점을 단순 문구가 아니라 상태 정보로 보여준다.
- 우선순위 변경이 실제 선점 순서에 반영된다면, 그 규칙을 UI 와 문서에 함께 드러낸다.
- 우선순위 반응 실행이 아직 부분적이라면, 어떤 범위까지 자동이고 어떤 범위는 수동인지 명확히 남긴다.
- gateway / worker / 문서 저장소 중 어디에서 우선순위를 해석할지 기본안을 정리한다.

## 범위

- 포함: worker 가시화, 우선순위 반응 흐름, 관련 상태 표시, 문서 갱신
- 제외: 멀티유저 권한 모델, DB 감사 로그 전체, 스케줄러 전면 재작성

## 완료 기준

- Started 구간에서 어떤 worker 가 일을 잡고 있는지 보인다.
- 우선순위 변경이 실행 흐름과 어떤 식으로 연결되는지 사용자가 읽을 수 있다.
- 자동 반응 범위와 수동 범위가 구분돼 있다.

## 선행 조건

- `TKT-039` Ready 레인과 상세 패널이 정리되어 있어야 한다.
- `TKT-040` 메타데이터 편집 구조가 정리되어 있어야 한다.

## 질문/결정 기록

- 결정: `v0.4.0` 에서는 우선순위 편집 문만 열고, 실제 반응 실행은 `v0.5.0` 로 넘긴다.
- 결정: worker 가시화의 1차 기준은 실제 worker 이름 또는 안정적인 worker ID 로 둔다.
- 결정: gateway 는 티켓 메타데이터를 정리하고, 우선순위 반영은 worker 가 큐 선점 시 해석하는 기본안을 따른다.
- 결정: UI 는 자동 반응과 수동 반응의 경계를 명시적으로 보여줘야 한다.

## 검토 메모

- gateway Work Manager 보드 응답에 `workerSummary`, `priorityPolicy` 를 추가하고, 프런트 운영 보드에 Started ownership 카드와 우선순위 반응 요약을 노출했다.
- 검토자는 Started 티켓이 없을 때/있을 때 worker summary 가 자연스럽게 읽히는지와 자동/수동 경계 문구가 혼동을 줄이지 않는지 확인하면 된다.
- 오케스트레이터 판정: gateway 테스트가 통과했고, 현재 단일 worker 기준에서는 안정적인 worker ID 노출과 우선순위 반응 설명이 완료 기준을 충족한다.

## Notes

- 우선순위에 반응하는 실제 worker 선점 로직은 시각화만 만들고 끝내지 말고, 어떤 규칙으로 움직이는지 문서와 함께 보여줘야 한다.
- 기능 정의서 기준으로 이 티켓은 `v0.4.0` 의 메타데이터 편집 문을 실제 worker 가시화/반응 실행으로 잇는 후속 작업이다.
- worker 는 먼저 worker ID 노출과 Started 상세 정보부터 붙이고, 그 다음 우선순위 반응 실행 규칙을 연결한다.
