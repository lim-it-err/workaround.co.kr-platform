# TKT-032

## 메타데이터

- 제목: Work Manager 티켓 이동과 command 브리지
- 우선순위: P1
- 대상 버전: `v0.4.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-032-work-manager-command-bridge`

## 목표

Work Manager 보드에서 티켓을 옮기면 실제 ticket 상태 변경과 실행 트리거가 일어나고, 오른쪽 command 창의 `프리셋 액션 + 메모` 입력이 플랫폼의 gateway/worker 경로로 전달되도록 한다.

## 작업 내용

- 티켓 컬럼 이동을 gateway API 또는 적절한 backend 경로와 연결한다.
- `backlog -> started`, `started -> need_review`, `need_review -> finished` 같은 허용 전이를 정리한다.
- 이동 시 단순 UI 변경이 아니라 실제 저장과 worker 수행 트리거가 일어나도록 한다.
- 오른쪽 command 패널의 `프리셋 액션 + 메모` 입력을 backend 명령 API 와 연결한다.
- command 는 직접 Codex에 소켓처럼 붙는 구조가 아니라, gateway -> ticket/worker/orchestrator 경로로 흘러가도록 설계한다.
- 최소한 command 이력, 실행 상태, 실패 메시지 를 패널 안에서 볼 수 있게 한다.
- freeform 텍스트 커맨드 대신 프리셋 액션을 우선 두고, 메모는 보조 설명으로만 받는다.
- 잘못된 전이, 실행 불가 티켓, worker 차단 조건을 UI 에 명확히 보여준다.

## 범위

- 포함: 티켓 상태 전이 API 연동, 실행 트리거, 프리셋 액션 + 메모 입력/응답 패널, 실패 표시, 문서 갱신.
- 제외: 비밀번호 검증 자체, 암호화 저장, 완전한 자연어 에이전트 연결, 외부 LLM 직접 호출.

## 완료 기준

- 보드에서 티켓을 옮기면 backend 상태가 함께 바뀐다.
- 실행 가능한 티켓은 이동 시 worker 수행 경로를 탈 수 있다.
- command 창의 프리셋 액션과 메모가 backend 로 전달되고 결과 또는 실패가 보인다.
- command 패널은 "직접 Codex 연결"이 아니라 플랫폼 명령 브리지라는 점이 문서에 적혀 있다.

## 선행 조건

- `TKT-031` Work Manager 보드 UI 가 먼저 준비되어야 한다.
- 티켓 상태 저장 기준은 `docs/ticket-policy.md` 와 `docs/tickets/board.md` 를 따른다.

## 질문/결정 기록

- 결정: command 창은 Codex 직접 연결이 아니라 플랫폼 명령 브리지로 구현한다.
- 결정: 컬럼 이동은 곧 상태 변경이며, 허용 전이만 backend 가 수용한다.
- 결정: command 입력은 freeform 텍스트가 아니라 프리셋 액션 + 메모 조합으로 받는다.
- 열린 질문: command 결과를 단순 로그로 볼지, run id 기준으로 추적할지.

## 검토 메모

- `frontend` Work Manager 보드에서 `Move to started`, `Mark need review`, `Close as finished` 액션이 실제 gateway 전이 API를 호출하도록 연결했다.
- `gateway` 에 `POST /api/work-manager/tickets/{ticketId}/transition`, `POST /api/work-manager/commands` 를 추가해 허용 전이만 처리하고, `started` 진입 시 worker bridge 티켓을 발행하도록 정리했다.
- command 입력은 freeform 대신 preset action + note 조합만 허용하고, 최근 command history 와 운영 feed 를 같은 패널에서 함께 보이도록 맞췄다.
- `powershell -ExecutionPolicy Bypass -File .\tools\run-frontend-build.ps1` 검증은 통과했다.
- 현재 작업 환경에는 `java`, `mvn`, wrapper 가 없어 gateway compile 검증은 아직 못 했다.

## Notes

- 이 티켓은 "옮기면 수행" 요구를 실제 시스템 전이로 연결하는 핵심 티켓이다.
- worker 가 임의 전이를 하지 않도록 오케스트레이터 규칙을 backend 에서도 다시 확인하는 편이 안전하다.
