# TKT-016

## 메타데이터

- 제목: 샘플 Python 서비스 정리와 엘리베이터 서비스 준비
- 우선순위: P2
- 대상 버전: `v0.1.3`
- 상태: `finished`
- 문서 상태: `작성완료`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-016-replace-sample-python-service`

## 목표

필수 기준이 약한 `sample-python-service` 를 정리하고, `v0.3.0` 엘리베이터 시뮬레이터 작업이 바로 이어질 수 있도록 서비스 계약 후보만 준비한다.

## 작업 내용

- `services/sample-python-service/` 가 compose, gateway, README, 프런트엔드에서 참조되는지 조사한다.
- 참조가 없다면 문서와 코드에서 남아 있는 설명을 정리한다.
- 참조가 있다면 제거 영향과 대체 필요성을 문서화한다.
- 이 티켓에서는 엘리베이터 시뮬레이터 본 구현을 하지 않는다.
- 서비스 ID, route prefix, Docker 계약 후보를 `TKT-011` 이 이어받을 수 있게 정리한다.

## 범위

- `sample-python-service` 가 필수 구성요소처럼 보이지 않게 정리한다.
- 엘리베이터 시뮬레이터 구현은 `v0.3.0` 후보인 `TKT-011` 로 넘긴다.
- `docs/`, compose, gateway descriptor, worker 환경변수에 남은 샘플 참조가 있으면 실제 상태와 맞춘다.

## 완료 기준

- `sample-python-service` 가 프리뷰 핵심 경로에서 빠진다.
- 샘플 서비스 제거 또는 유지 판단이 문서와 코드에 일관되게 나타난다.
- 엘리베이터 시뮬레이터 구현 범위가 `TKT-011` 로 명확히 넘어간다.
- `docs/network.md`, `docs/service-policy.md`, `README.md` 가 실제 구조와 맞는다.
- 남은 불일치가 문서에 기록된다.

## 선행 조건

- 없음

## 질문/결정 기록

- 결정: 샘플 Python 서비스는 필수 서비스가 아니다.
- 결정: 엘리베이터 시뮬레이터는 Python, Go, Java 중 적절한 언어로 구현할 수 있다.
- 결정: 엘리베이터 시뮬레이터 본 구현은 `v0.2.0` 이후 다음 minor 후보인 `v0.3.0` 에 둔다.
- 결정: `v0.2.0` 통합 작업이 비대해지지 않도록 이 티켓은 `v0.1.3` 준비 슬라이스로 관리한다.
- 결정: 서브서비스는 기본적으로 Docker 위에 올릴 수 있는 계약을 갖춘다.
- 열린 질문: 현재 참조 상태를 확인한 뒤 샘플 서비스를 제거할지, 임시 예제로 유지할지 판단한다.
