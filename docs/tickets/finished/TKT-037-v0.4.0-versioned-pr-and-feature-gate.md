# TKT-037

## 메타데이터

- 제목: PR 버전 표기와 one-version-one-feature 가드
- 우선순위: P1
- 대상 버전: `v0.4.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-037-versioned-pr-gate`

## 목표

버전이 붙는 PR 은 대상 버전을 반드시 드러내고, 현재 단계의 "하나의 release version = 하나의 기능 테마" 원칙이 PR 템플릿, 로컬 검증, GitHub Actions 검증에 함께 반영되도록 만든다.

## 작업 내용

- `.github/pull_request_template.md` 를 추가해 아래 필드를 기본 PR 형식으로 고정했다.
  - `Target Version`
  - `Feature Theme`
  - `Tickets`
  - `Summary`
  - `Scope`
  - `Verification`
  - one-version-one-feature 체크리스트
- `tools/check-pr-version-metadata.ps1` 를 추가해 로컬에서 PR 제목/본문 메타데이터를 같은 규칙으로 검증할 수 있게 했다.
- `.github/workflows/pr-version-guard.yml` 을 추가해 PR 이벤트에서 같은 스크립트를 다시 실행하도록 연결했다.
- `docs/version-policy.md`, `docs/release-automation.md`, `docs/ticket-policy.md`, `docs/tickets/orchestrator.md` 를 갱신해 제목 prefix, `Target Version`, `Feature Theme`, one-version-one-feature 체크리스트를 운영 기준으로 맞췄다.

## 범위

- 포함: PR template, PR metadata validation script, PR validation workflow, 관련 운영 문서 갱신
- 제외: GitHub branch protection 실제 서버 설정, 조직 전체 PR 규칙 강제, 기존 열린 PR 일괄 수정

## 완료 기준

- PR 템플릿 또는 동등한 입력 구조에 대상 버전 항목이 있다.
- 버전이 빠진 PR 을 걸러내는 자동 검증 또는 명확한 로컬 검증 경로가 있다.
- 관련 문서에 "하나의 version = 하나의 기능 테마" 원칙이 적혀 있다.
- `v0.4.0` Work Manager 라인 PR 을 만들 때 버전 표기가 빠지지 않는다.

## 선행 조건

- `TKT-036` 의 GitHub Actions 보강 방향을 함께 본다.
- `docs/version-policy.md`, `docs/release-automation.md`, `docs/tickets/orchestrator.md` 기준을 따른다.

## 질문/결정 기록

- 결정: PR 제목은 `[v0.4.0]`, `[infra]`, `[chore]` 같은 대상 버전 prefix 로 시작한다.
- 결정: PR 본문은 template 의 `Target Version`, `Feature Theme`, one-version-one-feature 체크리스트를 유지한다.
- 결정: 로컬 검증과 GitHub Actions 검증은 같은 PowerShell 스크립트를 재사용한다.
- 열린 질문: 기존에 이미 열려 있는 PR 들을 새 템플릿 형식으로 언제 맞출지는 후속 정리 시점에 판단한다.

## 검토 메모

- `.github/pull_request_template.md` 를 추가해 `Target Version`, `Feature Theme`, one-version-one-feature 체크리스트를 기본 PR 형식으로 고정했다.
- `tools/check-pr-version-metadata.ps1` 는 제목 prefix, 본문 target version, feature theme, 체크리스트 상태를 함께 검증한다.
- `.github/workflows/pr-version-guard.yml` 은 PR opened/edited/reopened/synchronize/ready_for_review 이벤트에서 같은 스크립트를 실행한다.
- 로컬 검증은 아래 두 케이스로 확인했다.
  - 성공 예시: `[v0.4.0] add pr version guard` + 유효한 body -> 통과
  - 실패 예시: prefix 없는 제목 + placeholder feature theme + 미체크 체크리스트 -> 실패
- 오케스트레이터 판정: PR template, 로컬 검증 스크립트, GitHub Actions workflow, 운영 문서 기준이 모두 맞물렸으므로 완료 기준을 충족한 것으로 본다.
