# TKT-039

## 메타데이터

- 제목: Work Manager `Backlog/Ready` 분리와 상세 패널
- 우선순위: P1
- 대상 버전: `v0.4.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-039-work-manager-ready-lane`

## 목표

Work Manager 를 단순 4컬럼 보드가 아니라 `Backlog`, `Ready`, `Started`, `Need Review`, `Finished` 운영 흐름으로 다시 보이게 만들고, 사용자가 `Backlog -> Ready` 를 드래그로 옮기며 티켓을 눌렀을 때 상세 내용을 읽을 수 있게 한다.

## 작업 내용

- Work Manager 보드 컬럼을 `Backlog`, `Ready`, `Started`, `Need Review`, `Finished` 로 재구성한다.
- 사용자가 직접 드래그 가능한 기본 전이는 `Backlog -> Ready` 로 한정한다.
- `Ready` 컬럼에는 `worker agent 다른 작업 중...` 같은 대기 설명 문구를 둘 수 있게 한다.
- `Need Review` 컬럼에는 `PM agent 확인중...` 같은 리뷰 설명 문구를 둘 수 있게 한다.
- 카드 클릭 시 티켓 상세 패널 또는 상세 모달이 열리게 한다.
- 상세 패널에는 최소한 `목표`, `작업 내용`, `선행 조건`, `질문/결정 기록`, `Notes`, `검토 메모`, `PR 준비 메모` 를 보여준다.
- 현재 저장소가 파일 기반이라는 점을 유지하되, 이 표시 모델과 실제 파일 기반 상태 전이의 연결 지점을 문서에 남긴다.

## 범위

- 포함: 5단계 보드 표현, `Backlog -> Ready` 드래그 UX, 시스템 소유 전이 설명, 상세 패널, 문서 갱신
- 제외: 실제 worker 할당 가시화, 우선순위에 따른 자동 선점 변경, DB 전환, 멀티유저 협업

## 완료 기준

- Work Manager 에서 `Backlog`, `Ready`, `Started`, `Need Review`, `Finished` 흐름이 읽힌다.
- `Backlog` 카드가 `Ready` 로 드래그 이동된다.
- 티켓 카드를 누르면 상세 내용이 열린다.
- `Ready -> Started`, `Need Review -> Finished` 는 현재 시스템/에이전트 소유 구간이라는 점이 UI 와 문서에 함께 남아 있다.

## 선행 조건

- `TKT-031` 의 기본 보드 UI 가 있어야 한다.
- `TKT-032` 와 충돌하지 않도록 실제 전이 API 책임 경계를 정리해야 한다.

## 질문/결정 기록

- 결정: 사용자가 직접 이동하는 첫 전이는 `Backlog -> Ready` 까지만 둔다.
- 결정: `Ready -> Started` 는 worker 소유 전이로 읽히게 한다.
- 결정: `Need Review -> Finished` 는 orchestrator/PM 소유 전이로 읽히게 한다.
- 결정: 상세 패널은 티켓 본문 섹션뿐 아니라 우선순위, 진행 판정, 작업자 산출물, `PR 준비 메모` 같은 운영 메타데이터도 함께 보여준다.
- 결정: `의존성` 섹션이 없는 기존 티켓은 우선 `선행 조건` 내용을 fallback 으로 사용해 상세 패널을 비우지 않는다.

## Notes

- `Ready` 분리는 사용자 체감상 중요하지만, 실제 worker 큐 선점 순서까지 자동 반영하는 것은 별도 후속 티켓으로 분리한다.
- `docs/feature-definition.md` 기준으로 `Backlog/Ready` 는 사용자 소유 가시화 구간이고, `Started/Need Review/Finished` 는 시스템 소유 흐름이라는 해석을 유지한다.
