# TKT-040

## 메타데이터

- 제목: Work Manager 메타데이터 편집과 목표 버전 헤더
- 우선순위: `P2`
- 대상 버전: `v0.4.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `진행 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-040-work-manager-meta-editor`

## 목표

티켓 상세 패널에서 대상 버전, 의존성, 우선순위 같은 핵심 메타데이터를 읽고 바꿀 수 있게 하고, Work Manager 상단에는 현재 목표 버전과 로드맵 요약을 보여준다.

## 작업 내용

- Work Manager 상단에 현재 목표 버전, 현재 작업중인 버전 범위, 간단한 로드맵 요약 패널을 추가한다.
- 티켓 상세 패널에서 대상 버전(`v0.4.0`, `v0.5.0`, `infra`, `chore` 등)을 수정할 수 있게 한다.
- 티켓 간 의존성 또는 선행 티켓을 읽고 수정할 수 있는 UI 를 둔다.
- 우선순위(`P1`~`P5`)를 읽고 수정할 수 있는 UI 를 둔다.
- 첫 버전은 파일 기반 티켓 메타데이터 수정으로 시작하고, 변경 결과가 문서와 보드에 반영되게 한다.
- "우선순위를 바꾸면 worker 가 더 먼저 잡을 수 있다"는 기대는 별도 후속 운영 티켓으로 분리하고, 현재 버전에서는 메타데이터 변경까지만 보장한다고 문서에 남긴다.

## 범위

- 포함: 목표 버전 헤더, 로드맵 요약, 대상 버전 수정, 의존성 수정, 우선순위 수정, 문서 갱신
- 제외: 실제 worker 스케줄러가 우선순위를 즉시 반영하는 로직, DB 감사 로그, 멀티유저 권한 모델

## 완료 기준

- Work Manager 상단에서 현재 목표 버전과 로드맵 요약이 보인다.
- 티켓 상세 패널에서 대상 버전, 의존성, 우선순위를 읽고 수정할 수 있다.
- 수정 결과가 파일 기반 티켓 문서와 보드에 일관되게 반영된다.
- 자동 우선순위 반응 실행은 아직 후속 범위라는 점이 문서에 명시돼 있다.

## 질문/결정 기록

- 결정: 버전 변경과 의존성 수정은 가능하게 여는 방향으로 간다.
- 결정: 우선순위 변경 자체는 `v0.4.0` 에 넣되, 이것이 실제 worker 선점 순서를 즉시 바꾸는 자동화는 `v0.5.0` 후속으로 둔다.
- 결정: 첫 메타데이터 편집 UI 는 선택형 대상 버전, 선택형 우선순위, 자유 텍스트 의존성 편집을 기본안으로 둔다.
- 결정: `의존성` 섹션이 없는 기존 티켓은 `선행 조건` 값을 fallback 으로 읽고, 저장 시에는 `## 의존성` 섹션을 새로 만들 수 있게 한다.

## 작업자 산출물

- gateway 에 `POST /api/work-manager/tickets/{ticketId}/metadata` 보호 API 를 추가했다.
- Work Manager detail panel 에 대상 버전, 우선순위, 의존성 편집 폼과 저장 버튼을 추가했다.
- Work Manager 상단에 현재 focus version, 개발 상한, active range, 로드맵 요약 카드를 추가했다.
- 파일 저장 방식은 ticket metadata(`대상 버전`, `우선순위`, 필요 시 `진행 판정`)와 `## 의존성` 섹션, 보드 한 줄 메타데이터를 함께 갱신하는 구조로 정리했다.

## Notes

- 이 티켓은 "문서형 티켓 저장소를 UI 로 조작할 수 있는가"를 여는 단계다. 실제 운영 스케줄러가 이 메타데이터를 어떻게 해석할지는 후속 운영 티켓으로 분리한다.
- 기능 정의서 기준으로 `v0.4.0` 에서는 메타데이터를 읽고 편집하는 문을 여는 것까지가 목표다. 우선순위 변경이 실제 실행 순서를 즉시 바꾸는 자동 반응은 `v0.5.0` 후속 범위다.
