# TKT-052

## 메타데이터

- 제목: Markdown 글 저장 계약과 렌더링 파이프라인
- 우선순위: P1
- 대상 버전: `v0.6.0`
- 상태: `finished`
- 문서 상태: `작성완료`
- 진행 판정: `v0.6.0 진행 시 가능`
- 소유자 유형: `worker`
- 권장 브랜치: `codex/tkt-052-markdown-post-storage-rendering`

## 목표

글 모델, 저장 계약, Markdown 렌더링 경로를 정리해 `Writing Studio` 와 공개 읽기 화면이 같은 콘텐츠를 안정적으로 읽도록 만든다.

## 작업 내용

- 글 데이터 모델을 코드 기준으로 정리한다.
- `id`, `slug`, `title`, `summary`, `bodyMarkdown`, `status`, `tags`, `createdAt`, `updatedAt`, `publishedAt` 최소 필드를 반영한다.
- 파일 기반 또는 단순 저장소 기준의 첫 저장 계약을 정한다.
- Markdown 을 공개 읽기 화면에서 렌더링하는 경로를 만든다.
- draft 와 published 를 구분하는 데이터 필터 규칙을 만든다.
- 저장 계약과 운영상 제약을 문서화한다.

## 범위

- 포함: 콘텐츠 모델, 저장 계약, Markdown 렌더링, 상태별 노출 규칙, 관련 문서 갱신
- 제외: DB 영속 저장 고도화, 다중 작성자 권한, 검색 인덱싱, 외부 CMS 연동

## 완료 기준

- 작성 화면과 읽기 화면이 같은 글 모델을 사용한다.
- Markdown 본문이 안정적으로 렌더링된다.
- draft 는 공개 목록에서 숨겨지고, published 만 공개 노출된다.
- 저장 계약이 문서로 남아 있다.

## 선행 조건

- `TKT-050`, `TKT-051` 과 데이터 계약이 충돌하지 않아야 한다.

## 질문/결정 기록

- 결정: 첫 버전은 Markdown 우선이다.
- 결정: 첫 저장 계약은 파일 기반 또는 단순 저장소부터 시작할 수 있다.
- 결정: 작성 화면 메타데이터는 UI 입력 필드로 관리하고, 저장 계약도 본문과 메타 필드를 명시적으로 분리한다.
- 결정: frontmatter 는 첫 버전 필수 조건이 아니다.
- 결정: 렌더링 typography 는 `design/blog-district-ui-system-2026-06-26.md` 의 읽기 기준과 맞춘다.

## 검토 메모

- 글 모델 `id/slug/title/summary/bodyMarkdown/status/tags/createdAt/updatedAt/publishedAt` 를 프런트 저장 계약으로 고정하고 Markdown 렌더러를 추가했다.
- 검토자는 draft 가 공개 아카이브에서 숨겨지는지, published 만 상세/목록으로 이어지는지, 기본 heading/list/blockquote/code block 렌더링이 안정적인지 확인하면 된다.
- 오케스트레이터 판정: 공개 읽기와 Studio 가 같은 콘텐츠 모델을 공유하고 있고, Markdown 렌더링도 완료 기준을 충족한다.
