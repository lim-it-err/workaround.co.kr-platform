# 릴리스 목표

이 문서는 각 버전 트랙이 왜 존재하는지, 그리고 해당 버전에서 무엇이 완료 상태인지 작업자가 빠르게 이해할 수 있도록 정리한 기준 문서다.

## 릴리스 운영 원칙

- 릴리스 진행은 사용자가 명시적으로 배포를 승인했을 때만 진행한다.
- 공식 버전 기준은 `Git tag` 와 `GitHub Releases` 이다.
- `GitHub Packages` 는 필요할 때만 쓴다. 컨테이너 이미지나 재사용 패키지가 필요할 때는 선택지지만, 릴리스 기준선 자체를 대신하지는 않는다.
- 릴리스가 끝나면 `docs/releases.md` 에 릴리스 날짜, 태그, 요약, 주의사항을 기록한다.
- 릴리스가 끝나면 기본적으로 최신 `main` 을 다시 가져와 다음 작업 기준선을 맞춘다.
- `infra` 와 `chore` 티켓은 릴리스 버전과 무관하게 진행할 수 있다.
- 버전이 붙는 티켓은 현재 릴리스가 아니라 해당 티켓의 `target version` 을 따른다.
- 워커는 현재 릴리스와 다음 릴리스를 구분해서 읽고, 임의로 버전 경계를 올리지 않는다.

## 현재 로컬 릴리스 후보 상태

- `v0.4.0`: 로컬 기능/검수 기준은 상당 부분 닫혔다.
- 다만 아직 공식 릴리스 상태는 아니다.
- 2026-06-16 재확인 기준 남은 blocker 는 아래와 같다.
  1. `VERSION` 이 아직 `0.1.0` 이다.
  2. 로컬 `main...origin/main [behind 30]` 이고 worktree 가 dirty 하다.
- Docker Desktop 설치와 daemon 기동 확인은 끝났다.
- 확인 결과:
  - Docker Server version: `29.5.3`
  - Docker Compose version: `v5.1.4`
- 따라서 현재 상태는 `v0.4.0 released` 나 `v0.4.0 release-ready` 보다, `v0.4.0 local completion candidate, publish pending baseline cleanup` 으로 읽는 편이 정확하다.
- 공식 `v0.4.0` 승격은 `main` 기준선 정리 후 `VERSION` 상향, 태그 생성, GitHub Release 생성 순서로 진행한다.

## 현재 개발 상한

- 최신 배포 완료 버전: `v0.1.0`
- 버전 기능 작업: 기본적으로 `v0.2.x`, 예외적으로 사용자 승인된 `v0.5.0` 이하 선작업까지
- 비버전 작업: `infra`, `chore`
- 다음 minor 후보: `v0.3.0`
- `v0.3.0` 다음 후보: `v0.4.0`
- `v0.4.0` 다음 후보: `v0.5.0`
- `v0.5.0` 후속 후보: `v0.5.1`
- `v0.5.1` 다음 후보: `v0.6.0`
- 예외: 사용자가 `localhost:7000` 확인 후 `v0.3.0` 선작업을 지시했고, 이후 `v0.4.0`, 이어서 `v0.5.0` 이하 작업까지 명시적으로 열어 두었으므로 `TKT-011`, `TKT-031`, `TKT-024` 같은 다음 minor 후보 작업은 미리 준비할 수 있다. 다만 `VERSION` 승격과 `v0.3.0`/`v0.4.0`/`v0.5.0` 릴리스 기준선 생성은 별도 승인 전까지 하지 않는다.

상세 규칙은 `docs/version-policy.md` 를 따른다.
