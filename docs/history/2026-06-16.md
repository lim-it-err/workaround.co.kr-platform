## 재시작 이후 기준선 재확인

- 사용자가 시스템 재시작을 마친 뒤 "마무리해줘" 라고 요청해, 재시작이 실제 blocker 를 줄였는지 다시 확인했다.
- 재확인 결과 재시작 자체로는 릴리스 blocker 가 해소되지 않았다.
  - `VERSION`: 여전히 `0.1.0`
  - Git 상태: `main...origin/main [behind 30]`
  - Docker: PATH 기준 미설치
- `java`, `mvn` 도 시스템 PATH 에는 여전히 없었지만, 저장소 내부에 설치한 portable runtime 은 계속 유효하다.
- 따라서 이번 재시작은 세션 꼬임 정리 수준의 효과만 있었고, 저장소 기준선 문제를 자동으로 닫지는 못했다.

## Docker Desktop 설치 시도와 결과

- 사용자가 Docker 설치를 직접 시도해 달라고 요청해, 공식 Docker Desktop Windows 설치 경로를 기준으로 설치를 진행했다.
- 설치 전 재확인한 조건은 아래와 같았다.
  - Windows: `Windows 10 Home`
  - `winget`, `choco`, `scoop`: 없음
  - `wsl --version`: `WSL 2.7.8.0` 확인
- 공식 Docker 문서 기준으로 Windows Home 에서는 Linux containers + WSL 2 backend 경로가 맞다고 보고, per-user 설치를 택했다.
- 공식 설치 파일을 내려받아 아래 인자로 설치했다.
  - `install --user --quiet --accept-license --backend=wsl-2`
- 설치 후 확인 결과:
  - Docker Desktop executable: `C:\Users\user\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe`
  - Docker CLI: `C:\Users\user\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe`
- 첫 확인에서는 daemon 이 아직 떠 있지 않아 `docker_engine` named pipe 연결 실패가 났다.
- 이어서 Docker Desktop 을 직접 실행하고 daemon 기동을 기다린 뒤 아래를 확인했다.
  - Server version: `29.5.3`
  - Docker Compose version: `v5.1.4`
- 따라서 "Docker 미설치 / Docker 재검증 부재" blocker 는 해소된 것으로 본다.
- 이 시점 기준 실질적인 release blocker 는 아래 2개만 남는다.
  1. `VERSION=0.4.0` 승격 미반영
  2. dirty `main...origin/main [behind 30]` 기준선 정리 미완료
