## 로컬 통합 프리뷰 복구

- 사용자가 `localhost:7000` 접근이 안 된다고 알려 주어, 현재 실행 프로세스부터 다시 확인했다.
- 재확인 당시 `node`, `java`, `python` 기반 앱 프로세스는 실제 프리뷰용으로 떠 있지 않았다.
- `frontend/README.md`, `gateway/README.md`, `services/elevator-service/README.md` 기준으로 현재 통합 프리뷰는 아래 3개가 함께 살아 있어야 한다고 다시 정리했다.
  - `frontend` dev server on `7000`
  - `gateway` on `8080`
  - `elevator-service` on `8003`
- 이를 반복 가능하게 만들기 위해 아래 스크립트를 추가했다.
  - `tools/start-local-preview.ps1`
  - `tools/stop-local-preview.ps1`
- `start-local-preview.ps1` 는 아래를 수행한다.
  - `elevator-service` 실행
  - packaged `gateway` jar 실행
  - `frontend` Vite dev server 실행
  - `8003/health`, `8080/api/health`, `7000` readiness 확인
- 실제 실행 결과:
  - `elevator-8003` started / HTTP 200
  - `gateway-8080` started / HTTP 200
  - `frontend-7000` started / HTTP 200
- 이후 Codex 샌드박스 안에서 띄운 백그라운드 프로세스는 명령 종료 뒤 같이 내려갈 수 있다는 점도 재확인했다.
- 이를 보완하기 위해 실제 사용자 세션에 남는 outside-sandbox 기동으로 다시 올렸고, `frontend:7000`, `gateway:8080` 은 그 상태로 유지됐다.
- `elevator-service` 는 로컬 Python direct launch 가 불안정해 Docker fallback 으로 최종 복구했다.
  - image: `workaround-elevator-service:local`
  - container: `workaround-elevator-service`
  - health: `GET http://127.0.0.1:8003/health` -> `200`
- 이에 맞춰 `tools/start-local-preview.ps1` 도 "로컬 Python 우선 -> 실패 시 Docker fallback" 구조로 보강했고, `tools/stop-local-preview.ps1` 는 컨테이너 정리까지 함께 수행하도록 갱신했다.

## 승격 준비 판정

- `VERSION` 은 정책상 아직 `0.1.0` 을 유지한다.
- 이유:
  - `VERSION` 은 최신 배포 완료 버전만 기록하는 파일이다.
  - 현재 사용자는 `승격 준비` 를 요청했지만, `main` 반영 완료 + 공식 배포 완료까지는 아직 닫히지 않았다.
- 따라서 오늘 단계의 목표는 `v0.4.0` 기능 후보를 안전한 Git 기준선으로 보존하고, 이후 `VERSION=0.4.0` 승격이 가능한 상태를 만드는 쪽으로 둔다.
- 같은 날 현재 dirty tree 는 새 브랜치 `codex/release-v0.4.0-local-candidate` 로 분기해 보존 커밋 `42f9b27` 로 묶었다.
