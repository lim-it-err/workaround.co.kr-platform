# 발견 노선 (Discovery Line) 정의

## 목적

매일 하나의 랜덤 주제를 "발견"하고, 원하면 세 방향으로 파고들며 배우는 실험 놀이터다. 부담 없이 하루 한 조각씩, 파고들고 싶을 때만 깊게 들어간다.

지하철 콘셉트: `Line D / Discovery`, 승강장 이름 "발견 정거장". 환승 홀 노선도(C 방식)의 한 지선으로 붙는다.

## 사용자 흐름

1. 발견 정거장에 들어가면 오늘의 주제 하나가 행선판처럼 뜬다(플랩 연출).
2. 주제의 **간단 설명**(2~3문장)을 먼저 읽는다.
3. 세 갈래 선택지가 승강장 출구처럼 제시된다.
   - ① 더 깊이 (deeper): 원리·디테일로 한 단계 파고든다.
   - ② 더 넓게 (broader): 맥락·역사·연결로 시야를 넓힌다.
   - ③ 뜻밖의 각도 (twist): 의외의 사실, 반대 관점, 엉뚱한 연결. (오케스트레이터가 만드는 세 번째 축)
4. 선택하면 그 방향의 설명이 나오고, 거기서 다시 같은 3갈래로 최대 **depth 3**까지 파고들 수 있다.
5. 하루가 지나면 다음 주제로 넘어간다. 지난 주제는 "지난 발견" 목록에서 다시 볼 수 있다.

## 하루 하나 규칙

- 날짜를 시드로 한 결정론적 선택으로 100개 주제 중 하나를 고른다(같은 날은 누구에게나 같은 주제). 날씨처럼 매일 바뀐다.
- 이미 본 주제는 `localStorage` 로 추적해 되도록 반복을 피한다(전부 소진하면 순환).

## 비용 모델 (핵심 설계)

토큰을 아끼면서도 "API 콜을 해보고 싶다"는 요구를 함께 만족하는 **하이브리드**로 둔다.

| 층위 | 생성 방식 | 런타임 토큰 |
| --- | --- | --- |
| depth 0: 간단 설명 | 미리 생성(정적 JSON) | 0 |
| depth 1: 3선택지 각 설명 | 미리 생성(정적 JSON) | 0 |
| depth 2~3: 더 파고든 설명 | **Claude API 온디맨드** + 캐싱 | 실제 파고들 때만 |

- 정적 데이터 규모: 100 주제 × (1 간단설명 + 3선택지) = **400 조각**. 이 정도는 프런트 번들 또는 서버 정적 파일로 충분히 관리된다.
- depth 2~3 는 사용자가 실제로 그 방향을 눌렀을 때만 gateway 경유로 Claude API 를 호출한다. 하루 몇 번 수준이라 비용이 작다.
- 같은 노드(주제+경로)를 다시 열면 캐시(서버 파일 또는 localStorage)에서 준다. 두 번째부터 토큰 0.

## 데이터 스키마 (정적)

```json
{
  "id": "d001",
  "title": "왜 하늘은 파랄까",
  "category": "science",
  "teaser": "빛이 대기의 공기 분자에 부딪혀 흩어지는 정도가 색마다 달라서다. 짧은 파장(파랑)이 더 많이 흩어진다. 노을이 붉은 이유도 같은 원리의 반대편이다.",
  "branches": {
    "deeper": "레일리 산란: 산란 세기는 파장의 4제곱에 반비례한다 ...",
    "broader": "같은 산란이 노을, 대기 원근, 담배 연기의 푸른빛까지 설명한다 ...",
    "twist": "화성의 하늘은 반대로 낮에 불그스름하고 노을이 파랗다 ..."
  }
}
```

- depth 2~3 응답은 별도 캐시 파일(`gateway/data/discovery-cache.json` 또는 유사)에 `{topicId, path: ["deeper","twist"], text}` 형태로 쌓는다.

## 게이트웨이 API (depth 2~3용)

- `POST /api/discovery/expand` — body `{ topicId, path: ["deeper", ...] }` → 캐시 히트면 저장분, 아니면 Claude API 호출 후 캐시하고 반환.
- LLM 경로는 `docs/agent-runtime.md`/`ollama-policy.md` 원칙을 따른다. 기본은 Claude API(외부), 대체로 로컬 Ollama 가능. 키/시크릿은 서버 환경변수로만 둔다.

## 범위

- 포함: 100 주제 정적 데이터(간단설명 + depth-1 3선택지), 발견 정거장 UI, 하루 하나 선택, 지난 발견 목록, depth 2~3 API 확장 + 캐싱, gateway 프록시 엔드포인트.
- 제외: 사용자 계정별 진도 동기화(로컬만), 정답/퀴즈, 소셜 공유, 주제 자동 무한 생성(첫 버전은 100개 고정).

## 열린 질문

- depth 2~3 LLM 제공자: Claude API(외부, 유료) vs 로컬 Ollama(RTX5070) vs 둘 다(우선순위/폴백)? 기본안: Claude API 우선, Ollama 폴백.
- 100 주제 카테고리 분포: 과학/역사/일상/기술/예술 등 균형? 기본안: 5~6개 카테고리 균등.
- 대상 버전: 기본안 `v0.8.0`.
