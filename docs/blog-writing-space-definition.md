# 블로그 글쓰기 공간 정의서

## 목적

이 문서는 사용자의 실제 목표인 "블로그 형식으로 글을 쓰고 축적하는 공간"을 제품 기준으로 정리한다.

`v0.6.0` 블로그 라인은 택시 시뮬레이터 다음의 별도 minor 로 두고, 시뮬레이터/아케이드 기능과 섞지 않는다.

## 기본 가정

- 작성자는 현재 한 명이다.
- 독자는 공개 페이지에서 글을 읽는다.
- 첫 버전은 다중 작성자 CMS 가 아니다.
- 첫 버전의 작성 방식은 Markdown 우선이다.
- 댓글, 좋아요, 구독, 검색, 추천 알고리즘은 첫 버전 범위에서 제외한다.

## 제품 한 줄 정의

`Blog District` 는 포털 안에서 사용자가 글을 쓰고, 초안으로 보관하고, 공개 발행까지 이어 갈 수 있는 단일 작성자용 글 공간이다.

## 왜 별도 버전으로 두는가

- Work Manager 와 시뮬레이터는 조작과 상태 읽기가 중심이다.
- 블로그는 읽기 리듬, 글쓰기 집중감, 초안/발행 흐름이 중심이다.
- 따라서 같은 minor 안에 섞으면 정보 구조와 디자인 판단이 다시 흔들린다.

## 정보 구조

### 1. Blog Entry

메인 허브 또는 후속 허브에서 `Blog District` 진입 카드를 본다.

역할:

- 글 공간으로 들어가는 진입점
- 최근 발행 글 수, 최근 발행일, 초안 수 같은 요약 지표 표시

### 2. Public Archive

공개 글 목록을 보는 페이지다.

필수 요소:

- 글 목록
- 대표 제목
- 짧은 요약
- 태그 또는 카테고리
- 발행일
- 글 상세로 이동하는 CTA

### 3. Post Detail

단일 글을 읽는 페이지다.

필수 요소:

- 제목
- 부제 또는 요약
- 본문
- 작성일 / 수정일 / 발행일
- 이전 글 / 다음 글 또는 아카이브 복귀

### 4. Writing Studio

단일 작성자가 글을 쓰고 관리하는 페이지다.

필수 요소:

- 제목 입력
- slug 입력 또는 자동 생성
- 요약 입력
- Markdown 본문 편집
- 미리보기
- 상태 전환: `draft`, `published`, `archived`
- 임시 저장 시간 표시

## 콘텐츠 모델

첫 버전의 최소 글 모델:

- `id`
- `slug`
- `title`
- `summary`
- `bodyMarkdown`
- `status`
- `tags`
- `createdAt`
- `updatedAt`
- `publishedAt`

## 작성 흐름

1. 새 글 생성
2. 제목 / 요약 / 본문 작성
3. 미리보기 확인
4. `draft` 저장
5. 필요 시 수정
6. `published` 전환
7. 공개 아카이브와 상세 페이지 반영

## 설계 기본안

- 저장 계약은 파일 기반 또는 단순 저장소부터 시작할 수 있다.
- 편집 UI 는 rich text 보다 Markdown 편집 + preview 를 우선한다.
- 공개 읽기 페이지는 긴 글을 읽기 편한 typography 를 우선한다.
- 작성자용 Studio 는 포털 분위기를 유지하되 읽기/쓰기 집중감을 해치지 않는 별도 화면 리듬이 필요하다.

## 제외 범위

- 다중 작성자 권한 체계
- 댓글
- 외부 OAuth
- 에디터 협업
- 실시간 공동 편집
- SEO 고도화
- RSS/뉴스레터 자동화

## 디자이너에게 필요한 산출물

1. `Blog District` 진입 카드와 허브 내 위치
2. 공개 아카이브 목록 레이아웃
3. 글 상세 읽기 typography 규칙
4. `Writing Studio` 편집/미리보기 이중 패널 구조
5. 모바일 읽기 화면과 모바일 작성 화면 우선순위
6. 수동 발행/임시저장 상태가 직관적으로 읽히는 badge 규칙

## worker 에게 필요한 구현 경계

1. 라우팅과 화면 껍데기
2. 글 모델과 저장 계약
3. Markdown 렌더링
4. 초안/발행 상태 전이
5. 읽기 페이지 typography 와 레이아웃

## 열린 질문

- 태그만 둘지, 카테고리까지 둘지
- 공개 글 정렬을 최신순만 둘지, 고정 글(pinned) 개념을 둘지

## 후속 버전으로 넘긴 것

- 이미지 업로드는 첫 버전 `v0.6.0` 에 넣지 않는다.
- 이미지 업로드와 미디어 자산 처리는 `v0.7.0` 의 별도 후속 티켓으로 분리한다.
