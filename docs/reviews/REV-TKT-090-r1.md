### ② 스탬프 상태 persist
**메모(기록 초안) persist를 실제 풀 페이지 리로드로 검증**: V01 카드 텍스트영역에 테스트 문구 입력 → `localStorage['workaround-voyage-archive:east-europe-2026']`에 `{"stamps":[],"notes":{"stop-1":"..."}}"` 저장 확인 → 완전 리로드(`navigate`) → 스플래시 재통과 → V03 재진입 → **같은 텍스트가 그대로 복원**되고 상단 요약이 "0개 스탬프 · 1개 기록"으로 정확히 갱신됨을 확인. 검증 후 테스트 데이터는 정리(`localStorage.removeItem`).
**스탬프 찍기(방문 도장) 자체는 오늘(2026-08-18)이 전 여정(9/8~9/18)보다 이전이라 9개 전부 `visited:false`(LOCKED)라 실클릭 재현이 불가능한 환경적 제약**이 있다 — 대신 코드로 이중 방어를 확인: `toggleStamp()` 함수 자체가 `if (!stop.visited) return`으로 가드하고(`VoyageArchiveView.vue:49-52`), 버튼도 `:disabled="!stop.visited"`(122행)라 네이티브 HTML단에서도 클릭이 막힌다. `stamps` 배열에 대한 저장 로직(`watch([stampedIds, notes], ...)`)은 메모와 동일한 watch 콜백을 공유하므로, 메모 persist가 실증됐다는 것은 저장 배선 자체가 정상 동작함을 뜻한다 — 남은 것은 여행 중 실제 클릭 UX뿐이며 로직상 리스크는 낮다고 판단.
