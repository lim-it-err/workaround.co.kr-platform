## [중요] I1 — 샘플을 실제 관제와 구분할 표시가 없고, 정상 순환 중에도 오래된 화면처럼 바뀐다

**보이는 현상:** URL 미설정 시 합성 샘플을 순환하지만 제목은 `유로트럭 관제`, 정보는 `82 km/h`, `감시 중 · 정지 0초`, 신선도는 `2초 전`이다. 상단·프레임·하단 어디에도 `샘플` 또는 `미리보기`라는 설명이 없다. 그림을 보고 예시임을 추측할 수는 있어도 값과 연결 상태가 실제인지 화면이 설명하지 않는다.

또한 샘플의 캡처 시각이 페이지 최초 진입 시각에 고정된다. 검증용 시계를 120초 진행시키면 샘플을 정상 사용 중인 화면이 `마지막 화면 · 2분 전`과 10초 폴링으로 바뀌고, 301초 진행 시 30초 폴링이 된다. 서버 신호가 끊기지 않았는데도 데모가 장애처럼 보인다. 이 시간 검증은 실제 5분 대기가 아니라 Date.now 오프셋 주입이다.

- 근거: `frontend/src/components/Ets2Live.vue:5` URL 미설정 분기, `:6` 최초 시각, `:86` 샘플 capturedAt 고정, `:128` 순환, `:177` 제목·신선도, `:221` 하단 표시.
- 실렌더: [375 다크 첫 화면](UX-TKT-168-r1-assets/ux-375-dark-live.png), [1440 라이트 첫 화면](UX-TKT-168-r1-assets/ux-1440-light-live.png), [375 라이트 시간 진행 후](UX-TKT-168-r1-assets/ux-375-light-stale.png), [5분 경과 표시](UX-TKT-168-r1-assets/ux-375-dark-five-minutes.png).
- **[디자이너 의견]** 실제 소스가 없으면 신선도 행에 `샘플 화면 · 실제 주행 정보 아님`을 표시하는 것이 필요하다. 정상 샘플 순환과 의도적 정지 예시는 구분하고, 샘플 순환이 단순 체류 시간 때문에 장애로 보이지 않게 해달라. 카피와 동작 확정은 PM 소관이다.
- 후속 확인: URL 미설정 상태에서 첫 진입과 장시간 체류 모두 샘플임을 알 수 있고, 실제 소스 연결 시에만 실제 주행 값으로 읽히는지 확인.

## [제안] S1 — 정지·신호 없음에서 주행 값도 마지막 수신 값임을 알려주기

프레임의 흐림과 `관제 신호 없음` 안내는 다크·라이트 모두 읽힌다. 다만 프레임 위의 주행 정보는 정상 상태와 같은 강조로 `82 km/h · 감시 중 · 정지 0초`를 유지한다. 사용자는 이미지의 정지와 감시 기능의 실행 상태를 따로 받아들일 수 있다. 마지막 값을 보존하는 선택은 유용하므로, 행 옆에 `마지막 수신 정보` 또는 `현재 상태 확인 불가`라는 관계를 드러내면 좋겠다.

- 근거: `frontend/src/components/Ets2Live.vue:56` 연결 판단은 마지막 메타만 사용, `:68` 감시 문구, `:185` 주행 행, `:217` 실패 안내는 프레임 쪽에만 배치. `frontend/src/styles.css:4518` 값 강조, `:4556` 프레임만 흐림.
- 실렌더: [375 다크 신호 없음](UX-TKT-168-r1-assets/ux-375-dark-lost.png), [1440 라이트 신호 없음](UX-TKT-168-r1-assets/ux-1440-light-lost.png).
- 스펙 위반 단정이나 필수 값 삭제 요청은 아니다. 정지 상태의 해석을 보완하는 PM 선택 사항이다.
