## 실행 검증 — 이번엔 "왜 안전한지"부터 코드로 확인

- `git diff -- frontend/src/App.vue`로 새 로직을 직접 읽었다:
  - `markReturnSplashSettled()`가 실제 정착 시각(`settledAtMs`)을 기록하고, 전환 시각을 `min(4000, max(3800, settledAtMs + 1000))`로 **동적으로 재계산**한다(r1의 "고정 3.8초"에서 "정착 기준 동적 계산"으로 구조 자체가 바뀜).
  - **핵심 안전장치**: `SPLASH_RETURN_SETTLE_LIMIT_MS = 2800` 타이머가 자연 애니메이션 완료 여부와 무관하게 2800ms 시점에 강제로 `markReturnSplashSettled()`를 호출한다(`settledSplashRunId` 가드로 이미 자연 완료됐으면 중복 호출 무시). 즉 **`settledAtMs`가 2800ms를 넘는 경로가 코드 구조상 존재하지 않는다** — 특정 난수값을 운 좋게 피해서가 아니라 타이머가 상한을 강제한다.
  - `compact` 모드(재방문 전용)는 spin 횟수 자체도 줄여(`charIndex % 2 + floor(random*3)` vs 기존 `% 3 + floor(random*4)`) 안전 타이머가 자주 발동하지 않도록 자연 완료를 앞당기는 보조 장치로 확인했다.
- 신규 E2E `recent visit worst random`(`Math.random=0.99`)을 코드로 대조: `floor(0.99*3)=2`가 해당 공식의 수학적 최댓값과 일치 — 임의로 "그럴듯한 큰 수"가 아니라 실제 상한값을 쓴 것을 확인했다. 다만 안전 장치가 타이머 기반이라 이 특정 난수값이 아니어도 상한 보장은 동일하게 성립한다(구조적 보장이 테스트보다 더 강함).
