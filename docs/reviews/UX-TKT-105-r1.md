## 발견 사항

### UX-01 [블로커] 표 식별자와 사진 인코딩 문자열이 편집 본문에 노출된다

**TKT-105 추가 기능.** 표 삽입 직후 본문에는 표 내용 대신 `[[studio-table:table-…]]`가 표시되고, 사진 첨부 직후에는 `data:image/png;base64,…`가 길게 들어온다. 이 상태에서 사용자는 표의 내용이나 사진을 보며 다음 문단을 쓸 수 없고, 미리보기와 편집을 오가며 저장 형식 사이에서 커서를 찾아야 한다. 사진·표가 미리보기에서 정상 렌더되는 것과 별개로, 편집 단계의 가독성과 내부 용어 비노출 원칙이 충족되지 않는다.

- 재현: Studio → 본문 끝에 커서 → 모바일 `＋` / 데스크톱 `표` → 표 이름·셀 입력 → `표 삽입` → `사진 첨부` → 가상 PNG 선택 → 본문에서 이어 쓰기.
- 실측: **1,823바이트 PNG 한 장**으로 본문 문자열은 2,588자가 됐다. 375px 본문은 `clientHeight=395`, `scrollHeight=2413`; 1440px에서도 `481/1200`으로 늘었다. 원래 짧은 글에 저장용 문자열이 대부분의 편집 스크롤을 차지한다. 네 뷰포트·테마 조합 모두 재현됐다.
- 소스: `frontend/src/components/WritingStudio.vue:164`(사진 data URL 삽입), `:213`(표 내부 토큰 삽입), `:297`(저장 문자열을 textarea에 그대로 표시).
- 기준: `design/writing-studio-spec.md` §2의 글 쓰는 방, §6 기능형 편집기 취지 및 `design/ux-copy-audit-2026-08-16.md` §2-3 내부 용어 비노출. **파이프 문법만 없다는 사실로 사용자 친화적인 편집 경험을 충족했다고 보기 어렵다.**
- 근거: [375px 표 삽입](UX-TKT-105-r1-assets/375-dark-table-inserted.png), [375px 라이트 사진 삽입](UX-TKT-105-r1-assets/375-light-photo-inserted.png), [375px 이어 쓰기](UX-TKT-105-r1-assets/375-dark-after-photo-writing.png), [1440px 사진 삽입](UX-TKT-105-r1-assets/1440-dark-photo-inserted.png).
- 디자이너 권고: 편집 표면에는 표 이름·내용 미리보기와 사진 썸네일처럼 사용자가 식별할 수 있는 블록을 보여주고, 저장용 식별자·바이너리 문자열은 숨기는 방향을 PM이 확정할 것을 요청한다. 저장 형식을 바꾸라는 결정은 하지 않는다.

### UX-02 [중요] 새 도구 진입 버튼과 데스크톱 도구가 40px 타깃 기준에 못 미친다

### UX-03 [중요] 모바일 제목의 끝이 잘려 글의 제목을 한 번에 확인할 수 없다

**기존 구현에서 이어진 결함이며 TKT-105 신규 회귀로 단정하지 않는다.** 가상 제목 `길 위에서 기록을 이어 쓰는 작은 방법`은 375px에서 마지막 부분이 보이지 않는다. 단일 행 input 내부는 `scrollWidth=372`, `clientWidth=321`로 **51px 넘친다**. 페이지 전체 overflow가 0이어도 제목 가시성은 확보되지 않는다. 1440px에서는 전체가 보인다.

- 소스: `frontend/src/components/WritingStudio.vue:296`, `:455`, `:456`.
- 목업 대조: `frontend/public/mockups/writing-studio.html:21`, `:40`의 여러 줄 제목에 같은 가상 제목을 입력하면 375px에서 `scrollWidth=clientWidth=335`, `scrollHeight=clientHeight=75`로 전체가 보인다. 목업 r2 제목 잘림 수정은 `REV-TKT-102-r1.md`에도 이미 기록돼 있다. TKT-105는 목업 배치가 참고 사항이므로, 목업과 픽셀 단위로 다르다는 이유로 지적한 것은 아니다.
- 근거: [실화면 375px](UX-TKT-105-r1-assets/375-light-baseline.png), [같은 제목의 목업 375px](UX-TKT-105-r1-assets/375-mockup-title.png).
- 디자이너 권고: 전체 제목을 편집 중에 읽을 수 있도록 여러 줄 표시를 검토한다. TKT-105에 함께 반영할지 후속 톤 전환에서 처리할지는 PM 배정 사항이다.

### UX-04 [제안] 모바일 표 편집기의 가로 이동 가능성을 더 분명히 보여준다

375px에서 표 영역은 333px, 실제 표는 420px로 기본 2열부터 **87px가 가로 스크롤 안에 들어간다**. 페이지 전체 overflow는 0이며 두 번째 열에도 입력할 수 있다. 다만 터치 화면에서는 가로로 더 볼 수 있다는 단서가 약하고, 우측 셀 경계가 잘려 있다. 데스크톱에서는 전체 표가 보인다.

- 소스: `frontend/src/components/WritingStudio.vue:492`, `:493`, `:496`.
- 근거: [375px 2열 편집](UX-TKT-105-r1-assets/375-dark-table-2cols.png), [375px 3열 편집](UX-TKT-105-r1-assets/375-dark-table-3cols.png), [1440px 2열 편집](UX-TKT-105-r1-assets/1440-light-table-2cols.png).
- 디자이너 권고: 기본 2열은 가능하면 한눈에 보이게 하고, 더 넓은 표에는 끝단·스크롤 가능 상태를 시각적으로 드러낸다. 내부 가로 스크롤 자체를 기능 실패로 판정하지 않는다.

### UX-05 [제안] 모바일에서도 블로그로 돌아가는 목적지를 표시한다

TKT-105에서 버튼 문구는 `← 블로그`로 바뀌었지만, 760px 이하 CSS가 span을 숨겨 실제 375px 화면에는 `←`만 남는다. 스크린리더 이름은 블로그로 제공된다. 데스크톱 문구와 목업의 모바일 문구는 `← 블로그`다.

- 소스: `frontend/src/components/WritingStudio.vue:277`, `:516`; 기준 `design/writing-studio-spec.md` §6.
- 근거: [375px 실제 바](UX-TKT-105-r1-assets/375-dark-baseline.png), [375px 목업 바](UX-TKT-105-r1-assets/375-mockup-title.png).
- 디자이너 권고: 좁은 화면에서 저장 상태·도구 배치를 조정할 때 목적지 이름도 함께 살리는 방향을 검토한다. 단순 화살표가 브라우저 뒤로가기와 혼동될 수 있다.
