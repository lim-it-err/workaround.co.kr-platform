## [중요] I1 — 만점에도 ‘먼저 고칠 것’과 재제출을 가장 강조한다

- 파일: `services/advisor/frontend/src/modules/missions/pages/ReviewPage.vue:118`, `:139`, `:145`.
- 모든 루브릭 항목의 획득 점수를 배점과 같게 둔 합성 리뷰(총 100점)로 375/1440 다크·라이트 4환경에서 재현했다. 화면은 **‘100점 / 먼저 고칠 것 1개 / 책임 분리 / 30 / 30점 · 0점 회복 여지 / 요구한 기준을 충족했습니다.’**와 **‘코드 고쳐서 재제출’**을 주 행동으로 보여 준다.
- 원인: `firstFix`의 reduce가 첫 항목을 무조건 선택하고 양의 감점이 있는지 걸러내지 않는다. 렌더도 리뷰 존재만으로 재제출 주 CTA를 보여 준다.
- 사용자 영향: 기준을 모두 충족한 사용자에게 무엇을 더 고치라는 것인지 모호하며 불필요한 재제출을 유도한다. TKT-154의 ‘상태에 맞는 CTA’ 목표에 남은 예외다.
- 제안: 양의 감점이 없으면 수정 항목을 숨기고 충족 상태를 안내한다. 실제 코스 다음 항목 또는 배우기 복귀를 주 행동으로, 선택적 재제출은 보조 행동으로 두는 안을 PM에 제안한다. 최종 문구·동작은 PM이 확정한다.
- 증거: [375 라이트 만점](UX-TKT-154-r1-assets/375-light-perfect-viewport.png), [1440 라이트 만점](UX-TKT-154-r1-assets/1440-light-perfect-viewport.png), [4환경 상태 측정](UX-TKT-154-r1-assets/metrics.json)의 `*-perfect` 항목.
- 재현 데이터는 실제 루브릭 배점 30/20/20/15/15를 그대로 사용했다. 로컬 저장소에 합성 리뷰를 주입했으며 실제 백엔드가 만점을 반환했다고 주장하지 않는다. 캡처의 ‘실시간 리뷰’ 문구도 저장된 리뷰 형식을 재현한 테스트 화면이다.
