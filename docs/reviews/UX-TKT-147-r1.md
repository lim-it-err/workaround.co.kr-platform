## [중요] I1 — 3.8초 고정 타이머가 실제 문구 정착 후 1초를 보장하지 않는다

- 근거: `frontend/src/App.vue:29` 재방문 3800ms, `:1413` 무작위 flip 횟수, `:1471` 셀 시퀀스·최종 flip 330ms, `:1486` 셀 지연, `:2348` 고정 전환 타이머. `frontend/src/styles.css:2739` 퇴장 페이드 0.45초.
- 사용자 영향: 문구가 완성되자마자 읽기 시작해도 1초가 되기 전에 화면이 흐려지며 이동한다. 목표 ‘정착 후 1.0초 이상 보이고 전환’의 안정적인 읽기 구간이 확보되지 않는다.
- 실제 난수·실제 시간의 Chromium 4환경에서 시각 정착과 `.fade-leave-active` 시작을 20ms 간격으로 관찰했다. 상단 문자뿐 아니라 실제 노출되는 하단 flip/static 문자, 실행 중 CSS animation 0개를 함께 확인했다. 아래 3/4환경이 1초 미달이었다. 375 라이트의 1.001초는 측정 해상도상 경계값으로 본다.

- 근거 이미지: [375 다크 정착 화면](UX-TKT-147-r1-assets/375-dark-followup-settled.png), [1440 다크 정착 화면](UX-TKT-147-r1-assets/1440-dark-followup-settled.png). 시각 근거와 시간 계측은 함께 읽어야 한다: [timing-followup.json](UX-TKT-147-r1-assets/timing-followup.json).
- **초기 측정 정정**: `metrics.json`의 `readingMs`는 DOM 제거까지 계산해 0.45초 페이드까지 포함한다. 그 값만으로 1초 충족이라고 판정하면 안 된다. 후속 측정의 `steadyReadingMs`가 전환 시작 전 구간이다. DOM 제거 시점은 약 4.26초였지만 제품 타이머 자체가 4.26초로 바뀐 것은 아니다.
- 직접 실행한 기존 splash E2E는 **6/6 통과**했다. `frontend/src/splashTone.e2e.mjs:86`의 `Math.random=0.1` 고정 fixture는 실제 분포의 긴 정착 사례를 대표하지 못한다. 테스트 통과와 이번 실제 시간 관찰은 분리한다.
- 제안: PM이 총 3.6~4.0초 계약을 유지한다면 재방문 셀의 최종 시각 정착 상한을 2.8초 이내로 보장하고, 대표 난수 한 값 외에 긴 정착 경로도 검증한다. 정착 완료 뒤 1초를 기다리는 방식은 총 시간 계약과의 정합을 PM이 결정해야 한다. 앱은 수정하지 않았다.

## [제안] S1 — 저장 안내 원의 실제 외경은 28px가 아니라 30px

- 근거: `frontend/src/styles.css:4408` 의사 요소에 width/height 28px와 양쪽 1px border를 사용한다. `:73`의 `* { box-sizing: border-box }`는 의사 요소를 포함하지 않아 실제 computed `::before.boxSizing`은 **content-box**다.
- 계산: 콘텐츠 28 + 좌우 border 각 1 = **외경 30px**. 4환경 모두 동일하다. 기존 테스트 `frontend/src/components/WritingStudio.e2e.mjs:128`는 computed width/height만 읽으므로 테두리를 포함한 외경을 놓친다.
- 근거: [375 라이트 저장 안내](UX-TKT-147-r1-assets/375-light-storage.png), [1440 라이트 저장 안내](UX-TKT-147-r1-assets/1440-light-storage.png), [metrics.json](UX-TKT-147-r1-assets/metrics.json) `geometry.pseudo`.
- 사용자 영향은 경미하다. 이전 40px 시각 원보다 가벼워졌고 실제 버튼 **40×40px**는 정상이다. 시각 외경을 정확히 28px로 맞추려면 해당 의사 요소에 `box-sizing: border-box`를 명시하는 안을 제안한다. 전역 box-sizing 변경은 필요하지 않다.

- 첫 방문 10초·재방문 표시 3.8초·다시 재생 10초·만료/저장 불가 fallback은 직접 splash E2E 6/6에서 확인했다. 이 시간 계약 테스트는 가상 시계로 실행했다.

## 재현·범위·인계

스냅샷의 메인 Pages-base를 직접 빌드(49 modules)해 127.0.0.1 정적 서버로 제공했다. 375×900·1440×900 다크/라이트, 실렌더 8회(초기4+전환 시점 보충4), 스크린샷28장. 스튜디오는 새 브라우저 컨텍스트의 저장소와 저장소 내 기본 샘플 초안만 사용했다. 실계정 데이터·실서버 API를 사용하지 않았다.

`UX-TKT-147-r1-assets/`에 스냅샷 위치·source-sha·source-comparison·측정 JSON·스크립트·검증 요약을 보존했다. 종료 대조 시 추적 소스 변경 없음. 무작위 애니메이션 전수/저사양 기기/WebKit/VoiceOver/실 Pages는 미검증. 난수·CPU 스케줄에 따라 정착 시각은 달라질 수 있으며 위 수치는 관찰한 재현 사례다.

앱·목업·티켓·보드 수정, commit/push 없음. 현재 need_review 검수 큐가 남아 기존 자동화의 임시 1분 주기를 재개한다. 한 실행 한 작업을 유지하고 TKT-161은 검수 루틴 뒤에 처리한다.
