## 추가로 확인한 것 (게이트에 명시는 없으나 적대적 관점에서 점검)

- **SVG 좌표 밀집도**: viewBox 원시 좌표만 보면 R 의 상태 텍스트(y=374)와 V 의 칩(y=369 시작)이 5px 차이로 붙어 보여 겹침을 의심했다. 실제 렌더링된 `getBoundingClientRect` 로 재보니 R "부분 저하" 텍스트 bottom=552.3, V "여행 준비" 텍스트 top=596.6 — **실측 44px 여유**, 겹침 없음. (viewBox 단위와 실제 렌더 스케일이 달라 원시 좌표 비교만으로는 오판할 뻔했다.)
- **모바일 375px — 실제 voyage 화면 기준**: 완료 게이트는 "375px 확인"이라고만 적혀 있어, 환승 홀이 아니라 **V01 화면 자체**에서 재확인했다(`document.documentElement.scrollWidth === clientWidth === 375`, 오버플로 0). 클린 스크린샷으로 레이아웃 확인(노선 배지·타이틀·상태 라인·나가기 버튼 375px 안에 정상 배치).
- **콘솔 에러**: `/api/services/elevator-service/*`, `/api/runtime`, `/api/work-manager/board` 에서 404/502 다수 발생했으나, 네트워크 로그로 확인한 결과 **전부 백엔드 게이트웨이 미기동(이번 검증은 프런트 단독 기동) 때문** — voyage 페이지 자체는 어떤 API 도 호출하지 않는 정적 placeholder라 V 기능과 무관. 이 에러들을 "V 티켓이 만든 콘솔 에러"로 잡으면 오판이라 별도로 기록한다.
