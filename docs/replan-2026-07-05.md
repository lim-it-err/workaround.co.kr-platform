# 재수립 계획 2026-07-05 (호스팅 로드맵)

## 배경

2026-07-05 사용자 지시로 오케스트레이터(Claude)가 전체 계획을 재수립한다. 이 문서는 호스팅까지의 상위 실행 계획이며, 버전 정책과 티켓 규칙은 기존 `docs/version-policy.md`, `docs/ticket-policy.md` 를 그대로 따른다.

## 확정된 사용자 결정 (2026-07-05)

- 사이트 정체성: **개인 블로그 중심 + 실험 놀이터**.
- 개발 상한을 `v0.6.0` 라인까지 연다. 구현은 에이전트(워커)에게 위임하고, Codex 에이전트도 참여할 수 있도록 티켓은 실행 지시서 수준으로 유지한다.
- 디자인/UX는 **지하철 콘셉트를 유지하되 전면 재작업**한다. 시안 2~3개를 테스트용 HTML로 만들어 사용자 검토를 받는다. 플랩(행선판) 연출은 지금보다 매끄럽게 다듬는다.
- 기존 기능 오작동을 전부 수정한다. 사용자 지목 우선순위: **엘리베이터 시뮬레이터, Work Manager, 블로그/글쓰기 스튜디오** (택시는 상대적으로 양호). 전 기능 QA도 병행한다.
- 공개 순서는 **블로그 먼저**. 운영 도구(Work Manager 등)는 보호 경로 뒤에 둔다.
- 사용자 코드 검토 채널은 **PR**이다. 코드 작업은 PR까지 올려 두고, PR 생성이 어려우면 태그를 만들어 둔다.

## 완료된 기반 정리 (Phase 0, 2026-07-05)

- 미커밋 `v0.3.1`/`v0.5.0`/`v0.6.0` 작업을 `codex/local-snapshot-2026-07-05` 브랜치와 `snapshot-2026-07-05` 태그로 안전 확보.
- 로컬 `main` 을 `origin/main`(`v0.2.0` 릴리스 + PR #1/#2 머지 상태)으로 동기화.
- `codex/v0.6.0-line` 통합 브랜치를 만들어 스냅샷을 `origin/main` 위로 머지. 충돌 24건 해소: 코드/운영 문서는 진화한 스냅샷 측 채택, `VERSION` 은 `0.2.0` 유지, `docs/releases.md` 는 내용 병합. origin 고유 픽스 2건(gateway payload `LinkedHashMap`, worker once-mode 출력) 보존 확인.
- 검증: 프런트엔드 빌드 성공, 게이트웨이 테스트 3/3 통과.

이후 모든 작업의 기준 브랜치는 `codex/v0.6.0-line` 이다. 작업 브랜치는 `codex/tkt-XXX-...` 로 파서 이 브랜치로 모으고, `main` 반영은 사용자 승인 PR로만 한다.

## 남은 단계

### Phase 1 — 방향/문서 정비 (orchestrator)

- 티켓 보드 정리: `TKT-018` 재판정(`v0.2.0` 은 원격에서 이미 릴리스 완료), 인코딩 깨진 티켓 5건(`TKT-012`, `TKT-018`, `TKT-026`, `TKT-028`, `TKT-029`) 복구, `docs/tickets/started/README.md` 잔존 항목 정리.
- 사이트 정체성(블로그 중심 + 실험 놀이터)에 맞춘 `docs/feature-definition.md` 개정.

### Phase 2 — UX 전면 재작업 (designer → 사용자 검토 → worker)

- 디자이너: 지하철 콘셉트 유지 시안을 `design/mockups/2026-07-05/` 아래 자체 완결형 HTML로 제작. 플랩 연출 개선, 라이트/다크, 데스크톱/모바일 포함.
- 사용자 검토로 방향 확정 → 디자인 시스템 문서(`design/ui-ux-rules.md` 등) 갱신 → UI 재구현 티켓 발행.
- UI 재구현과 함께 `frontend/src/App.vue` 모놀리스를 컴포넌트 단위로 분해한다. 여러 에이전트가 병렬로 개발하기 위한 전제 조건이다.

### Phase 3 — 버그 소탕 (worker)

- QA 스윕: 엘리베이터/Work Manager/블로그 우선, 이후 전 기능.
- 발견 버그는 재현 절차 + 기대 동작 + acceptance criteria를 갖춘 티켓으로 만들어 워커가 수정한다. 검토는 PR 단위.

### Phase 4 — v0.6.0 완성 (worker)

- 블로그 글 저장을 브라우저 `localStorage` 에서 **서버측 저장**으로 전환한다. 호스팅 시 방문자가 글을 읽으려면 필수 선결 조건이며, `TKT-043`(운영 저장소 전환)과 함께 저장 계약을 재설계한다.
- 블로그 이미지 업로드(`TKT-053`)는 2026-07-05 사용자 승인으로 `v0.6.0` 라인에 편입되었다. 서버측 글 저장 전환 뒤에 착수한다.
- 시뮬레이터 라인(`v0.3.x`/`v0.5.0`)의 마감 품질을 정리한다.

### Phase 5 — 호스팅 (infra, 사용자 승인 필수)

- 공개 범위: 블로그(공개) / Work Manager 등 운영 도구(보호) / 시뮬레이터(준비되는 대로 공개).
- 프로덕션 compose 구성, Caddy 기반 TLS, DNS(`workaround.co.kr` canonical, `workaround.kr` redirect), 시크릿/보안 정비, 백업 경로.
- 서버 사양/접속/포트 정책은 사용자 확인이 필요하다(`docs/roadmap.md` 의 로드맵 결정 질문 참고).

## 릴리스/PR 운영

- 사용자 검토 단위는 PR. `gh` CLI 설치 전에는 push된 브랜치 + 태그 + PR 초안 메모로 대신하고, 사용자가 GitHub에서 PR을 연다.
- `main` 반영, `VERSION` 승격, 릴리스 태그, GitHub Release는 사용자 승인 후에만 진행한다.
- 히스토리 기록은 기존 방식(`docs/history/YYYY-MM-DD.md`)을 유지하되, 사용자 결정/검증 결과/PR·태그 링크를 항상 포함한다.
