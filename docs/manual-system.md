# 매뉴얼 체계

## 목적

제품 기능이 늘어나도 "어디에 무엇을 적어야 하는가"가 흔들리지 않도록, 매뉴얼 문서의 역할과 위치를 고정한다.

## 핵심 원칙

1. 기능 정의서와 사용 매뉴얼을 섞지 않는다.
2. 운영 매뉴얼과 사용자용 매뉴얼을 분리한다.
3. 구현이 바뀌면 관련 매뉴얼도 같은 변경 안에서 갱신한다.
4. 짧은 README 와 상세 매뉴얼의 역할을 분리한다.

## 권장 매뉴얼 계층

### 1. 제품 기준 문서

대상:

- 오케스트레이터
- worker
- 디자이너

문서 예:

- `docs/feature-definition.md`
- `docs/blog-writing-space-definition.md`
- `docs/roadmap.md`

역할:

- 무엇을 만들 것인지
- 어느 버전에 무엇이 들어가는지
- 제품 경계가 무엇인지

### 2. 작성자 매뉴얼

대상:

- 실제 글을 쓰는 사용자

권장 문서:

- `docs/manuals/author-writing-guide.md`
- `docs/manuals/publishing-checklist.md`

역할:

- 새 글 만드는 법
- 초안 저장 / 발행 흐름
- 제목, 요약, 태그 작성 규칙
- 발행 전 체크리스트

### 3. 독자-facing 운영 가이드

대상:

- 블로그 화면을 읽는 사용자

권장 문서:

- `docs/manuals/blog-reading-guide.md`

역할:

- 글 목록/상세 탐색 방식
- 아카이브 구조
- 카테고리/태그 읽는 법

### 4. 운영/관리 매뉴얼

대상:

- 오케스트레이터
- 운영 사용자

권장 문서:

- `docs/manuals/blog-operations.md`
- `docs/manuals/content-recovery.md`

역할:

- 글 저장 위치
- 백업/복구
- 발행 실패 시 확인 순서
- slug 충돌, 렌더 오류, 콘텐츠 복원 절차

### 5. 디자인 스타일 매뉴얼

대상:

- 디자이너
- 프런트 worker

권장 문서:

- `design/ui-ux-rules.md`
- 향후 `design/blog-reading-style.md`

역할:

- 읽기 typography
- 편집기/미리보기 화면 리듬
- 모바일 읽기/쓰기 패턴

## 블로그 기능에 바로 필요한 매뉴얼 묶음

첫 블로그 버전에서 최소한 필요한 것은 아래 4개다.

1. 글쓰기 가이드
2. 발행 체크리스트
3. 운영/복구 가이드
4. 디자인 읽기 규칙

## 업데이트 규칙

- 글쓰기 기능이 바뀌면 작성자 매뉴얼을 같이 갱신한다.
- 저장 경로나 발행 계약이 바뀌면 운영 매뉴얼을 같이 갱신한다.
- 읽기 UX 가 크게 바뀌면 디자인 매뉴얼을 같이 갱신한다.
- 릴리스 후 실제 사용 흐름이 달라졌다면 히스토리에 먼저 남기고 매뉴얼을 맞춘다.

## 지금 단계의 권장 실행 순서

1. `v0.6.0` 블로그 기능 정의 확정
2. `Writing Studio` 와 공개 아카이브 구현
3. 그 다음 작성자 매뉴얼 초안 작성
4. 실제 사용 후 운영/복구 가이드 보강
