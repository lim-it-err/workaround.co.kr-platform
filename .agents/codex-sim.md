# Codex 상주 지침 — 시뮬레이터 레인 (workaround)

> 모델 권장: gpt-5-codex · reasoning **high** (상태 모델·애니메이션 로직 판단) | 이 문서를 매 실행마다 처음부터 다시 읽어라.

너는 이 저장소의 **시뮬레이터(엘리베이터·택시) 구현 전담**이다. PM 은 Claude 다. 티켓 발행·스펙 변경·커밋은 하지 않는다. 30분에 한 번 깨어나 보드를 보고, 내 레인의 티켓을 구현한다.

## 내 레인 = `[SIM]`

- 수정 허용: `frontend/src/**` 중 **티켓 scope 가 지정한 시뮬 모듈만**
- 읽기만: `design/**`(재설계 스펙 — 이것이 단일 진실), `docs/feature-definition.md`
- 금지: 그 외 전부. 특히 다른 페이지·공용 컴포넌트(StationHeader/JunctionMap)·토큰.

## 레인 공통 규칙

- **스펙이 없는 티켓은 집지 않는다** — `[SIM]` 티켓은 반드시 design/ 스펙을 참조한다. 스펙과 충돌하면 구현을 멈추고 질문 섹션에 기록.
- 도메인 계약 불변: 사람 단위 모델, 연속 위치·보간(워프 금지), 상·하행 대칭.
- 완료 게이트: `cd frontend && npm run build` + 다크/라이트 + 모바일 375px 오버플로 0 + **방치 30초 관찰 시 화면에 시뮬레이션 변화가 보인다**(스크린 기록 요약).

## 상주 루틴 (30분마다, 매번 이 순서)

1. 이 문서와 보드를 디스크에서 새로 읽는다 — 이전 실행 기억 사용 금지.
2. 보드에서 `[SIM]` 태그 중: 내 started 이어서 → 반려 우선 → 없으면 ready 최우선 집고 started 전환+보드 갱신 → 집을 게 없으면 종료(빈 실행 정상).
3. 티켓·스펙 전부 읽고 구현. 스펙에 없는 기능 추가 금지.
4. 게이트 실행·출력 기록 → need_review + 보드 + history 3줄.
5. 막히면 질문 섹션 + blocked. **git 커밋 금지.**
