# 서울지하철 UI/UX 시스템

작성일: 2026-06-15  
작성자: designer

## 문서 목적

이 문서는 서울지하철의 실제 길찾기 감각, 색 체계, 사인 구조, 플랫폼 경험을 현재 웹사이트의 UI/UX 시스템으로 번역한 기준선이다.

이번 기준선은 아래 목적을 가진다.

1. 서울지하철 콘셉트를 장식이 아니라 정보 구조로 사용한다.
2. 메인 페이지를 환승 허브처럼 설계한다.
3. 기능 페이지를 실제 승강장처럼 분리한다.
4. 모바일과 데스크톱 모두에서 길찾기 UX가 선명하게 보이게 한다.

## 조사에서 가져온 핵심 레퍼런스

### 1. 시스템은 매우 크지만 사용자는 길을 잃지 않게 설계되어 있다

수도권 전철은 매우 큰 네트워크이고, 다수의 운영 주체와 노선을 하나의 체계처럼 읽히게 만든다. 이 점은 현재 제품에도 중요하다. 기능이 늘어나더라도 메인 허브에서 일관된 규칙으로 분기되어야 한다.

디자인 번역:

- 메인 허브는 기능이 늘어도 같은 구조로 확장돼야 한다.
- 각 기능 페이지는 개별 노선처럼 독립적이되, 전체 포털 안에서는 같은 네트워크 일부로 읽혀야 한다.

### 2. 서울지하철은 색과 번호로 빠르게 노선을 인식시킨다

지하철은 노선 색과 노선 번호를 함께 써서 즉시 식별되도록 한다. 특히 Line 2는 순환선이라는 구조 자체가 정체성이다.

디자인 번역:

- 모든 핵심 기능은 `노선 번호 + 노선 색 + 기능명` 3요소를 함께 가진다.
- 메인 허브에서는 카드보다 "노선 입구"처럼 보여야 한다.
- 원형 이동 구조나 순환 개념이 필요한 화면은 2호선의 링 구조를 참고할 수 있다.

### 3. 사인은 말보다 방향을 먼저 준다

서울지하철 역은 출구 번호, `Way Out`, 환승 색띠, 화살표, 플랫폼 색 라인 같은 규칙으로 빠르게 방향을 준다.

디자인 번역:

- 모든 화면은 제목보다 먼저 "지금 어디인지"와 "어디로 갈 수 있는지"를 보여준다.
- 버튼은 단순 CTA 가 아니라 이동 표식처럼 보여야 한다.
- 뒤로 가기 대신 `Main page 환승 홀로` 같은 명시적 복귀 동선을 둔다.

### 4. 플랫폼 바닥 정보는 행동을 정렬한다

서울지하철 플랫폼에는 노란 안전선, 점자/유도 블록, 3갈래 승하차 화살표 같은 바닥 규칙이 있다. 이것은 예쁜 장식이 아니라 군중의 행동을 정렬하는 인터페이스다.

디자인 번역:

- 복수 행동이 있는 UI 에서는 순서를 바닥 마킹처럼 드러낸다.
- 예: `보기 -> 선택 -> 진입`, `검토 -> 인증 -> 실행`.
- Work Manager 에서는 preview, gate locked, live action 상태를 바닥 마킹 수준으로 분명히 나눈다.

### 5. 다국어와 실시간 정보가 함께 간다

서울지하철은 한글 중심이지만 영어 등 보조 표기를 유지하고, LCD 기반 실시간 도착 정보도 강하다.

디자인 번역:

- 기능명은 영어를 유지할 수 있다.
- 설명, 상태 문장, 안내 문구는 한국어 중심으로 정리한다.
- 모든 운영 화면에는 정적인 장식보다 실시간 상태 요약이 우선한다.

## 현재 제품에 적용하는 핵심 구조

### Splash

- 역할: 도착 연출, 브랜드 몰입, 도시적 톤 제시
- 서울지하철 번역 요소:
  - 플랩 보드
  - 역명형 타이틀
  - 시계
  - 운행 상태 보조 문구
- 가드레일:
  - 모바일에서는 플랩 보드 높이를 줄인다.
  - 검은 면적이 너무 크면 안 된다.
  - 10초 뒤 메인 허브로 부드럽게 전환한다.

### Main Page

- 역할: 중앙 환승 홀
- 서울지하철 번역 요소:
  - 노선별 입구
  - 환승 안내
  - 현재 운행 상태 요약
  - 방향 표식형 CTA
- 금지:
  - 실제 Elevator 전체 보드 직접 노출
  - 실제 Work Manager 전체 보드 직접 노출
  - 긴 최근 티켓 목록 직접 노출
  - 상세 런타임 규칙 표 직접 노출

### Feature Page

- 역할: 실제 승강장
- 서울지하철 번역 요소:
  - 노선 색
  - 현재 역/페이지명
  - 다음 이동 가능 경로
  - 실제 조작 화면

## 노선 체계 제안

현재 사이트는 아래 노선 체계로 읽히게 한다.

### Line E

- 이름: `Elevator Station`
- 역할: 엘리베이터 시뮬레이터
- 추천 색: 하늘색 또는 4호선 계열 청색
- 이유: 움직임, 방향, 수직 이동 감각이 잘 맞는다.

### Line W

- 이름: `Work Manager`
- 역할: 운영/티켓/명령 보드
- 추천 색: 2호선 초록 또는 5호선 보라
- 권장안: 2호선 초록
- 이유: 메인 운영 레인, 중심 순환, 가장 자주 드나드는 축으로 읽히기 좋다.

### Line R

- 이름: `Runtime Board`
- 역할: 노드, 오프로드, degraded 상태 확인
- 추천 색: 1호선 진한 남색
- 이유: 인프라와 시스템 신뢰감이 강하게 느껴진다.

### Future Lines

- `Arcade`
- `Public Site`
- `Docs / Control`

이 확장도 모두 같은 규칙을 따른다.

## 색 시스템

### 기본 원칙

- 배경은 실제 역 내부처럼 어두운 중성 톤을 유지한다.
- 강조는 노선 색으로만 준다.
- 한 화면 안에서 포인트 색을 2개 이상 경쟁시키지 않는다.

### 추천 토큰

- Base Metal: `#111721`
- Panel Surface: `#1A212D`
- Rail Grid: `rgba(255,255,255,0.06)`
- Text Primary: `#F3F6FB`
- Text Secondary: `#AEB8C8`
- Safety Yellow: `#F3C544`
- Exit Green: `#14A44D`

### 노선 색 권장

- Line 1 / Runtime: 진한 남색
- Line 2 / Work Manager: 초록
- Line 3 / Archive or Route: 주황
- Line 4 / Elevator: 하늘색
- Line 5 / Support or Review: 보라
- Line 9 / Premium / Priority: 금색

## 타이포그래피 제안

### 기본 방향

- 제목은 역명판처럼 크고 굵게
- 본문은 읽기 빠른 고딕
- 숫자, 시간, 티켓 번호는 폭이 안정적인 서체 사용

### 추천 구조

- 제목: 서울시 계열 서체가 가능하면 `Seoul Namsan` 또는 유사한 단단한 산세리프
- 본문: `Pretendard`, `Noto Sans KR`, `Segoe UI` 계열
- 숫자/운행 정보: tabular figures 지원 서체

### 규칙

- 메인 허브 제목은 크고 짧게
- 버튼 문구는 짧고 결과 중심
- 보조 설명은 한글 중심
- 영어는 기능명, 시스템명, 코드명에 한정

## 컴포넌트 시스템

### 1. 노선 카드

- 메인 허브 전용 컴포넌트
- 구성:
  - 노선 번호 배지
  - 기능명
  - 한 줄 설명
  - 현재 상태
  - 진입 버튼

버튼 문구 예시:

- `플랫폼 입장`
- `운영 보드 열기`
- `런타임 보기`

### 2. 환승 배지

- 현재 위치와 연결 가능한 페이지를 보여주는 컴포넌트
- 예:
  - `현재 위치: Main Junction`
  - `환승 가능: Line E, Line W`

### 3. 출구 표식 버튼

- `Way Out` 표식처럼 설계하는 버튼
- 예:
  - `Exit 1 Main page`
  - `Exit 2 Runtime`

이건 실제로 페이지 이동을 직관적으로 만든다.

### 4. 플랫폼 헤더

- 기능 페이지 상단 고정 헤더
- 구성:
  - 노선색 띠
  - 페이지명
  - 상태 배지
  - 메인 허브 복귀

### 5. 도착 정보 바

- 페이지 하단 또는 상단 보조 영역
- 예:
  - `ion2 정상`
  - `rtx5070 대기`
  - `bridge protected`

장식보다 실시간 상태 요약에 집중한다.

## Work Manager 번역 규칙

서울지하철 감각을 가장 잘 살릴 수 있는 곳은 Work Manager 다.

### 구조

- 컬럼 = 운행 상태 구간
- 카드 = 열차 또는 작업 단위
- 상세 패널 = 역무실 상세 판독
- command gate = 승인된 관제 조작

### 시각 규칙

- `preview`: 점선, 약한 노랑, 시험 표식
- `locked`: 빨강이 아닌 주황/황색 경고
- `live`: 선명한 초록 또는 파랑

### 동선 규칙

- 드래그 가능한 구간은 실제 플랫폼 동선처럼 명확해야 한다.
- 시스템 소유 구간은 사용자가 끌 수 없는 레일처럼 보여야 한다.

## Elevator 번역 규칙

### 구조

- 전체 보드는 노선도보다 관제실 패널에 가깝다.
- 다만 상단 요약은 역 전광판처럼 빠르게 읽혀야 한다.

### 권장 분리

1. 상단: 현재 대기 인원, 이동 중 car 수, 병목 요약
2. 중단: 23층 x 4대 보드
3. 하단: 수동 승객 추가 / 시뮬레이터 조작

### 이유

서울지하철은 처음부터 모든 디테일을 던지지 않는다. 현재 위치, 방향, 환승, 도착 정보를 먼저 준다. Elevator 도 같은 흐름이 좋다.

## 모바일 UX 규칙

- 메인 허브는 세로 카드 스택
- 카드 하나가 화면폭 대부분을 차지
- 페이지 진입 버튼은 엄지로 닿기 쉽게 하단 정렬
- 기능 페이지에서는 상단 헤더를 더 단순하게
- 복귀 버튼은 항상 노출

모바일에서 중요한 것은 "작아진 데스크톱"이 아니라 "빠른 환승"이다.

## 접근성 규칙

- 노선색만으로 상태를 구분하지 않는다.
- 색 + 텍스트 + 아이콘을 함께 쓴다.
- 노란 유도선 개념을 실제 UI 포커스 라인이나 현재 단계 표시로 번역한다.
- 터치 타깃은 충분히 크게 둔다.
- 한글 본문은 대비를 높이고, 영문 보조 표기는 더 작게 둔다.

## 바로 구현해도 되는 추천 방향

### 즉시 적용

1. 메인 페이지에서 실제 기능 패널 제거
2. 노선 카드형 허브 도입
3. 기능 페이지별 플랫폼 헤더 통일
4. `Main page 환승 홀로` 복귀 버튼 통일
5. Work Manager preview/live 상태 시각 분리

### 후속 적용

1. 출구 번호형 빠른 내비게이션
2. 플랫폼 바닥 마킹형 단계 UI
3. 노선도형 전역 라우팅 미니맵
