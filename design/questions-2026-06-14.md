# 사용자 질문 정리

작성일: 2026-06-14  
작성자: designer

## 브랜드와 톤

1. 첫 화면에서 지금의 "지하철/관제실" 콘셉트를 얼마나 강하게 유지하고 싶나요?
2. 사이트가 주는 첫인상은 어떤 쪽에 더 가까워야 하나요?
   - 실험적이고 인상적인 포털
   - 차분하고 정돈된 운영 대시보드
   - 둘의 중간
3. 한국어 중심으로 갈지, 시스템 명칭만 영어로 남길지 기준을 정하고 싶습니다.

## 정보 우선순위

4. 메인 화면에서 사용자가 가장 먼저 해야 하는 행동은 무엇인가요?
5. 현재 기준으로 더 중요한 축은 어느 쪽인가요?
   - Elevator 시뮬레이터
   - Work Manager
   - 서비스 포털 개요
6. Work Manager 는 메인 화면 안에 강하게 노출할지, 별도 탭/섹션처럼 분리할지 선호가 있나요?

## 사용자 유형

7. 이 사이트의 주 사용자 유형은 누구인가요?
   - 본인만 쓰는 개인 운영 포털
   - 외부에게도 보여 줄 포트폴리오형 사이트
   - 둘 다
8. 외부 방문자가 처음 들어왔을 때 봐야 하는 정보와, 본인이 운영할 때 필요한 정보가 같은 화면에 있어야 하나요?

## 시각 취향

9. 더 좋아하는 방향은 어느 쪽인가요?
   - 묵직하고 어두운 관제실 톤
   - 밝고 선명한 정보 패널 톤
   - 어둡지만 밀도를 낮춘 절충형
10. 현재 화면에서 꼭 유지하고 싶은 요소 3개와, 과하다고 느끼는 요소 3개를 알려주세요.

## 인터랙션

11. 스플래시는 계속 10초 자동 전환이 좋나요, 아니면 더 짧거나 건너뛸 수 있어야 하나요?
12. preview 전용 액션은 지금처럼 화면에서 바로 눌러보는 방식이 좋은가요, 아니면 더 안전하게 분리되어야 하나요?

## 운영 제약

13. UI 구현에서 가장 먼저 개선하고 싶은 페이지는 어디인가요?
14. 지금 단계에서 디자인 문서는 Markdown 중심으로 갈지, Figma 시안도 병행할지 결정이 필요합니다.
15. 오케스트레이터가 바로 구현해도 되는 수준의 거친 규칙이 우선인가요, 아니면 더 정교한 화면 시안이 먼저인가요?

## 현재 우려

- 현재 스플래시는 개성은 강하지만 모바일에서 빈 화면처럼 느껴질 가능성이 있다.
- 메인 화면은 기능이 많아질수록 더 예뻐지기보다 더 복잡해질 위험이 있다.
- 지금 시점에 디자인 기준선을 먼저 고정하지 않으면 오케스트레이터 구현이 다시 사용자 요청 중심의 임시 조정으로 흐를 수 있다.
