# 2026-06-21 UI-v0.5.0 프로토타입 handoff

## 요약

- `v0.4.0` 실사용 포털은 유지했다.
- `v0.5.0` 디자인 프로토타입은 `/test/v0-5-0` 아래로 분리했다.
- 오케스트레이터는 이 레일을 보고 구현 티켓을 슬라이스하면 된다.

## 확인 경로

실사용:

- `http://localhost:7000/`

기존 검수:

- `http://localhost:7000/test`
- `http://localhost:7000/test?view=junction`
- `http://localhost:7000/test?view=elevator`
- `http://localhost:7000/test?view=work`
- `http://localhost:7000/test?view=runtime`

신규 프로토타입:

- `http://localhost:7000/test/v0-5-0/junction`
- `http://localhost:7000/test/v0-5-0/taxi`
- `http://localhost:7000/test/v0-5-0/ops`
- `http://localhost:7000/test/v0-5-0/signals`

## 오케스트레이터가 봐야 하는 것

1. `junction`
   - 메인이 여전히 라우터로만 읽히는가
   - 구현 슬라이스가 카드 단위로 분리되는가

2. `taxi`
   - 택시 시뮬레이터가 표가 아니라 구역/요청/차량/리워드 흐름으로 읽히는가

3. `ops`
   - worker 가시화와 우선순위 반응이 기존 Work Manager 와 분리되어 보이는가

4. `signals`
   - 실사용 `/`, 기존 `/test`, 신규 `/test/v0-5-0` 의 경계가 명확한가

## 구현 티켓으로 옮기기 좋은 경계

1. `Hub Shell v0.5.0`
2. `Taxi District Lab`
3. `Crew Board`
4. `Signal Room`
5. `Mobile restack for v0.5.0`

## acceptance 힌트

- `/` 는 live 포털로 유지한다.
- `/test` 는 `v0.4.0` 검수 전용으로 유지한다.
- `v0.5.0` 가상 화면은 `/test/v0-5-0` 아래에서만 개발/검수한다.
- 모바일에서 허브 카드와 택시 구역 메쉬가 세로 리듬으로 다시 쌓여야 한다.

## 디자이너 메모

- 이번 프로토타입은 완성 구현이 아니라 오케스트레이터가 티켓을 나누기 쉬운 구조를 먼저 만든 것이다.
- 다음 단계에서는 각 승강장을 실제 데이터 계약과 연결하거나, 필요한 경우 더 세밀한 시각 시안을 추가한다.
