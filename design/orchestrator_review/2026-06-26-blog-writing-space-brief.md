# 2026-06-26 블로그 글쓰기 공간 디자이너 브리프

## 배경

사용자의 실제 목표는 시뮬레이터 자체보다 "블로그 형식으로 글을 쓰고 쌓는 공간"에 더 가깝다. 오케스트레이터는 이를 `v0.6.0` 블로그 라인으로 분리해 잡았다.

## 디자이너가 풀어야 하는 문제

1. 포털 안에서 `Blog District` 가 어떤 승강장으로 읽혀야 하는가
2. 공개 글 목록이 서울지하철식 분위기와 긴 글 읽기 경험 사이에서 어떻게 균형을 잡아야 하는가
3. `Writing Studio` 는 운영 패널이 아니라 실제 글쓰기 공간처럼 느껴져야 하는데, 그 집중감을 어떻게 만들 것인가
4. 모바일에서 긴 글 읽기와 간단한 초안 편집이 각각 어떻게 재배치되어야 하는가

## 요청 산출물

1. 메인 허브 내 `Blog District` 진입 카드 시안
2. 공개 아카이브 목록 시안
3. 글 상세 읽기 typography 규칙
4. `Writing Studio` 편집/미리보기 레이아웃
5. 모바일 읽기/모바일 작성 우선순위 문서
6. draft / published / archived 상태 badge 규칙

## 반드시 지켜야 할 기준

- `/` 실사용 포털을 더미가 덮어쓰면 안 된다.
- 블로그 라인은 시뮬레이터와 다른 읽기 리듬을 가져야 한다.
- 글 상세는 콘셉트보다 읽기성을 우선한다.
- `Writing Studio` 는 한 화면에 모든 운영 정보를 때려 넣지 말고, 작성 집중과 발행 상태를 분리해 보여줘야 한다.
- 모바일은 축소판이 아니라 재배치다.

## 구현 티켓과의 연결

- `TKT-050`: 블로그 허브와 공개 아카이브
- `TKT-051`: 글쓰기 스튜디오와 초안/미리보기/발행 흐름
- `TKT-052`: Markdown 저장 계약과 렌더링 파이프라인

## 오케스트레이터 메모

- 블로그는 단일 작성자, Markdown 우선, 초안/발행 분리 구조를 기본안으로 둔다.
- 댓글, 좋아요, 구독 같은 커뮤니티 기능은 이번 라인에 넣지 않는다.
- 공개 읽기 화면과 작성자 Studio 를 같은 패널 미학으로 처리하면 다시 흔들릴 수 있으니, 두 리듬을 의도적으로 분리해 달라.
