한글 고정폭 함정과 각 안의 대응

고정폭 글꼴에서 영문·박스 문자는 1칸, 한글은 2칸(또는 글꼴에 따라 1.6~2칸)이다. 글자 수로 줄을 맞추는 텍스트 박스는 한글이 섞이는 순간 오른쪽 │가 어긋난다. 글꼴이 달라지면(맥·윈도·모바일) 어긋나는 정도도 달라져서, 공백을 보정해도 한 환경에서만 맞는다.

나쁜 예 — 텍스트로 그린 박스 (이 화면 글꼴에서 오른쪽이 어긋난다)

┌────────────┐
│ 환승 홀    │
│ Advisor    │
│ 자취 밥상  │
└────────────┘

쓰는 예 — CSS 테두리 + 모서리 글자

┌┐└┘┤ 환승 홀 ├Advisor · 자취 밥상 — 글자 수와 상관없이 테두리가 닫힌다.
  • A — 테두리는 CSS border, 모서리 ┌ ┐ └ ┘와 제목 둘레 ┤ ├만 글자(전부 aria-hidden). 구분선·장식 행은 ─를 넉넉히 깔고 overflow:hidden으로 자른다(폭 무관). 노선도의 ├─ └─는 줄 왼쪽 끝에만 있어 한글 폭과 상관없다. 오른쪽 정렬이 필요한 값은 글자 수 맞춤이 아니라 flex 로 민다.
  • B — 박스 문자를 거의 쓰지 않는다. 노선색 머리띠·둥근 배지·CSS 선으로 안내판을 만들어 함정 자체가 없다. 대신 "터미널" 느낌은 가장 약하다.
  • C — A와 같은 원리인데 테두리를 3px double로 바꿔 이중선 느낌을 낸다. 스캔라인·비네트는 fixed 오버레이(pointer-events 없음). 자취 밥상은 호박색 변형.
  • 공통 — 한글이 들어가는 줄에는 열 맞춤용 공백을 쓰지 않는다. 표처럼 보이는 곳은 flex/grid 로 만든다. 실제 구현에서도 이 규칙을 지키면 글꼴 폴백(맥/윈도/안드로이드)에 안전하다.

[반박]

"고정폭 글꼴 + 한글"은 폭이 정확히 2칸이 되는 글꼴(D2Coding 등)이 있어야 터미널다운 격자가 나온다. 시스템 스택만 쓰면 기기마다 격자가 다르다. 그래서 어느 안도 "글자 격자"를 약속하지 않고 CSS 격자를 쓴다. 진짜 격자가 목표라면 웹폰트(외부 의존·용량)를 따로 결정해야 한다.
