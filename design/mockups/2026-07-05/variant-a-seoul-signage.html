스플릿 플랩 보드를 CSS 트랜스폼으로 다시 만들기

페이드 인은 플랩이 아니다. 위 반쪽이 떨어지고 아래 반쪽이 받아내는 두 장의 판, 그 사이의 시차가 기계식 행선판의 전부라는 걸 다시 만들면서 알았다.

#css#애니메이션#프런트엔드 공개

처음 구현한 스플래시 보드는 타일이 한 번에 회전하며 나타나는 등장 연출이었다. 멀리서 보면 그럴듯했지만, 어느 순간부터 눈에 걸리기 시작했다. 실제 행선판은 글자가 「나타나는」 것이 아니라 「넘어가는」 것이기 때문이다.

반쪽 플랩의 구조

한 글자 셀은 네 장의 반쪽 판으로 구성된다. 고정된 위·아래 판 두 장, 그리고 회전하는 플랩 두 장. 위 플랩은 현재 글자를 안고 아래로 떨어지고, 아래 플랩은 다음 글자를 안고 올라와 정착한다.

  • 위 고정판 — 다음 글자의 윗부분을 미리 보여준다
  • 아래 고정판 — 현재 글자의 아랫부분을 유지한다
  • 위 플랩 — 현재 글자를 안고 rotateX(0 → -90deg) 로 낙하
  • 아래 플랩 — 다음 글자를 안고 rotateX(90deg → 0) 으로 착지
.flap.run .top    { animation: drop 90ms cubic-bezier(.52,0,.86,.4) forwards; }
.flap.run .bottom { animation: land 120ms cubic-bezier(.15,.66,.24,1) forwards;
                    animation-delay: 38ms; }

@keyframes land {
  0%   { transform: rotateX(90deg); }
  55%  { transform: rotateX(0); }
  72%  { transform: rotateX(10.5deg); }  /* 기계식 반동 */
  100% { transform: rotateX(0); }
}

애니메이션의 품질은 곡선이 아니라 멈추는 순간에서 결정된다. 판이 「탁」 하고 정착하는 반동 한 번이 전체 인상을 바꾼다.

시차와 리듬

모든 셀이 같은 박자로 넘어가면 오히려 디지털처럼 보인다. 열마다 col * 55ms 의 출발 시차를 주고, 셀마다 넘기는 중간 글자 수를 3~9장 사이에서 다르게 잡았다. 목적 글자에 먼저 도착한 셀이 멈춰 있는 동안 옆 셀이 계속 넘어가는 풍경이 만들어진다.

남은 일

모션 감소 설정을 켠 사용자에게는 회전 없이 결과만 보여주고, 저사양 기기에서 플랩 수를 줄이는 옵션을 검토 중이다. 다음 글에서는 이 보드를 실제 스플래시 전환과 연결한 기록을 남긴다.
