# 택시 구역 재설계 스펙 (TKT-074 지도부 + TKT-082 버그 · [SIM] 구현용)

근거: PO "최소한 지도는 있어야" + "수동 호출해도 택시가 놀고 큐가 안 줄어" / R1 승인. 이 문서만 보고 구현 가능해야 한다.

## 0. 존재 이유

**배차가 눈에 보이는 도시 보드.** 지도는 장식이 아니라 관측 장치다 — 유휴 차량이 대기 요청을 안 집으면 지도에서 즉시 보인다(TKT-082 버그의 상시 감시 장치).

## 1. 순서 — 버그 먼저 (TKT-082)

지도를 그리기 전에 디스패치를 고친다. 진단 절차:
1. 수동 호출 → activeRequests 에 들어가는 큐와, 배차 매칭이 읽는 큐가 **같은 배열인지** 확인 (분리돼 있으면 그게 원인).
2. 차량 상태 전이 로그: 경로 완료 시 `idle` 복귀가 실제로 일어나는지. 안 일어나면 완료 판정 조건(도착 오차 등) 확인.
3. 매칭 트리거: "요청 발생 시"와 "차량 idle 전이 시" **양쪽 모두**에서 매칭을 시도하도록 수정 (한쪽만 있으면 반대 케이스가 굶는다).
- 회귀 테스트: `유휴 차량 1 + 대기 요청 1 → 1틱 내 배차` / `전 차량 busy 중 요청 적재 → 첫 idle 전이 시 즉시 배차` 두 케이스를 순수 함수 레벨로.

## 2. 지도 (신규 `TaxiDistrictMap.vue` — 3×3 그리드)

- **타일 = 구역 9개** (기존 taxiDistricts 데이터). 타일 배경 = 수요 강도 3단계 톤(`--panel` → `color-mix(--line-t 10%)` → `color-mix(--line-t 22%)`). 타일 안: 구역명(짧게) + 대기 요청 수(`.num`, 0이면 표시 안 함).
- **차량 마커**: 원형 배지(차량 ID 마지막 글자), 상태색 — idle `--text-2` / 이동 중 `--line-t` / 승객 탑승 `--exit`. 위치는 구역 타일 안 상대 좌표(코어의 구역+진행률로 계산). 이동은 타일 간 위치 전환(300ms transition, reduced-motion 시 즉시).
- **요청 마커**: 대기 요청 = 타일 모서리 깜빡이는 점(`--safety`), 배차되면 점이 사라지고 해당 차량 마커에 목적지 구역으로 가는 얇은 라인(1.5px, `--line-t`) 표시.
- **상호작용**: 타일 클릭 = 그 구역에 수동 호출 1건 (기존 수동 호출 폼 대체). 차량 마커 클릭 = 우측 패널에 그 차량 상세.
