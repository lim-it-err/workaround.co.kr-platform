# Blog District UI 시스템

작성일: 2026-06-26  
작성자: designer

## 목적

이 문서는 `Blog District` 와 `Writing Studio` 를 위한 핵심 디자이너 산출물 6개를 한 번에 고정하는 기준선이다.

대상 티켓:

- `TKT-050`: 블로그 허브와 공개 아카이브/상세
- `TKT-051`: 글쓰기 스튜디오와 초안/미리보기/발행
- `TKT-052`: Markdown 저장 계약과 렌더링

## 전제

- 블로그 라인은 시뮬레이터와 다른 읽기 리듬을 가져야 한다.
- 공개 읽기 화면은 콘셉트보다 읽기성이 우선이다.
- `Writing Studio` 는 운영 패널이 아니라 작성 집중 공간처럼 느껴져야 한다.
- 모바일은 축소판이 아니라 재배치다.
- 실사용 `/` 를 더미가 덮어쓰면 안 된다.

## 1. Blog District 진입 카드 시안

### 역할

- 메인 허브 또는 후속 허브에서 블로그 라인으로 들어가는 승강장
- "여기는 읽기/쓰기 공간" 이라는 성격을 다른 시뮬레이터와 즉시 구분

### 카드 구조

- 상단 라벨: `Line B / Blog District`
- 메인 제목: `읽고 쓰는 승강장`
- 보조 설명: "공개 아카이브, 글 상세 읽기, Writing Studio 로 이어지는 개인 글 공간"
- 요약 지표:
  - 최근 발행 글 수
  - 최근 발행일
  - draft 수
- CTA:
  - `아카이브 들어가기`
  - 필요 시 보조 CTA `Studio 열기`

### 시각 방향

- 지하철 허브의 언어는 유지하되, 금속성/운영실 톤을 약하게 줄인다.
- 더 조용한 종이/잉크/역사 안내판 감각이 어울린다.
- 강조 색은 신규 라인임을 보여 주는 별도 `Line B` 계열을 둔다.
  - 권장: 남청, 딥 버건디, 또는 저채도 잉크 블루

### 금지

- Work Manager 처럼 배지와 상태를 과도하게 덕지덕지 붙이지 않는다.
- 택시/엘리베이터 카드처럼 "조작 중" 인상을 주지 않는다.

## 2. 공개 아카이브 목록 시안

### 역할

- 독자가 공개 글 목록을 훑고 원하는 글로 들어가는 페이지

### 정보 우선순위

1. 제목
2. 짧은 요약
3. 발행일
4. 태그
5. 상태 배지

### 레이아웃 기본안

- 상단:
  - 페이지 제목 `Public Archive`
  - 짧은 소개 문장
  - 아카이브 복귀 / 허브 복귀 동선
- 본문:
  - 세로 목록형 카드
  - 너무 촘촘한 masonry 보다 읽기 흐름이 일정한 단열 리스트 우선
- 각 카드:
  - 제목
  - 2~3줄 요약
  - 태그 줄
  - 발행일
  - `글 읽기` CTA

### 읽기 리듬

- 목록에서 한 카드가 너무 시각적으로 시끄러우면 안 된다.
- 스크롤 리듬은 뉴스 피드보다 "기록 보관함" 에 가깝게 차분해야 한다.
- 카드 간 간격은 넉넉하게 두고, hover/active 효과는 얕게 준다.

## 3. 글 상세 읽기 typography 규칙

### 우선 원칙

- 글 상세는 서울지하철 콘셉트보다 읽기성이 우선이다.
- 본문에서 line badge, route motif, 과한 gradient 를 전면에 세우지 않는다.

### 본문 폭

- 데스크톱 읽기 폭은 지나치게 넓지 않게 제한한다.
- 권장:
  - 본문 최대 폭 `680px` ~ `760px`
  - 메타 정보와 본문은 한 덩어리 column 으로 읽히게 유지

### 타입 계층

- 제목:
  - 강한 대비
  - 2줄까지 안정적으로 버티는 크기
- 요약:
  - 제목 바로 아래, 본문보다 약간 큰 크기
  - 한 문단 설명 느낌
- 본문:
  - line-height 충분히 크게
  - 문단 간 간격 여유
  - 리스트, blockquote, code block 은 본문과 확실히 구분

### Markdown 요소 규칙

- `h1` 은 페이지 제목 전용으로 쓰고, 본문 내부는 사실상 `h2` 부터 시작하는 느낌으로 다루는 편이 안정적이다.
- code block 은 운영 패널 느낌이 아니라 문서 삽입물처럼 차분해야 한다.
- blockquote 는 노선 정보판 같은 장식보다, 인용문 자체의 가독성이 우선이다.

### 메타 정보

- 제목 위 또는 아래에 아래 항목을 짧게 둔다.
  - 작성일
  - 수정일
  - 발행일
  - 태그
- 메타 줄은 본문보다 한 단계 낮은 톤이어야 한다.

## 4. Writing Studio 편집/미리보기 레이아웃

### 핵심 원칙

- 한 화면에 모든 운영 정보를 때려 넣지 않는다.
- 작성 집중 레이어와 발행 상태 레이어를 분리한다.

### 기본 구조

1. 상단 Studio 헤더
   - 현재 문서 제목
   - 저장 상태
   - 현재 상태 badge
   - `draft 저장`, `미리보기`, `발행`, `보관` 액션

2. 좌측 편집 레이어
   - 제목
   - slug
   - 요약
   - Markdown 본문 편집기

3. 우측 미리보기 레이어
   - 실제 공개 글처럼 읽히는 preview
   - typography 규칙은 공개 상세와 최대한 일치

4. 보조 상태 레이어
   - 마지막 저장 시각
   - 공개 여부
   - 간단한 태그/메모

### 데스크톱 리듬

- 기본은 `편집 60 / 미리보기 40` 또는 `편집 55 / 미리보기 45`
- 미리보기는 운영 패널처럼 좁고 답답하게 만들지 않는다.
- 편집기와 미리보기 사이에는 충분한 구획선이 필요하다.

### UX 포인트

- 저장은 자주 보이되 위협적으로 보이지 않게 한다.
- `published` 전환은 가장 강한 액션이지만 남용되지 않게 별도 강조만 준다.
- `archived` 는 파괴적 액션처럼 보여도 삭제와 혼동되면 안 된다.

## 5. 모바일 읽기 / 모바일 작성 우선순위

### 모바일 읽기 우선순위

1. 제목
2. 요약
3. 메타 정보
4. 본문
5. 이전/다음 또는 아카이브 복귀

원칙:

- 모바일 읽기 화면은 "간판 -> 본문" 흐름이 아니라 "제목 -> 내용" 흐름이어야 한다.
- 허브 감각은 상단 최소한의 breadcrumb 수준으로만 남긴다.

### 모바일 작성 우선순위

1. 제목
2. 요약
3. 본문 편집
4. 저장 상태
5. 미리보기 전환
6. 발행/보관 액션

원칙:

- 모바일에서 편집기와 미리보기를 동시에 좌우 분할하지 않는다.
- `편집` 과 `미리보기` 를 탭 전환 또는 세그먼트 전환으로 나눈다.
- 발행 상태 액션은 하단 sticky bar 또는 상단 고정 영역 중 하나로 일관되게 둔다.

## 6. draft / published / archived 상태 badge 규칙

### 목적

- 사용자가 지금 이 글이 어떤 공개 상태인지 즉시 이해하게 한다.
- 상태 badge 는 예쁘기보다 오해가 없어야 한다.

### 규칙

- `draft`
  - 의미: 아직 공개되지 않음
  - 톤: 중립 + 작성 중
  - 권장 색: 회청/슬레이트
- `published`
  - 의미: 공개 중
  - 톤: 가장 명확한 활성 상태
  - 권장 색: 짙은 초록 또는 안정적인 블루그린
- `archived`
  - 의미: 삭제가 아니라 보관, 기본 공개 흐름에서 제외
  - 톤: 비활성 + 보존
  - 권장 색: 갈회/브론즈 계열

### 금지

- `archived` 를 위험/삭제 색과 동일하게 두지 않는다.
- `draft` 와 `archived` 를 둘 다 회색 하나로 퉁치지 않는다.
- badge 내부 문구가 길어져 본문 리듬을 깨지 않게 한다.
