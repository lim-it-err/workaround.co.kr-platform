# 현재 UI/UX 진단

작성일: 2026-06-14  
작성자: designer

## 확인 범위

- `frontend/src/App.vue`
- `frontend/src/styles.css`
- 로컬 프리뷰 `http://127.0.0.1:7000`
- 스플래시 스크린샷 기준 시각 점검
- `frontend/src/App.vue` 기준 10초 후 메인 전환 구조 확인
- 메인 화면 아래 스크롤 영역(`Recent tickets`, `Runtime targets`, `Route map`, `Work Manager`) 검수 필요 범위 확인

## 총평

현재 사이트는 콘셉트의 힘은 강하다. 지하철 플랩, 관제실 톤, 어두운 금속성 표면은 첫인상에 확실한 개성을 준다.

다만 실제 사용 단계로 넘어가면 다음 문제가 크다.

1. 콘셉트가 강한 대신 정보 우선순위가 흐려진다.
2. 한 페이지 안에 너무 많은 역할이 동등한 비중으로 놓여 있다.
3. 모바일에서 시각 밀도보다 빈 여백이 먼저 느껴진다.
4. Work Manager 와 시뮬레이터가 모두 중요해 보이지만, 무엇부터 봐야 하는지 안내가 약하다.

스플래시 기준 문제만으로는 부족하다. 이 앱은 10초 뒤 메인 화면으로 자동 전환되고, 실제 운영 경험의 핵심도 스크롤 아래 영역에 있기 때문에 아래 두 장면을 반드시 따로 검수해야 한다.

1. 10초 후 첫 메인 화면
2. 메인 화면에서 아래로 스크롤한 뒤 Work Manager 까지 내려간 상태

현재 코드 기준 메인 전환 뒤 주요 섹션은 다음 순서로 이어진다.

- 서비스 타일
- Elevator dispatch panel
- Recent tickets
- Runtime targets
- Route map
- Work Manager

즉, 현재 UX 평가는 "첫 화면 인상" 과 "전환 뒤 운영 화면" 을 분리해서 봐야 한다.

## 핵심 문제

### P1. 스플래시의 검은 대면적이 의미 없는 여백처럼 보인다

- 특히 모바일에서 플랩 보드 아래와 오른쪽이 크게 비어 보인다.
- 화면이 "의도된 몰입감" 보다 "아직 비어 있는 상태" 처럼 읽힐 위험이 있다.
- 개선 방향
  - 플랩 보드 크기와 행 수를 화면에 더 밀착시킨다.
  - 모바일에서는 스플래시를 짧게 줄이고 핵심 정보 2~3개만 남긴다.

### P1. 메인 화면의 정보 구조가 과밀하다

- 서비스 타일, 엘리베이터 패널, 최근 티켓, 런타임 패널, 레일, Work Manager 가 한 번에 나온다.
- 각 섹션이 모두 중요한 것처럼 보이며 첫 시선이 분산된다.
- 개선 방향
  - 메인 화면을 "운영 개요" 와 "세부 작업 레인" 으로 나눈다.
  - Work Manager 또는 Elevator 를 탭/모드/분리 섹션으로 재조정한다.

### P1. Work Manager 의 실제 상태와 preview 상태 구분이 약하다

- `preview move` 와 실제 저장/실행 대기 상태가 가까이 놓여 있어 오해 소지가 있다.
- command slot 역시 아직 bridge pending 인데 강한 인터랙션 영역처럼 보인다.
- 개선 방향
  - preview 영역에 별도 톤과 경고 문구를 준다.
  - 실제 실행 가능 여부를 더 직접적으로 표기한다.

### P2. 상태 배지 체계가 많지만 의미 체계는 약하다

- `capsule`, `ticket-status`, node badge, profile badge 가 많다.
- 전부 비슷한 스타일 계열이라 빠른 스캔 시 우선순위가 약하다.
- 개선 방향
  - 시스템 상태, 실행 상태, 우선순위, 환경 정보의 badge 체계를 분리한다.

### P2. Elevator 패널은 인상적이지만 진입 피로도가 높다

- 23층 x 4대 구조는 멋지지만 처음 보는 사용자에게는 읽기 비용이 높다.
- 현재는 "요약" 보다 "전체 구조" 를 먼저 보여 준다.
- 개선 방향
  - 상단에 1차 요약 카드 제공
  - 상세 보드는 그 아래 또는 접기 가능한 영역으로 분리

### P2. 영어와 한국어 문장 톤이 혼합돼 제품 톤이 흔들린다

- 예: `Station Control`, `Work Manager`, `Recent tickets`, `offload contract and degraded fallback`
- 의도적으로 혼용할 수는 있지만 기준이 아직 보이지 않는다.
- 개선 방향
  - 시스템명은 영어, 설명은 한국어처럼 규칙을 고정한다.

### P3. 서비스 타일의 행동 목적이 약하다

- `Open station` 이 어떤 변화를 만드는지 덜 분명하다.
- 선택 상태가 생겨도 전체 화면의 맥락 변화가 명확히 느껴지지 않을 수 있다.
- 개선 방향
  - "상세 보기", "시뮬레이터 열기", "운영 보기" 같이 결과 중심 문구로 조정

## 강점

- 콘셉트가 분명하다.
- 다크 톤 안에서도 금속, 노선, 플랩 감성이 살아 있다.
- Elevator / Work Manager 모두 제품의 서사를 만들 수 있는 좋은 재료다.
- 단순한 스타트업 랜딩이 아니라는 점이 분명하다.

## 1차 개선 우선순위

1. 모바일 스플래시 구조 축소 및 여백 재조정
2. 메인 화면 정보 구조 재분할
3. Work Manager preview/real action 구분 강화
4. 상태 배지 체계 재정의
5. 문장 톤과 라벨링 기준 통일

## 추가 검수 메모

- 다음 디자인 리뷰에서는 반드시 아래 두 화면 캡처를 기준 산출물에 포함한다.
  - 10초 후 메인 화면 상단
  - 스크롤 하단의 Work Manager 진입 구간
- 스플래시가 아무리 좋아도, 실제 사용 구간이 스크롤 아래에서 무너지면 전체 UX 는 좋아졌다고 볼 수 없다.
