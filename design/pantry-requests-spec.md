# 자취 밥상 v2 — 조합 판정 다양화 + "주인장에게 요청" (보안 검토 포함)

- 작성: PM(Claude Opus 5.5), 2026-10-25 · 대상 버전 **v2.0**(D-034 — 서버 쓰기가 필요) · 티켓 TKT-198(판정·콘텐츠)·199(요청 저장)
- 요청: PO 「사케에 닭은 어울리지 않을 수 있지. 주인장에게 요청 추가하라고 한 후에 그걸 filedb에 저장하는 건 어떻니, 검토해봐 현재 예상 배포 파이프라인에서 취약하지는 않을지. 그리고 이 조합은 아직 없어요 랑, 이 조합은 어울리지 않아요를 구분해서 케이스를 다양화해줘」

## 1. 지금 문제

`닭 + 사케` 를 고르면 `이 조합은 아직 없어요 — 가까운 상: 평일 된장찌개 집밥` 이 나온다. 가까운 상이 사케 하나만 겹치고 **고른 재료(닭)를 하나도 담지 않는다.** 그래서 "없어서 대신 보여 준다"와 "안 맞아서 다른 걸 권한다"가 구분되지 않는다.

PM 의견: 닭꼬치·닭구이와 사케는 일본 이자카야의 흔한 짝이라 `어울리지 않아요` 보다 `아직 없어요` 가 정직하다. 대신 닭 + 사케 세트를 콘텐츠로 하나 추가한다. `어울리지 않아요` 는 근거를 댈 수 있는 조합에만 쓴다.

## 2. 판정 케이스 (위에서부터 먼저 맞는 것)

| # | 케이스 | 조건 | 화면 |
|---|---|---|---|
| A | 맞는 상 있음 | AND 일치 ≥1 | 지금 그대로 |
| B | 서로 배타 | `무알코올` + 술 태그 | 이미 정규화(술 태그 해제) — 유지 |
| C | 어울리지 않아요 | `PANTRY_MISMATCHES` 규칙에 걸림 | `이 조합은 어울리지 않아요` + 이유 한 줄 + 바꿀 칩 1~2개 제안 |
| D | 조건이 많아요 | 태그 4개 이상이고 0건, 하나만 빼면 일치 | `하나만 빼 볼까요` + 뺄 칩 버튼 |
| E | 재료가 아직 없어요 | 고른 재료 태그를 담은 상이 0개 | `닭이 들어간 상은 아직 없어요` + 요청 버튼(v2) — 엉뚱한 가까운 상은 보여 주지 않는다 |
| F | 조합이 아직 없어요 | 재료별 상은 있으나 조합 0건 | `이 조합은 아직 없어요` + 재료를 담은 가장 가까운 상 + 요청 버튼(v2) |

- 가까운 상은 **고른 재료를 하나 이상 담은 상** 중에서만 고른다(E 와 F 를 가르는 기준).
- 문구는 콘텐츠 파일에 두고 카피 원칙(25자 이내 안내, 자기 해설 금지)을 따른다.

## 3. "어울리지 않아요" 규칙 — 근거 있는 것만 (PM 콘텐츠 초안)

| 조합 | 이유(화면 한 줄) | 제안 |
|---|---|---|
| `해장` + 술 태그 | 해장하는 날의 술은 내일로 미뤄요 | `무알코올` |
| `다이어트` + `야식`·`삼겹살`·`라면` | 오늘 다이어트는 내일의 나에게 맡길까요 | 해당 칩 빼기 |
| `도시락` + `회` | 회는 들고 다니면 상하기 쉬워요 | `고등어`·`스팸` |
| `냉동가능` + `회` | 회는 얼리면 식감이 무너져요 | `고등어` |
| `더운날` + `냄비하나` 찌개류 | 더운 날 냄비 앞은 벌이에요 | `소면`·`10분` |

농담조는 유지하되 사실 근거(식품 안전·조리 상식)가 있는 것만 넣는다. 취향 문제(사케 + 닭 등)는 규칙으로 만들지 않는다.

## 4. "주인장에게 요청" — filedb 안 검토

### 제안된 흐름
방문자가 E·F 화면에서 요청 → 저장 → 주인장(PO)이 보고 세트를 추가.

### 지금·예상 파이프라인에서의 취약점

| # | 위험 | 왜 생기나 | 대응 |
|---|---|---|---|
| 1 | **지금은 저장할 곳이 없다** | 공개본은 GitHub Pages(정적). 쓰기 API 가 없다 | v2.0 의 Worker 게이트가 생긴 뒤에만 연다 |
| 2 | 익명 쓰기 남용 | 로그인 없는 공개 입력 = 봇·스팸·디스크 채우기 | Turnstile + 세션·전역 속도 제한 + 하루 상한(예: 200건) + 같은 조합 중복은 카운트만 증가 |
| 3 | **집 PC filedb 는 꺼지면 유실** | 요청은 Tunnel 너머 집 PC 까지 가야 저장된다 | 저장은 **엣지(Cloudflare KV/D1, 무료 범위)** 에서. 집 PC 는 필요할 때 끌어가는 사본 |
| 4 | 파일 손상 | 단일 JSON 파일을 읽고-고쳐-쓰면 동시 요청에 깨진다 | 엣지 저장 + 집 PC 사본은 추가 전용(JSONL) |
| 5 | **저장형 XSS** | 사용자 글이 관리 화면(운영 노트·Work)에 그대로 렌더 | 자유 텍스트를 받지 않는다(선택형). 받더라도 40자·이스케이프·`v-html` 금지 |
| 6 | 개인정보 | 자유 텍스트에 연락처·실명을 적을 수 있다 | 선택형만, IP 는 해시, 30일 보관 |
| 7 | **배포 파이프라인 오염** | 요청을 저장소 파일에 자동 커밋해 콘텐츠로 쓰면 공개 입력이 빌드·배포까지 흘러든다 | 자동 반영 금지. PM 이 집계를 읽고 `[콘텐츠]` 티켓으로만 세트를 추가 |
| 8 | 백업 | 저장소 밖 데이터는 git 이 지켜 주지 않는다 | 엣지 저장이 원본, 주 1회 JSON 내보내기 |

### 결론
filedb(집 PC 파일) 를 **원본으로 쓰는 안은 비권고**다. 집 PC 가 꺼지면 요청이 사라지고, 파일 손상·저장형 XSS·파이프라인 오염 위험이 한꺼번에 생긴다. 권고는 **엣지에 선택형 요청만 저장 → 집계만 관리 화면에 → PM 이 콘텐츠 티켓으로 반영**이다.

요청 데이터 모양(자유 텍스트 없음):

```json
{ "kind": "missing-ingredient | missing-combo | disagree-mismatch", "tags": ["닭", "사케"], "at": "2026-10-25", "count": 3 }
```

`disagree-mismatch` 는 C 화면의 `그래도 먹고 싶어요` 버튼 — 규칙이 틀렸다는 신호로 쓴다.
