# 메인 페이지 라우터형 시안

작성일: 2026-06-15  
작성자: designer

## 결정 요약

- 메인 화면은 더 이상 기능을 직접 수행하는 작업 화면이 아니다.
- 메인 화면은 지하철 중앙 환승 홀처럼 각 기능 페이지로 갈라지는 라우터 역할만 맡는다.
- 실제 기능은 한 단계 더 들어간 페이지에서만 보인다.
- 전체 콘셉트는 계속 지하철/관제실 계열을 유지한다.

## 왜 바꿔야 하는가

현재 구조는 한 화면 안에 아래 요소가 함께 놓인다.

- 서비스 진입 타일
- Elevator dispatch panel
- Recent tickets
- Runtime targets
- Route map
- Work Manager

이 구성은 개성은 강하지만, 메인 화면이 너무 많은 역할을 동시에 떠안는다.

1. 첫 진입 시 무엇부터 봐야 하는지 흐린다.
2. 메인 화면이 허브인지 작업 화면인지 성격이 섞인다.
3. Elevator 와 Work Manager 가 서로 경쟁하면서 둘 다 덜 강하게 읽힌다.
4. 모바일에서는 긴 스크롤형 포털처럼 보여 라우팅 감각이 약해진다.

## 목표 경험

사용자는 10초 스플래시 이후 "역에 도착한 사람"처럼 메인 환승 홀에 들어온다.

메인 페이지는 아래 경험만 제공한다.

1. 지금 어디에 들어왔는지 이해한다.
2. 어떤 노선/기능으로 이동할 수 있는지 본다.
3. 한 번의 선택으로 목적 페이지에 진입한다.

즉, 메인 페이지는 "설명 + 선택 + 이동"까지만 맡고, 실제 조작은 각 기능 페이지가 맡는다.

## 정보 구조 제안

### 1. Splash

- 역할: 브랜드 인상, 세계관, 도착 감각
- 유지 요소
  - 플랩 보드
  - 큰 도착 카피
  - 관제실 톤
- 조정 요소
  - 모바일에서는 플랩 행 수와 보드 높이를 줄인다.
  - 전환 뒤 메인 허브로 자연스럽게 넘어가야 한다.

### 2. Main Page

- 역할: 중앙 환승 홀, 라우터, 노선 선택 화면
- 금지 요소
  - 실제 Elevator 보드 전체 노출
  - 실제 Work Manager 보드 전체 노출
  - 상세 runtime 규칙 표의 과도한 노출
  - 최근 티켓 긴 목록 직접 노출

- 허용 요소
  - 각 기능을 대표하는 노선/플랫폼 카드
  - 현재 연결 상태의 아주 짧은 요약
  - 이동 버튼
  - 메인 환승 안내 문구

### 3. Feature Pages

- `Elevator Station`
  - 여기 들어와서만 23층, 4대 shaft, 승객 흐름, 제어 UI를 본다.
- `Work Manager`
  - 여기 들어와서만 보드, 상세 패널, command gate, activity feed를 본다.
- 추후 기능
  - 각 기능은 모두 메인 환승 홀에서 갈라져 나가는 개별 역/노선 페이지처럼 확장한다.

## 메인 페이지 시안 구조

### 상단

- 큰 역명형 타이틀
  - 예: `Main Junction`, `환승 중앙홀`, `workaround central`
- 작은 현재 상태 문구
  - 예: "지금 3개 노선이 운행 중입니다."
- 짧은 방향 안내
  - 예: "원하는 노선으로 이동해 실제 화면에 들어가세요."

### 중앙

- 노선 카드 3~5개
- 각 카드는 지하철 노선 표지처럼 보인다.
- 카드 구성
  - 노선 색/번호
  - 기능명
  - 한 줄 설명
  - 상태 요약
  - `입장하기` 또는 `플랫폼 열기`

추천 기본 카드:

1. `Line E` / `Elevator Station`
2. `Line W` / `Work Manager`
3. `Line R` / `Runtime Board`
4. 향후 `Arcade`, `Public Site` 등 확장 가능

### 하단

- 얇은 운행 상황 바
- 현재 온라인/오프라인 상태 정도만 매우 짧게 표시
- 여기서도 상세 목록 대신 "무슨 일이 벌어지는 중인지"만 요약

## 지하철 콘셉트 적용 방식

메인 페이지는 "기능 카드 모음"보다 "환승역 안내 공간"처럼 보여야 한다.

- 카드 = 노선 입구
- 버튼 = 승강장 진입
- 현재 상태 = 전광판 운행 정보
- 페이지 이동 = 환승

중요한 점은 지하철 콘셉트를 장식으로만 쓰지 않는 것이다.

- 화면 구조 자체가 이동 중심이어야 한다.
- 사용자는 메인에서 머무르기보다 기능 페이지로 들어가야 한다.
- 따라서 메인은 "예쁜 대시보드"가 아니라 "명확한 분기점"이어야 한다.

## 데스크톱 시안 방향

- 중앙에 2x2 또는 3x2 카드 레이아웃
- 좌우로 넓은 환승 홀 여백
- 큰 타이틀과 큰 노선 카드
- 상세 정보는 억제하고, 선택 감각을 키운다.

핵심 인상:

- "지금 무언가를 조작하기보다, 어디로 들어갈지 정하는 곳"

## 모바일 시안 방향

- 세로 스택 카드
- 타이틀은 유지하되 설명은 더 짧게
- 상태 요약은 아이콘+짧은 텍스트만 유지
- 첫 화면에서 바로 기능 선택이 가능해야 한다.

핵심 인상:

- "앱 홈"이 아니라 "지하철 환승 화면"

## 페이지별 톤 차등

- Splash: 가장 극적
- Main Page: 가장 선명하고 길 안내 중심
- Feature Page: 가장 기능적

즉, 메인 페이지는 스플래시보다 덜 연출적이어야 하고, 기능 페이지보다 덜 복잡해야 한다.

## 라벨링 제안

메인 허브에서 쓰는 문구는 결과 중심이 좋다.

- `Open station` 보다 `플랫폼 입장`
- `Work Manager` 하위 버튼은 `운영 보드 열기`
- `Elevator Station` 하위 버튼은 `시뮬레이터 입장`

문장 톤 규칙:

- 기능명: 영어 유지 가능
- 설명/상태: 한국어

예시:

- `Work Manager`
  - "티켓 흐름과 운영 명령을 관리하는 노선"
- `Elevator Station`
  - "23층 다중 엘리베이터 흐름을 보는 시뮬레이터 노선"

## 구현 가드레일

- 메인 페이지에 실제 Work Manager 컬럼 보드를 다시 끌어오지 않는다.
- 메인 페이지에 실제 Elevator shaft 전체를 다시 끌어오지 않는다.
- 메인은 요약 카드까지만 보여주고, 상세는 반드시 개별 라우트에서 연다.
- `Main page 로 돌아가기` 동선은 모든 기능 페이지에 분명히 둔다.
- 스크롤 길이보다 라우팅 분기를 우선한다.

## 오케스트레이터 handoff 기준

이 시안을 구현 티켓으로 옮길 때 acceptance criteria 에 아래 항목을 넣는다.

1. 스플래시 이후 메인 페이지에는 실제 기능 패널이 직접 노출되지 않는다.
2. 메인 페이지는 라우터형 노선 카드만 보여 준다.
3. Elevator 와 Work Manager 는 각각 별도 기능 페이지에서만 전체 UI를 노출한다.
4. 데스크톱/모바일 모두에서 메인 페이지가 "환승 허브"처럼 읽혀야 한다.
5. 지하철 콘셉트가 장식이 아니라 정보 구조에 반영되어야 한다.
