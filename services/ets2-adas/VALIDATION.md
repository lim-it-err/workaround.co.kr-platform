## PoC 02 검증 (2026-09-27)

- 기존 주행 제어 7개 + 정체 감시/복구 프로세스 9개 = 16개 통과. 마지막 2개는 자동 호출 차단과 복구 중단 시 입력 해제 협약 검사다.
- 119초에는 요청 없음, 120초에서 1회 요청, 반복 요청 방지 확인. 실제 120초를 기다리는 게임 시험 대신 주입한 단조 시계로 검증했다.
- 메뉴/일시정지/오래된 데이터/연결 끊김/NaN/게임 변경/프로세스 지연/전후진 시 타이머 초기화 확인.
- 복구 실패 보류, 성공 후 5분 대기, 누락/잘못된 요청 ID/수리 미확인/비정상 종료 응답 거부 확인. 성공 응답 시험은 테스트용 프로세스이며 실제 게임 수리 증거가 아니다.
- 실제 ETS2 창을 Windows Graphics Capture로 읽고 브라우저에서 1280×720 JPEG 표시 확인. PrintWindow는 DirectX에서 검은 화면이라 사용하지 않는다.
- localhost와 127.0.0.1의 화면 API 200 image/jpeg 확인. Origin/토큰 없는 조작 POST는 403.
- 사용자 SDK 승인 이후 게임 로그의 Telemetry/Input connected 확인. 스캔 코드 입력으로 F7 메뉴의 견인 선택과 확인이 반영됐다. 게임 로그의 Teleported 및 SDK 좌표 변화로 정비소 이동 약 854m를 확인했다. 최초 위치 확인 제한 50초보다 로딩이 길어 해당 요청은 실패로 표시됐으나, 실제 이동은 후속 관측으로 확인했다. 현재 위치 확인 제한은 90초다.
- 정비소 안내에서 Enter 입력으로 차량 서비스 메뉴에 진입했다. 서비스 항목 마우스 클릭은 반영되지 않았다. 수리 미확인, 무인 자동 복구 비활성. 120초 감지부터 수리까지 연결된 실게임 시험은 통과하지 않았다.
- 복구 중단 시 먼저 취소 메시지를 보내 입력을 해제하고, 1초 내 종료하지 않을 때 프로세스를 종료하도록 변경했다. 전체 복구 제한은 180초다.
- 이번 변경에서 native DLL/공유 메모리 ABI는 변경하지 않았다. 게임 실행 중이므로 네이티브 하네스는 다시 실행하지 않았다.
