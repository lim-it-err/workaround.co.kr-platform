# ETS2 주행 보조 PoC

**실제 ETS2 연결 먼저, 같은 제어기를 사용하는 브라우저 시뮬레이션을 다음으로 제공한다.** 외부 서버, 계정, 유료 API는 없다. 실게임 연결은 이 PC의 작은 로컬 프로그램이 담당한다. 시뮬레이션만 사용할 때는 서버 자체가 필요 없다.

## PoC 02 · 화면 중계와 무기한 감시

`START.cmd` 실행 후 http://localhost:8765 에서 ETS2 창을 최대 1280×720, 약 1초 간격으로 볼 수 있다. 브라우저를 닫아도 로컬 프로세스는 종료 시간 없이 계속 실행한다. PC 절전·종료·재부팅 후 자동 실행은 설정하지 않았다. 이번 ‘무제한’은 실행 시간이며 110km/h 제어 상한을 제거한다는 뜻이 아니다.

- 화면은 Windows Graphics Capture로 ETS2 창만 캡처한다. 화면 전체를 대신 캡처하지 않으며 JPEG는 메모리에 최신 1장만 유지한다. 창 최소화·오래된 프레임은 상태로 표시한다.
- 감시는 서버 시작과 함께 켜진다. 신선한 SDK 주행 데이터에서 **속도 절댓값 1km/h 미만이 120초 연속** 유지되면 복구 요청을 한 번 만든다. 일시정지·메뉴·연결 끊김·게임 변경·실행 루프 정지는 타이머를 초기화한다. 1km/h 이상 전진/후진해도 초기화한다. 정상 신호 대기와 고장을 구분하는 기능은 아직 없다.
- **자동 견인·수리는 아직 완성되지 않았다.** 실제 SDK 수신, F7 서비스 선택, 견인 확인, 정비소로 약 854m 이동, 차량 서비스 메뉴 진입을 확인했다. 서비스 항목의 자동 마우스 클릭이 반영되지 않아 수리는 미확인이다. `recovery.config.json`의 `manualOnly: true`가 자동 호출을 차단한다. 대시보드의 ‘견인 서비스 입력 시험’은 확인된 메뉴에서 단계별 연결 시험만 수행하며, 완료된 자동 복구 기능이 아니다.
- 향후 어댑터를 연결하면 이동과 수리를 모두 확인한 완료 응답에만 5분 재시도 대기를 적용한다. 실패는 사용자가 감시를 다시 시작할 때까지 보류한다. 복구 후 자동 출발·경로 주행은 미구현이다.
- 게임이 활성 창일 때 **F8**, 대시보드 **커스텀 제어 중단**은 감시·복구·커스텀 입력을 중단한다. **감시 중단**은 감시·복구만 중단한다. 게임 내장 ACC는 브레이크나 ACC 버튼으로 끈다.
- 프로그램 전체 종료는 `STOP.cmd`. 브라우저 창 닫기로는 종료하지 않는다. 주행 제어는 게임 정지·SDK 연결 지연·브레이크 등 기존 중단 조건을 계속 적용한다.
- `runtime/events.ndjson`은 약 1MB 단위로 이전 파일 1개만 유지한다. `runtime/last-recovery-request.json`은 마지막 요청 하나다. 이 파일들은 로컬에만 저장된다.

현재 제공물은 **계속 켜 두는 감시 PoC**이며, 무인으로 출발·운전·견인·수리·재출발까지 반복하는 완성된 자율주행 루프는 아니다. `TEST.ps1`은 기존 제어 7개와 감시/복구 연결 9개 시험을 실행한다. [RECOVERY.md](RECOVERY.md)에 후속 작업과 연결 계약을 기록했다.

화면 중계에는 `vendor`의 Windows Capture 2.0.1(MIT), OpenCV headless 5.0.0.93 및 이 PC Python의 Pillow/NumPy를 사용한다. 라이브러리 출처와 라이선스는 [THIRD_PARTY.md](THIRD_PARTY.md)에 기록했다.

## 실행

1. `START.cmd`를 더블클릭한다. 이 PC에 있는 Node/Python으로 연결 프로그램과 브라우저가 열린다. 화면 주소는 http://127.0.0.1:8765 이다.
2. ETS2를 실행하고 SDK 안내를 확인한 뒤 프로필의 업무를 불러온다.
3. **01 실제 ETS2**에서 속도·크루즈 설정·목적지 거리·이동 궤적을 확인한다.
4. **02 시뮬레이션**은 게임 없이도 사용한다. `index.html`을 직접 열어도 된다.

처음 설치는 게임 종료 상태에서 `INSTALL.ps1`을 실행한다. 현재 제공된 기본 경로는 이 PC의 `<프로필 B>` 프로필이다. 다른 프로필은 `-ProfileConfig`에 해당 config.cfg 경로를 지정한다. 설치 스크립트는 플러그인과 `g_lane_assistant=2`, `g_acc=40.0`만 적용하며 원본을 `backups`에 저장한다. `g_acc=40`은 SDK 문서의 실시간 앞차 간격 값이 아니라 게임 설정의 기준 거리다.

## 구현 범위

| 기능 | 실제 ETS2 | 시뮬레이션 |
|---|---|---|
| 내 트럭 속도·위치·방향 | 직접 만든 SCS SDK 플러그인으로 읽기 | 가상 차량 상태 |
| 차선 유지 | ETS2 내장 차선 유지 보조 사용 | 자체 중심선 피드백 제어 |
| 앞차 속도·간격 유지 | ETS2 내장 ACC 사용 | 자체 간격/상대속도 제어 |
| 차선 변경 | 사용자 확인 후 위치 피드백으로 한 차로 이동하는 실험 | 동일한 차선 변경 제어기 |
| 주변 차량을 보고 변경 보류 | 없음. 사용자가 빈 차로 확인 | 앞뒤 간격 및 뒤 차량 접근 검사 |
| 경로 기반 추월 | 후속 단계 | 출구 접근 시 변경을 보류하는 시험 입력 |

실제 게임의 차선 유지·ACC를 새로 개발했다고 주장하지 않는다. 이번 PoC에서 만든 것은 네이티브 연결, 로컬 제어 경로, 위치 피드백 차선 변경, 중단 처리, 시뮬레이터다. 차선/객체 인식 모델은 아직 없다.

## 실제 게임 사용법

- 고속도로의 단순한 직선 구간에서 주행한다. 크루즈는 게임의 기존 `C` 키로 현재 속도에 설정할 수 있다. 설치된 ACC 설정에 따라 게임이 앞차를 추종한다.
- 대시보드에서 `명령 준비` 후 `ACC 설정/해제`, `±5 km/h`, `차선유지 보조 켜기/끄기`를 보낼 수 있다. 증가 명령의 상한은 110km/h다. 게임에서 직접 설정하는 값까지 이 앱이 강제하지는 않는다.
- 게임이 일시정지되어 있으면 명령 준비와 다음 명령을 예약한 뒤 30초 안에 게임으로 돌아간다. 예약은 명령 하나이며 새 예약이 앞선 예약을 대체한다. `커스텀 제어 중단`으로 취소한다.
- 차선 변경은 30~110km/h, 빈 직선 구간, 옆 차로 간격을 직접 확인한 조건에서만 실험한다. 내장 차선유지 보조를 먼저 끄고 두 확인란을 선택한다. 기본 차로 폭 3.6m와 약 7초 궤적을 사용한다.
- 완료 후 내장 차선유지 보조를 다시 켠다. 실제 차선 인식이 없으므로 곡선, 합류, 분기, 다른 차로 폭, 주차장에서는 사용하지 않는다. 실제 도로 주행 성능은 아직 검증되지 않았다.
- **F8 / 브레이크 / 좌우 방향키 / 일시정지**는 커스텀 차선 변경을 중단시킨다. F8은 게임 내장 ACC까지 끄는 키가 아니다. 내장 ACC는 브레이크 또는 크루즈 버튼으로 해제한다.
- 조향 휠을 통한 수동 개입은 모든 장치에서 검증하지 않았다. 확실한 커스텀 중단 수단은 F8 또는 브레이크다.

## 시뮬레이터

느린 앞차 추종, 차선 중심 복귀, 빈 차로 변경, 빠른 뒤 차량 때문에 변경 보류, 출구 접근 때문에 변경 보류의 다섯 상황을 제공한다. 목표 속도 60~110km/h, 1×/2× 진행, JSON 기록 저장을 사용할 수 있다. 가상 차로/차량은 실제 게임 관측과 구분해서 저장된다.

횡방향 모델은 단순한 자전거 모델이며 트레일러 관절, 타이어 마찰, 경사, 정확한 조향 지연을 구현하지 않았다. 따라서 시뮬레이터 통과는 게임 주행 검증을 대신하지 않는다.

## 코드와 Java 전환

- `native/plugin.cpp`: SCS SDK 텔레메트리/입력, F8, 300ms 명령 만료 처리.
- `native/protocol.h`: 고정 크기 공유 메모리 구조.
- `bridge.py`: Windows 공유 메모리 ↔ 줄 단위 JSON. 표준 라이브러리만 사용.
- `controller.js`: 화면과 독립된 차선 변경·ACC·차선 유지·변경 허용 함수.
- `server.js`: 로컬 실행 루프와 브라우저 API. 이후 Java로 교체할 위치.
- `java/BridgeProbe.java`: Java 8+로 어댑터에 연결하는 읽기 전용 예제.
- [API.md](API.md): 데이터 단위, 명령, Java 전환 경계, 후속 인식/경로 입력 계약.

자동 추월을 추가하려면 먼저 차선 경계 및 주변 차량의 위치·속도·관측 신뢰도를 얻는 어댑터가 필요하다. SDK의 목적지까지 거리만으로 실제 도로의 차로 경로를 계획할 수는 없다.

## 검증과 복구

`node --test tests/controller.test.cjs`로 7개 로직 시험을 실행한다. 네이티브 smoke test는 DLL 로딩, 실제 SDK 함수 형태, 공유 메모리 ABI, 입력 부호, 크루즈 펄스, 300ms 만료, 재활성화 차단, 일시정지, 브레이크, NaN 및 조향 상한을 검사한다. 게임을 켜기 전에만 이 네이티브 시험을 실행한다.

SDK 헤더와 라이선스가 `native/sdk`, `native/sdk_license.txt`에 포함되어 있다. 재빌드는 Zig 0.15.2의 `zig.exe`를 `BUILD.ps1 -Zig <경로>`에 전달한다.

원상복구는 게임 종료 후 `backups/<시각>/config.cfg`를 해당 프로필 config.cfg로 복원하고 게임의 `bin/win_x64/plugins/ets2_adas_poc.dll`을 제거한다. 다른 플러그인은 건드리지 않는다. Node 연결 프로그램을 종료해도 게임 플러그인이 명령 만료를 감지하여 커스텀 조향을 0으로 만든다.
